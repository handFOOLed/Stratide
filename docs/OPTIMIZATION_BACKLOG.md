## 1. 当前基线及需要澄清的概念

- **TimesFM 2.5**：本地 CPU，`LOCAL_NO_BILLING`，不产生模型云 API 调用。
- **DeepSeek Fusion**：目前真实 API 的成本来自 Provider 返回的 token 用量，Stratide 对外采用**高峰期、全部输入 cache miss** 的保守费率作估算及最大预算预留；这里的**费用估算不是官方发票**。
- **统一 Agent 预算**：`CNY`，`Asia/Shanghai`，**每日 ¥5 / 每月 ¥100**；是**单一 Stratide Owner Agent 的内部硬门禁**，不是 DeepSeek 账户全局封顶。用户可能在别处使用同一 API Key。
- **2026-11-03 两次真实测试快照**：最大预留合计 **¥0.196608**；基于保守 token 单价的用量估算 **¥0.015420**；用户反馈账户实际扣费合计**不到 ¥0.01**（未获得可精确归属两次 Request ID 的官方逐笔账单，因此不能记录为已核销事实）。第一次 `PORTFOLIO_SCHEMA`，第二次生成了合法 100% 现金研究组合。详见 `docs/evidence/m2-pr19/`。
- **预留 ≠ 已扣费 ≠ 估算 ≠ 已核销**。已观察到“余额占用明显高于估算支出”的体验问题；暂时接受这一保守性，不因此扩预算或改变预留释放规则。

## 2. API 费用、预算与对账（建议优先评估）

| 编号 | 优化候选 | 当前不足 / 建议方向 | 风险与验收边界 | 优先建议 |
| --- | --- | --- | --- | --- |
| BILL-01 | **三种金额明确分离** | 将 `maximum_reserved`（最大风险占用）、`usage_estimate`（按响应计算）、`reconciled_actual`（经过官方账单/人工核销的事实）分成独立列与 Dashboard 指标；明确未知费用和累计余额 | 不要把¥0.20预留显示成¥0.20真实消费；未核销金额保留为 pending | 近期 UX 优先 |
| BILL-02 | **估算模型贴近真实计价** | 在 Provider 实际提供时读取 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 等分项；结合请求发生时的峰/谷、计价版本、生效时区和输出 tokens 计算单笔估算，保存计价公式版本与原始用量字段 | 官方定价和返回字段可能变化：版本/字段缺失时使用**保守估算**并展示不确定性；不能把该金额标为 invoice | 近期评估 |
| BILL-03 | **成功请求的预留释放策略** | 比较原“成功仍持有最大预留直至核销”和“经可信账单确认后释放差额”的方案；将 `usage_received`、`outcome_uncertain`、`settled` 清晰区分 | **不能仅凭 token 估算就无条件释放全部超额预留**；未知/失败/缺 usage/超时必须防超支，不能自动重发 | 财务规则专项 |
| BILL-04 | **官方账单证据接入与手动核销** | 如未来官方提供有文档保证的逐笔费用接口，使用 request ID + 精确发生时点 + 币种对账；否则提供只读流水导入/Owner 人工确认的幂等核销路径，保留原 receipt 和变更日志 | 切勿编造逐笔账单接口或从响应 token 推断“已扣费”；核销不得覆盖历史、丢弃未知预留或跳过原预算内核 | 有可信接口时 |
| BILL-05 | **账户余额只作观测** | DeepSeek 已知有账户余额查询接口 `GET /user/balance`；可作为资金充足性提示（需核对权限/更新延迟/精度） | **同一 Key 可能被其他软件调用**，加上充值、赠金变化，调用前后余额差不能可靠归属 Stratide 的单次请求；**不得用于自动逐笔结算** | 可选，非硬门禁 |
| BILL-06 | **统一预算可观测性** | 同一 CNY Agent 的 PR17 结构化研究、PR19 Fusion 等按 `calls` 汇总；显示日/月已核销、所有未释放预留、剩余额度、最近调用和源任务/模型；加入额度将耗尽时的明确信息 | 保持日 ¥5 / 月 ¥100，Asia/Shanghai；跨周期不明费用和并发 reserve 继续强制占用，不能分裂钱包规避 cap | 近期 UX 优先 |
| BILL-07 | **费用配置版本管理** | 费率变化/价格有效期、缓存规则、新模型别名出现时提示重新检查，历史研究保留旧计价版本；高峰费率优先满足预留上界 | 不能自动用新费率重签旧任务，旧估算和发票差异应可复盘 | 中期 |

**实现原则**：请求发送前始终按**最坏合理单次账单**进行原子预留；发送后以已知 token 计算**估算**，官方发票/人工确认才标记**核销**；Provider 超时/429/500/断线/缺 usage 或无法确定是否已送达时**保留原最大预留，不重发**。同一 API Key 在其他客户端产生的调用应在界面明确注明“**不属于 Stratide 内部预算统计**”；本地上限不能限制外部 API 消费，也不能代替 Provider 账户级限额。
