## 三种资格

| 字段 | 含义 |
| --- | --- |
| `source_evidence_status` | `UNKNOWN`、`FACTS_PARTIAL` 或 `ON_DAY_COVERAGE_VERIFIED_LOCALLY`；最后一种只说明受信操作人提供的来源契约、按时取得记录和内容校验成立 |
| `forward_research_readiness` | `BLOCKED` 或最多 `ALLOW_RESEARCH_ONLY`；只针对冻结的 21 会话研究输入 |
| `historical_pit_status` / 执行权限 | 始终 `NOT_VERIFIED`、`ELIGIBILITY_DENIED`、`opening_source=BLOCKED`、`can_execute_forward_paper=false`、`live_allowed=false` |

SHA 证明内容一致性，不能认证发行人、供应商、其时钟或文件事实。独立来源身份、合法权限和完整覆盖契约仍需受信操作人核对；研究模型不能自行声明这些权限。这里的“实际取得”是**本机离线导入时首次可证明持有这些字节的时刻**，不是凭公告日期推断的历史 HTTP 收到时间。CLI 不接收历史 acquisition time、`ready`、`--force` 或模式转换参数。

## CLI

仓库根目录、Python 3.12+，沿用现有 Rust 构建。所有输入先放在原数据目录或新的 ignored 目录；真实 raw、PDF、路径和 SQLite 不入 Git。

```powershell
# 原 PR33 store 目录可以来自另一个现有工作树；绝不在这里 sync 或迁移它。
python -B scripts/forward-research-readiness.py --name owner-forward init --snapshot-store '<EXISTING_PR33_STORE>' --corporate-action-bundle '<EXISTING_PR38_BUNDLE>'
python -B scripts/forward-research-readiness.py --name owner-forward audit
python -B scripts/forward-research-readiness.py --name owner-forward status
python -B scripts/forward-research-readiness.py --name owner-forward verify --receipt '<RECEIPT_SHA256>'
python -B scripts/forward-research-readiness.py --name owner-forward report
```

初始化成功退出 0，但研究资格仍 BLOCKED。`audit/status/verify/report` 的 BLOCKED 退出 2；合格收据退出 0。格式、SHA、时钟、来源故障也退出 2，附稳定 `error_code`。输出为 UTF-8 JSON，不输出原始价格。审计对当前缺证仍发布可复核的失败收据；连原快照都无法读取时直接返回来源错误，不伪造一张成功收据。

有合法事件源后，显式登记其完整覆盖契约，再导入**当天实际取得**的响应：

```powershell
python -B scripts/forward-research-readiness.py --name owner-forward source --contract '<REVIEWED_SOURCE_CONTRACT.json>'
python -B scripts/forward-research-readiness.py --name owner-forward capture --payload '<TODAYS_COVERAGE_PAYLOAD.json>'
python -B scripts/forward-research-readiness.py --name owner-forward audit
```

未来证据齐备后仍使用这些入口。原 Operator 继续按原流程收集行情；本模块不改其采集槽、网络请求、启停、失败重发或计划任务。`capture` 也不发 HTTP 请求。收据有效时可在**同一 checkout 的原 PR33 store**上接通研究：

```powershell
python -B scripts/multimodal-research.py --name owner-research init --snapshot-store '<LOCAL_PR33_STORE_NAME>' --readiness-store owner-forward
python -B scripts/multimodal-research.py --name owner-research enable
python -B scripts/multimodal-research.py --name owner-research once
```

`init` 只绑定来源，允许在尚未满足 21 日时先配置。`once` 仍要求已有合格收据、原 Owner enable、预算和 fake-only 设置。旧 synthetic 任务未配置 readiness 时沿用 PR52 行为；forward 未配置 readiness 时继续硬拒绝。没有新增 Provider Scope、真实云 Fusion 或外部时序模型。

## 来源输入契约

V1 是离线、受信操作人审查后的证据格式，**没有实现 Tushare/SSE 的公司行为抓取 adapter，也没有自动认证一份任意 JSON 的官方真实性**。真实 feed 未接入就是 `ACTION_FEED_UNAVAILABLE`。有供应商响应也必须保留其可证明完整覆盖的来源契约；不能把空事件列表当作覆盖证明。

来源契约 manifest 必须恰含下列字段；`document_path` 是 manifest 同目录内的相对文件路径，拒绝 `..`、绝对路径和软链/junction。文件上限沿用 PR38 的 4,000,000 bytes。

| 字段 | 约束 |
| --- | --- |
| `schema_version` | 整数 1 |
| `source_id` / `version` | 明确的独立事件源及其契约版本；更改版本追加证据，不能覆盖 |
| `kind` | 真实源为 `official_event_feed`；合成源只能为 `synthetic_test`，由原 journal 模式绑定 |
| `publisher_url` | 真实源须为 PR38 已支持的官方发行人/交易所/巨潮 HTTPS 来源；合成源为 null |
| `permission_basis` | 取得和本机保存该事件证据的权限依据；本地校验不能代替真实许可 |
| `completeness_scope` | 固定 `all_price_affecting_corporate_actions` |
| `completeness_quote` | 原契约逐字引用，必须存在于下项文件；是否确实承诺完整性仍由操作人审查 |
| `document_path` / `document_sha256` | 实际核对的 UTF-8 来源契约全文及 SHA，原字节保存于新 store |
| `review_method` | 固定 `operator_manual_document_text_crosscheck` |

coverage payload 必须恰含：

```text
schema_version: 1
source_id / source_version: 同已登记契约
instrument: 600000.SH
as_of_day / covered_from / covered_through: YYYYMMDD，含上下界
complete_scope: all_price_affecting_corporate_actions 或 null（null 阻断）
publisher_generated_at: UTC 毫秒或 null（供应商声明，与本机取得时间分开）
revision / supersedes: 来源版本及显式更正关系；无更正为 null
events: 原始结构化事件事实列表；无事件为 []
```

真实来源导出/规范化过程必须由受信操作人核对原响应、范围和完整性，不允许研究模型编造这些字段。外部数据服务尚无完整性契约或未提供该格式时保留 BLOCKED；不购买接口或静默把别的 API 当成完整事件源。

每个事件的字段字面直接复用 `research/corporate_actions.py::FIELDS`：证券、事件 ID/类型、公告/登记/除权/支付/上市等日期、现金金额/每股或每十股单位/CNY、gross/net、税务和股份比例，未知为 null。复用 PR38 日期、币种/单位和金额约束；现金模型 PR40 的日期顺序及 gross CNY 语义不被放宽。事件缺项为 `EVENT_FACT_PARTIAL`；即使事实齐全，只要窗口涉及公司行为，仍为 `PRICE_SEMANTICS_UNSAFE`。本轮没有真实价格调整或账户分红核算。

## 逐日判定与恢复

1. 重读原 observer 摘要链/checkpoint/raw SHA，与原 PR33 当前快照、source identity、原 observer binding 和同步结果核对。原交易日历决定连续会话；不推算周一到周五，也不把回填算前向观察。
2. 要求当前上海日期的盘后窗口、fresh PR33、21 个连续 on-day 会话；检查原 observed ≤ received ≤ available ≤ as-of ≤ 当前决策时刻、未复权分/股和 OHLCV、未来标签、窗口内修订/晚补。
3. 每个有效日都要求当天首次本机取得的独立覆盖记录；每个收益区间覆盖前一会话至本日的全部日历日期。原文缺失、空 HTTP 响应或数据库空表都不能证明无公司行为。
4. 每次 capture 固定当时的 PR33 SHA；复验会读取 PR33 保留的对应快照，核对 identity、源日、SHA 和实际核验时间 ≤ capture 时间。后来一次下载不能补出此前 20 天的证据。
5. 新契约、更正或新资料追加内容寻址版本。旧收据、旧失败和实际取得时间不重写。相同 payload 的重复导入复用第一次取得时间；相同审计 basis 的重复发布复用同一收据 SHA。
6. 所需窗口内的事件源更正/冲突、来源失败、时钟回退、状态变化均阻断。已经离开窗口的旧缺口/旧修订保留为诊断；其后新形成的完整 21 会话窗口可以重新审计，不能把旧失败改成当时成功。原 PR48 Shadow 的判断契约不变。

同日早先不完整的空响应没有“无事件”断言；当天后来确实取得完整覆盖，可以生成一张新的合格收据，原失败仍可回放。仅响应时间戳刷新、事件事实相同不叫事实冲突，但仍追加证据版本，使旧 queued 任务失效。事件事实差异或显式更正继续阻断。

新状态位于 `state/forward-readiness/<name>/readiness.sqlite`，schema 1110。证据链、原字节 BLOB、冻结快照和收据同一 SQLite FULL 事务发布；复用 PR33 OS 生命周期 writer lock，查询使用原 PR48 immutable reader。未提交写入中断不出现成功收据；本模块自己的 writer 可恢复其热日志。并发竞争返回 `STORE_BUSY`。上限 64 MiB / 256 条来源或覆盖记录；满额时拒绝继续记录，不丢弃金融或原始证据。

`verify/report/status` 回放冻结证据，不刷新历史资格；当前可调用权限仍须重新检查。PR52 的冻结 spec、Fusion summary、原任务、Registry provenance 都包含 readiness store / receipt SHA / evidence head。新版本产生新实验身份，同日变更仍要求原显式 `experiment --label`，旧任务不会自动改绑。

Rust 的**实际已领取任务**在原 reserve 前和 dispatch 事务内都调用同一固定只读 verifier，检查它自己的 PR33 SHA、source identity/day/mode、收据、当前原 journal 和 Owner 状态。另一个成功任务不能代替它。已失效的 queued 任务持久取消；预留后失效记录 `no_charge`；settled/UNKNOWN 的既有费用事实沿用原状态机，不重发。

原 Rust PR33 reader 对已 checkpoint 的 WAL 文件使用 immutable 读取，并检查 WAL 文件头和前后文件 SHA，避免只读检查改变原文件时间/空 sidecar。非空 live WAL 继续走原 SQLite 事务；readiness Python 读取仍按原 PR48 规则拒绝 busy/hot 状态。

## 本次真实来源与权限结果

原 observer 的 5 事件、4 raw 引用和 PR33 SHA `3def7bf43e54d889a68db292b09cfe0885782f650438792b01baff70f44cde03` 均复核；有效日仅 `20261028/29`。逐日原时间/SHA 见 [真实审计](evidence/m1-pr11/real-audit.json)。没有运行行情采集或重新 sync 原 store。

原 PR38 bundle `c9b15d74dd687691e9418742fefa22bf70e4843dc6a066cb5f554df43329b49b` 及公告原字节仍相同；文档支持的每股税前 CNY 0.42、7/15 登记、7/16 除息事实不增加当时取得证据。该原包是事后取得的 `FACTS_PARTIAL / historical_pit=NOT_VERIFIED`，不是十月窗口无事件覆盖，PR40 synthetic 会计也不构成真实来源权威。

官方 [Tushare dividend 文档](https://tushare.pro/document/2?doc_id=103) 当前声明至少 2000 积分、每日 20–21 点更新；[权限说明](https://tushare.pro/document/1?doc_id=108) 区分各接口权限。它们未给本模块提供按时的完整事件/修订覆盖证据。本次没有读取 Token、查询账户积分、试探 dividend 接口或购买权限；不能据已有 daily/trade_cal 授权推定事件接口可用。

实际 blockers：`ACTION_FEED_UNAVAILABLE`、`COVERAGE_NOT_ATTESTED`、`INSUFFICIENT_FORWARD_HISTORY`、`INSUFFICIENT_FORWARD_WARMUP`、`MISSED_OR_STALE`、`NO_VALID_CURRENT_ON_DAY_EOD`、`SNAPSHOT_SYNC_STALE_OR_CLOCK`。14 个实际读取的原文件 byte+mtime 保全、4 raw 与 receipt SHA 独立复算见 [保全清单](evidence/m1-pr11/preservation.json)。
