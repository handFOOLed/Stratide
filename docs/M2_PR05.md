## 使用

Windows / Python **3.12+**，仅标准库，无需构建 Rust、Token、行情 HTTP、云模型或额外安装。仓库根目录执行：

```powershell
# 完整离线样例：固定合成输入，只能产生 synthetic_test。
python -B scripts/research-data.py --store demo-eod sync --fixture
python -B scripts/research-data.py --store demo-eod status
python -B scripts/research-data.py --store demo-eod snapshot
python -B scripts/research-data.py --store demo-eod consume

# Owner 指定的既有 observer，只读目录或 forward.sqlite。
python -B scripts/research-data.py --store owner-eod sync --observer '<既有observer目录>'
# 后续沿用本地已保存的来源绑定，不换来源，也不采集。
python -B scripts/research-data.py --store owner-eod sync
```

`sync` 成功退出 0；核验/质量阻断退出 2，输出错误码和保留快照的状态。`status`、`snapshot`、`consume` 读取成功退出 0，即使最近刷新被阻断：消费者必须读取其 `can_research` 和 `quality.latest_sync`。没有已发布快照时 `consume` 退出 2。未初始化的 store 只读命令返回 `STORE_NOT_INITIALIZED`。

store 名称只允许小写字母、数字、`_`、`-`。新写入仅在 git-ignored `state/data-sync/<名称>/`：`snapshots.sqlite`、其 SQLite WAL/SHM 和进程锁。首次成功发布将来源路径、genesis 与模式绑定；路径只保存在本机，不输出到 CLI。不能通过刷新切换 observer、fixture 或重建过的 journal；需要新名称以保持证据分离。

## 读取与发布契约

原 `forward-status/report/eod-at` 使用有写锁的 `Journal::open`；本期不调用这些写入者 API，也不改变它们。`research/eod_journal.py` 沿用现有 `verify-forward-readonly.py` 和 Rust forward 的 **1041 schema、摘要链、checkpoint、raw 哈希与规范化格式**，用 SQLite `mode=ro`、`query_only`、只读事务读取一致视图；显式关闭连接。重新核对来源身份/本地授权、完整性、事件/run/时间顺序、HTTP 状态、日历范围、OHLC 与手到股单位、HTTP Date 与收取时间、重复/修订引用及晚补语义。

原 observer 仍为 DELETE 模式；发现 `-wal/-shm/-journal` 或读锁冲突则停止本次刷新，不复制在线 DB、不创建原 SHM、不迁移或恢复原库。核验期间原文件 SHA 改变也会阻断。同步只读取保存的响应，不执行任何外部请求。

1. 持有新 store 的进程锁，先保存 `latest_attempt.state=running`。
2. 核验完整输入和上次已发布的 journal 前缀。回滚、重写、冲突、未知日历、未完成采集或时钟错误阻断发布。
3. 生成确定性的内容 JSON，以 UTF-8、键排序、紧凑分隔符、无 NaN 计算 SHA-256。
4. 在新 store 的单个 SQLite 事务中插入完整快照、切换 current 指针、保存 succeeded。使用 `synchronous=FULL` 与 WAL，支持读者读取上次提交。相同内容复用同一行及首次 `verified_at`，只更新本次尝试时间。
5. 失败保存 blocked/错误码，上次快照仍可核验和读取；进程突然终止时未提交事务回滚，最后尝试可保留 running，表示**未确认完成**。显式重试重新核验，不清除旧快照。

`snapshot_sha256 = SHA256(canonical(content))`；`snapshot_id = eod-v1:<SHA>`。内容包括来源 genesis/HEAD/链、模式、日线版本与选择、raw 摘要/时间、覆盖/缺口和研究门禁。`verified_at` 是首次完成本地核验的墙钟采样，保存在内容之外，不参与市场内容身份，也不是持久可见时刻或外部时间认证。重复刷新、重启、不同 store 不因墙钟变化产生不同市场内容 SHA。

`latest_attempt` 与快照分开：`started_at/finished_at/state/error_code/blockers`、本次读取的 `journal_head/source_database_sha256`、`source_changed/new_append`。前缀未验证时 `new_append=null`；失败保持旧快照自己的源日、时间和哈希。`source_changed` 仅比较上次发布与本次读取的 HEAD，不表示发现新有效交易日。

## 快照字段与研究资格

所有时间为 UTC epoch 毫秒；源日用 Asia/Shanghai 的 `YYYYMMDD`。CLI 默认只输出元数据，不输出行情值或 raw 正文。

| 字段 | 含义 |
| --- | --- |
| `schema_version=1` | 内容版本；消费者拒绝未知版本 |
| `data_mode` | `forward_observed_eod` 是原观察证据；固定 fixture / 带 synthetic 标记的测试 journal 只能是 `synthetic_test` |
| `last_valid_source_day` | 已校验有效日线的最大源日；刷新时间和本地“今天”不会前移此字段 |
| `journal_genesis/journal_head/event_count/journal_chain` | 本次一致读的原 journal 版本/前缀，不是新的 Collection |
| `raw_sha256` | 原响应 SHA、API、原事件序号与实际 received_at；没有正文 |
| `bars/versions/attempts` | 本地保存的规范化日线、各版本及重复/修订/晚补引用；选择各源日的最新已核验版本，保留原可得时刻 |
| `observed_at/received_at/available_at` | 各版本按实有字段；CLI 概览对应最大有效源日的选中版本 |
| `provider_published_at=null` | 当前来源未提供独立发布时间；不能用 HTTP Date 或 verified_at 代替 |
| `available_at_semantics` | 原值是进程内校验后、SQLite 提交前墙钟采样；不证明精确持久可见或开盘时已可得 |
| `coverage/gaps` | 从原 genesis 日至原最后事件日的逐日覆盖；日历来自保存的 raw，不推断工作日；晚补不修复当日观察缺口 |
| `warnings/blockers` | 晚补/修订/缺当日观察等可标注研究；冲突/未知日历/clock fault/pending 则阻断新快照 |
| `can_research` | 快照内仅指可做标注的本地研究；status/consume 的有效值还要求最近同步 succeeded |
| `can_execute_forward_paper=false/live_allowed=false` | 固定拒绝；无提案、交易、现金、NAV 或资格写权限 |
| `historical_pit=NOT_VERIFIED/opening_source=BLOCKED` | 两日 EOD 与可读时间不能解锁开盘或历史 PIT |

`historical_replay` 继续走现有历史输入/评价链路，**不接受历史报告作为本 EOD observer**，不与上述两类补日线或构造 forward NAV。当前快照是版本化研究视图，后来的修订适用于研究，不能回写成修订前已知数据。原报告和 `forward-eod-at` 的历史时点语义不变。

`status` 给出 `wall_clock_day`、`source_day_differs_from_wall_clock` 和 `calendar_after_snapshot=UNKNOWN_NOT_FETCHED`。范围只截至 journal 的事件日；不把后来经过的每个工作日猜成开市缺口，不因可核验就声称今天新鲜。`status/consume` 不轮询原源文件；新 append 需显式 `sync` 才会被发现。

## 只读消费 adapter

`research/data_snapshot.py` 的 `Store(name).read_snapshot()` 返回 `(snapshot, latest_attempt)`，内含本地日线；消费者必须结合后者判断可用性。`Store(name).consume()` / CLI `consume` 是**本期已接通的研究消费者**：重新核验内容版本/SHA、genesis/模式绑定和固定权限字段，输出 `source_day`（YYYY-MM-DD）、`data_mode/snapshot_sha256`、质量与最新同步状态，不创建 Agent 任务、不调用 Provider、不写 Agent SQLite。

本地 Python 可直接 `from research.data_snapshot import Store` 后调用 `Store("owner-eod").consume()`；完整数值保留在 `read_snapshot()` 返回的本地 `content.bars`，不进入默认 CLI/脱敏证据。

这是供后续 Agent/候选接线的稳定接口与可运行 offline consumer；**没有替换现有 Agent `InputSummary` 的报告投影、EOD 调度或 Dashboard 启动时 pin 的六报告**。返回 `eod_eligible=false`。没有外部 JSON 导入/资格覆盖接口；模型自然语言不能升级数据等级。只改快照模式并重算 SHA 仍会与独立保存的来源绑定冲突。

信任基础是 Owner 指定的既有 observer 和本机受信保存目录；本地链/哈希不能抵御有全部文件写权限者重写整个来源与状态库，也不认证远端来源或供应商许可。本次未增加秘密、云外发授权或交易权限。
