## 数据与权限

V2 只调用 `adj_factor`、`suspend_d`、`stk_limit`、`daily_basic`，使用 Owner 已有 2000 积分账号。原 Tushare HTTPS、凭据读取、重定向拒绝、Token 回显拒绝、锁、raw 原子写入及 lexical no-link 检查复用 PR #58；V1 生产模块不改动。V2 不写旧目录、未复权日线、旧 checkpoint、Observer/Operator、Snapshot、Agent/Budget、Paper/Risk 或 Ledger。

本期始终保持：

```text
data_mode=historical_backfill_ex_post
coverage=PARTIAL
historical_pit_status=NOT_VERIFIED
forward_research_readiness=BLOCKED
paper_allowed=false
live_allowed=false
```

`obtained_at` 是真实下载结束 UTC 时间；供应商当年发布时间、历史修订过程和历史接收时间未知。V1 当前目录不能证明全历史证券身份，北交所独立日历仍未核实。这些缺口不会因下载完所有日期而自动消失。

| API | 精确保留内容 | 日期状态的含义 |
| --- | --- | --- |
| `adj_factor` | 正且有限的原因子，原代码、日期、来源版本 | 官方未给明确单次行上限，普通日仍标 `PARTIAL / TRUNCATION_OR_UNIVERSE_UNVERIFIED_UNDOCUMENTED_CAP`；不自证穷尽 |
| `suspend_d` | 明确分别请求 S/R，保留日内区间、多个事件和零事件日期 | S/R 两次响应通过且低于各自 5000 行时可为 COMPLETE；只说明事件响应已处理，空事件不证明可交易 |
| `stk_limit` | 元计价的上下限及真实返回的昨收、asset_type、exchange | 5800 行即截断嫌疑；来源交易所与代码后缀冲突原样保留并降为 PARTIAL；限价不等于可成交 |
| `daily_basic` | 真实可得估值/换手/股本/市值字段，缺失字段另记 manifest | 6000 行即截断嫌疑；合法 NULL、负估值、零保留，不填值、不转 float；`limit_status` 仅在供应商实际返回时存在 |

`turnover_rate / turnover_rate_f / dv_ratio / dv_ttm` 是百分数；`total_share / float_share / free_share` 是万股；`total_mv / circ_mv` 是万元。请求字段和实际缺少的可选字段都能追溯。B 股代码家族单列，其他非 A 股或身份未核实代码标 `NON_A_OR_IDENTITY_UNVERIFIED`，不将 `stk_limit` 全部返回行叫作 A 股。按代码家族识别也不构成历史身份认证。

实现时核对的官方接口：[复权因子](https://tushare.pro/document/2?doc_id=28)、[停复牌](https://tushare.pro/document/2?doc_id=214)、[涨跌停价格](https://tushare.pro/document/2?doc_id=183)、[每日指标](https://tushare.pro/document/2?doc_id=32)。[频次表](https://tushare.pro/document/1?doc_id=290) 当前将 2000 档列为每分钟 200 次、每 API 每天 100000 次；不能套用 5000 档无总量限制。没有获准的剩余额度查询端点，报告明确 `UNKNOWN_NO_AUTHORIZED_BALANCE_ENDPOINT`，不将本地剩余硬预算称为账号剩余额度。

## 前台采集和恢复

Python 3.12 标准库；不启动旧服务。以下命令在本 worktree 根目录执行。首次需要一个已存在的 V1 仓库，只读冻结其中的目录/日历和原请求来源 SHA。原 V1 数据无需复制，也无需迁移。

```powershell
python -I -B scripts/historical-sidecar.py plan

python -I -B scripts/historical-sidecar.py preflight `
  --v1-root '<已有 V1 仓库目录>' `
  --credential-source existing-tushare-mcp-config --rpm 60

# 预检通过后，同一 Owner 授权下立即执行整个冻结区间
python -I -B scripts/historical-sidecar.py backfill `
  --credential-source existing-tushare-mcp-config --rpm 60

# 有明确失败记录时先核对其原因，再显式恢复
python -I -B scripts/historical-sidecar.py resume `
  --credential-source existing-tushare-mcp-config --rpm 60

# 确认前次未知/限额结果、冷却和恢复条件后，显式重试失败 scope
python -I -B scripts/historical-sidecar.py resume --retry-failed `
  --credential-source existing-tushare-mcp-config --rpm 30
```

默认单 worker、60 次/分钟，CLI 硬上限 120，低于官方 2000 档 200；实际频控/权限响应优先。真实运行遇到网络中断（Owner 反馈与本机网络切换相关）后，V2 在不改 V1 的前提下将 HTTP 读取等待延长到 120 秒，继续复用原固定 HTTPS/重定向/密钥检查；超时仍持久为未知并停止，不自动重发。本次已知 1212 个开放日，预算按 `5 × open_days + 8`（停牌与复牌分别请求）加 15% 或至少 100 次余量，并考虑一次有界分区余量，首次持久上限为 **6979 次**。`--total-call-cap` 只能在首次预算建立时选择；resume 不自动扩大。`--max-calls` 可进一步降低一轮调用量，每个真实错误/未知尝试也消耗预算。

每次请求前检查磁盘至少剩余 1 GiB、单轮和累计上限及持久限速。实际启动器还依据预检落盘量估算整个区间的空间需求并核对可用空间。只在 25%、50%、75%、100% 的 API×日期提交节点输出进度。

429、供应商频控、鉴权/积分拒绝、日额度耗尽、网络结果未知会保存 attempt 和收到的 raw，并停止该轮；没有内部自动重试、购买、升档或换账号。额度耗尽标 `PARTIAL_QUOTA_LIMIT`。跨进程保留冷却；超过一分钟的剩余冷却直接返回 `QUOTA_COOLDOWN_ACTIVE / RATE_COOLDOWN_ACTIVE`，不让进程挂着等一天。普通 resume 跳过失败 scope，显式 `--retry-failed` 才重试；已准入的 COMPLETE 和 PARTIAL 日期都跳过，不反复下载未知 cap 的因子日期。

进程在收到原响应后、日期提交前中断，恢复时可以复用同参数的完整成功 raw。`SENDING` 则恢复为 `NETWORK_OUTCOME_UNKNOWN`，不会按已成功处理。没有永久后台、开机服务或新定时任务。

## 版本、截断和存储

```text
state/historical-sidecar/<store>/       # 独立 ignored，只在 Owner 本地
  warehouse.sqlite                    # schema 2013 / FULL / WAL
  writer.lock                         # 同仓库唯一写者
  raw/00000001.json.gz                 # 原 HTTP body，SHA 针对解压字节
```

连接前拒绝自身/祖先/内部 SQLite、WAL/SHM、锁、raw 的 symlink 或 junction；异类 SQLite 在修改 journal 前拒绝。只读命令锁住已存在的文件，以 immutable/query-only 连接读取；活动 writer 或未恢复 WAL 会明确拒绝，不创建文件、不联网、不读 Token、不改 bytes/mtime。

每次 attempt 保存 API、精确参数/请求字段、凭据来源标识、Owner 权限来源、实际起止 UTC、HTTP/供应商码、原响应字节 SHA/大小、canonical SHA 和 metadata SHA。每日版本、全部行、source links 与 checkpoint 在一个 SQLite 事务提交。manifest 绑定合同/单位、冻结目录、请求来源和上一版本。

已准入版本刷新时，空响应、缺证券/事件、丢失先前来源字段、或 COMPLETE 降级的响应只进入 raw/attempt/rejections，不替换原 checkpoint。合法同日修订形成新版本；改回更早数值也保留修订时间线。相同当前内容不增加行版本。旧 as-of 始终能读到原冻结输入。

达到已知 cap、因子 sentinel 6000 或疑似整千平台时，不把响应当完整日期。合并可信目录与原响应代码，按每组最多 200 个 `ts_code` 有界重查（S/R 仍分开），检查返回 scope 和原行重合一致性；扩张前核对剩余硬预算。当前真实预检未命中 cap；多代码分片的生产解析/合并由 recorded HTTP 测试覆盖，真实账号若不接受该参数形式会停止，不能声称已获真实分片兼容认证。即使成功分片，也保留 `PARTITIONED_KNOWN_UNIVERSE_UNVERIFIED / PARTIAL`。

## 只读研究查询与复权

```powershell
python -I -B scripts/historical-sidecar.py status
python -I -B scripts/historical-sidecar.py report
python -I -B scripts/historical-sidecar.py verify

# 20 个交易日；将 --api 依次换为四种接口
python -I -B scripts/historical-sidecar.py query --api daily_basic `
  --start 20211101 --end 20211126 `
  --symbols 600000.SH,000001.SZ,600519.SH --limit 100

# 单日全市场；分页不会把截断输出说成完整输出
python -I -B scripts/historical-sidecar.py query --api stk_limit `
  --trade-date 20261030 --limit 10000 --offset 0

# 必须明确锚点及两仓库版本上界；示例中的版本号用真实查询版本替换
python -I -B scripts/historical-sidecar.py adjusted `
  --v1-root '<已有 V1 仓库目录>' --symbols 600000.SH `
  --start 20211101 --end 20211126 --anchor-date 20261030 `
  --as-of-version <V2因子版本上界> --daily-version <V1日线版本上界> `
  --adjustment qfq
```

查询给出逐行来源、质量、query SHA，以及覆盖日期的版本/来源 SHA/缺口；零事件日期也保留来源。前复权按冻结版本的 `raw_price × factor(date) / factor(anchor_date)` 推导，后复权 `raw_price × factor(date)` 单列。显式 Decimal 上下文精度为 50，输出是研究推导值；原 OHLC、因子、价格和旧日版本都不覆写。没有当时可得版本，结果始终 ex-post。冻结因子/V1 日线的版本上界和 query SHA，后来下载的新锚点因子不会改变旧视图；这不接现金分红账务或自动调仓。
