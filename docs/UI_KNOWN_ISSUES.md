## 2. 本轮范围内未做/延后

1. **首次使用协议页的数字是静态文案**：¥100,000 初始资金、最多 2 只、单票 ¥20,000、
   日亏损 2% / 回撤 10%、云端 ¥5/日 / ¥100/月、84 个交易日、10 年有效期等来自产品当前
   默认配置，页面未从运行配置动态读取。若 Owner 修改账户参数，协议页需要同步（建议
   后续由后端提供“当前账户规则”只读摘要，前端再渲染）。
2. **旧深链**：`#history/strategies` 与 `#history/research` 已不再是 Tab；前端会把它们
   解析到成交 Tab，避免白屏。若希望给旧链接一个“已迁移”提示，可后续补充。
3. **未挂载组件**：`ResearchOperations.tsx`、`MarketResearchPanel.tsx` 没有出现在任何
   路由中（历史遗留），本轮未接入也未删除；其中包含大量内部术语（Owner/Provider/
   payload/BLOCKED）。若未来接入必须先按术语表改写。`Badges.tsx` 的
   `SnapshotBadges/toneForBoolean` 等也将随页面改造逐步淘汰。
4. **图表与回撤指标**：保留现有真实计算与展示；“最大日回撤”等指标未被重新定义。
5. **浏览器自动化**：仓库既有的 Playwright 用例大多针对旧版 Owner 令牌解锁流程与旧文案，
   与 0.3.0 单机同源模型不一致；本轮更新了单元测试（`npm test`）并新增术语/状态映射
   单测，浏览器级验收以本地截图工具与人工检查为准（见 `docs/ui-evidence/README.md`）。
6. **截图数据**：改造前后截图使用仓库自带 sample report + 本地 fake research fixture
   （CNY 预算测试配置）。它不是真实行情/真实云调用，不能当作产品收益证据；真实安装数据
   全程只读、未被修改。

## 3. 真实安装数据的说明（任务 #1/#10/#20）

- 这三个 ID 不是测试任务、也不是重复付费任务，而是全市场研究阻断时由 Python 写入的
  “研究阻断状态通知”：`provider_id=market-research-status`、`calls=[]`、`result=null`，
  按源日 + 原因去重（#1=20261030、#10=20261102、#20=20261105）。
- 真实阻断原因分别是“行情目录晚到/回填，不能作为当日决策证据”与“本地研究阶段异常”；
  与“84 天暖机”无关（补录 `sessions_ready=87, remaining=0` 已完成）。
- 处理建议：**保留不删**（审计证据，且没有删除 API）。UI 已归入“研究未运行”，用橙色
  “需要处理”展示，不冒充任务失败，也不占用资金/预算。

## 4. 文案/视觉残留检查

- 主界面（诊断折叠区除外）不得出现 `not_configured`、`PIT`、`daily.open`、`EOD`、
  `Supervisor`、`Owner`、`Agent`、`Paper`、“见技术详情”“占位”“不调用模型”
  “不发起推理”、hash、内部版本串。全站术语见 `docs/UI_TERMINOLOGY.md`。
- 若后续新增页面/组件，请复用 `apps/dashboard/src/lib/copy.ts` 与
  `apps/dashboard/src/lib/status.ts`，不要新造状态词。

## 更新（2026-11-06）：后端实现后的已解决项与当前限制

### 已解决

| 原问题 | 处理 |
| --- | --- |
| 预算不可在页面修改（B1） | 已提供 `POST /api/agent/budget`，AI 研究页与设置页均可编辑；低于已结算+预留需二次确认 |
| 研究失败只有英文码（B2） | 后端 `reason_text` + 前端映射；主界面不显示原始码，诊断区保留 |
| 通知标题/结论/分类需前端 join（B5） | 后端直接返回 `name/conclusion/provider_id/kind/unread_count` |
| “已标记完成”不可撤销（B6） | 设置页可撤销首次设置（经确认，幂等） |
| 构建信息缺失（B10） | 关于/诊断显示 build、repo、issues |
| Paper 永远被 `OWNER_PORTFOLIO_POLICY_REQUIRED` / `PAPER_LOCAL_INPUT_OR_LEDGER_UNAVAILABLE` 阻断 | 首次成功采集后自动启用默认 Paper 策略；模拟确认/冻结链路恢复 |
| 安装版 dashboard 持有 agent.lock，自动研究永远无法运行 | dashboard 改为观察者模式，后台 watch 独占研究执行 |
| 代码更新后研究永久 `SCREEN_IMPLEMENTATION_CHANGED` | 未派发云任务的阻断运行可重建 screen/plan；有云端任务时仍严格拒绝 |
| 云端返回 JSON 模式回显 `type=json_object` 导致 `PORTFOLIO_SCHEMA` | 在解析边界剥离该传输字段并记录本地诊断；不再重试已不确定的计费调用 |

### 当前限制（诚实说明）

1. **观察者模式下手动新建研究不可用**：安装版由后台自动研究执行任务，按钮禁用并显示原因；
   这是“单一研究执行者”设计，避免 dashboard 与 watch 争抢 agent.lock。
2. **真实安装 2026-11-05 的云端研究已被拒绝**：当日上午的 billable 调用返回内容不符合契约，
   产品按“未知结果不自动重试”保留 `outcome_uncertain`；该日不会补跑。修复后的代码在下一交易日
   自动流程中生效（当晚在隔离数据副本中已验证 `CANDIDATE_FROZEN`）。
3. **跨日后再补研究上一日不可行**：研究要求决策时点与 84 会话上下文同日盘后；午夜后不应补跑。
   这是时点规则，不是缺陷。
4. **Paper 成交需要下一交易日开盘数据确认**：冻结批次后等待 T+1 日线；首日验证只到冻结点。
5. **默认策略自动启用是 Paper-only 的产品默认值**：不接券商、不产生真实委托；仍可在账本层暂停。
