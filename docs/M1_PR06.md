## 工具职责

`scripts/research-evaluate.py audit` 只审计来源/单位/日历/价格带/断点并产生新 `audit.json`、`input/dataset.json` 和 `split.json`，不读取收益。复用原 `historical-data.py prepare`，不扩大其 CLI 适用期或跳过失败。

`evaluate` 从原 SQLite 的只读连接备份到新目录，然后让原 Rust `paper-report` 打开副本、重放验证 v3 链并重导出六报告；要求与提供的六报告逐字节相同。原库、writer.lock、输入和原报告不写。再独立复核逐日 `cash + held×close = NAV`、成交增减/费用、已实现+未实现 P&L 与资金流。缺估值时相关回报/回撤为 null，不跳过空值计算“完整”表现。

`paper-benchmark` 是隔离的新研究 CLI：每个窗口首日收盘按已知 close+ceil(2%)、夹在当日价格带内，提交一次 100 股买单，下日仅一次 next-open 尝试，然后只持有。首日持现金；不依据 SMA 第一笔买入日、盈利或事后价格选择入场。使用原 `Ledger`、`HistoricalNextOpenV1`、Risk 和 FeeSchedule；没有第二套撮合/费率实现。失败/停牌/无下一日为 NOT_EVALUATED，不再择日；末日 pending 保留可见。各基准是互相独立的假设比较，不是策略账户资金复制。窗口 NAV 超出原授权模拟本金则不启动新基准。

新 `evaluation.json`/`evaluation.csv` 绑定 protocol SHA、dataset SHA、策略/成交/费用/滑点、ledger HEAD、六报告 SHA、分界和三维结论。完整输出与 benchmark ledgers 均只在本机 ignore 目录，GitHub 只有此脱敏汇总和[自测证据](evidence/m1-pr06/README.md)。
