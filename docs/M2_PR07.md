# M2-PR07：EOD 自动研究与候选归档 V1

对应 [Issue #43](https://github.com/handFOOLed/Stratide/issues/43)，固定 base `dd39133d656298d1bef6f5b799e28284f627783f`。一个独立 worktree、一个分支、一个 Draft PR。Sol 独立开发、自测和修复，`agents=0`；ChatGPT 审查固定 HEAD，Owner 明确授权后才可合并。开发自测不是独立验收。

本模块是 **LOCAL_FAKE_ONLY / RESEARCH_ONLY** 的前台自动研究工具。复用 PR33 快照、原 Agent 任务/调用/预算与 PR30 候选注册；没有第二个 Agent、预算账本或策略执行器。

```text
Owner 本机 init → enable（默认 OFF）
  once / 前台 watch
    → 可选 --sync：只读已绑定 observer，不采集行情
    → 原快照 reader + 原 observer 重新核对 + 上海当天/on-day/16:00/24h
    → 原 Agent SQLite meta 保存冻结触发意图
    → 原 tasks.trigger_key 去重 → Agent::tick → 持久 fake calls/result
    → 从实际 SQLite 导出 completed 任务 → 原 candidates.register 重校来源
    → 内容寻址候选 → 原 Agent meta 保存归档 SHA
  status / task / candidate：只读已保存状态，不运行模型
```

## 使用

Windows、Python 3.12+、现有 Rust/MSVC 缓存即可。所有命令从本 worktree 根目录执行：

```powershell
$env:CARGO_INCREMENTAL = '0'
pwsh -NoProfile -File scripts/with-msvc.ps1 build -p stratide-research --locked --offline

# 原 observer 已由 Owner 授权并保存；此命令只读核验，不访问网络。
python -B scripts/research-data.py --store owner-eod sync --observer '<既有observer目录>'

# 必须使用未存在的名称；自动研究目录、Agent 与候选 registry 都是新的。
python -B scripts/eod-auto-research.py --name owner-auto init --snapshot-store owner-eod
python -B scripts/eod-auto-research.py --name owner-auto status
python -B scripts/eod-auto-research.py --name owner-auto enable
python -B scripts/eod-auto-research.py --name owner-auto once --sync

# 前台持续检查；可 Ctrl+C 停止，也可 --cycles 1 只检查一轮。
python -B scripts/eod-auto-research.py --name owner-auto watch --sync --interval-seconds 300
python -B scripts/eod-auto-research.py --name owner-auto pause
python -B scripts/eod-auto-research.py --name owner-auto resume
python -B scripts/eod-auto-research.py --name owner-auto disable

python -B scripts/eod-auto-research.py --name owner-auto task 1
python -B scripts/eod-auto-research.py --name owner-auto candidate '<registration_sha256>'
python -B scripts/eod-auto-research.py --name owner-auto cancel 1
```

只有原 observer 中存在当前上海源日、原始 on-day 可得时间均在 16:00 后、已完成新鲜同步且质量允许，`once` 才会创建当天任务。市场是否开市由已保存日历/观察决定。固定 `sync --fixture` 的 10/26–10/27 样例在真实当前时钟下会跳过；不会把它改成今天。可复现的 synthetic 成功链路见下面测试命令。

`watch` 间隔 **60–3600 秒**，默认 300 秒；`--cycles` 可限制循环次数，默认持续运行。Ctrl+C 只停止当前前台程序，持久 enable/pause 状态仍保留。没有安装系统服务、任务计划或自启。`disable` 与 `pause` 是单独的本机控制命令，可在另一终端运行；disable 阻止新任务，pause 使用原 Agent 的 `paused` 位。已经提交的 fake 按原语义保存结果；取消也不抹掉已经发生的调用/费用。

退出码：**0** 为查询/控制成功、完成或已归档重复触发；**3** 为 `OWNER_DISABLED / OWNER_PAUSED / BEFORE_EOD_WINDOW / MISSED_OR_STALE / NO_VALID_CURRENT_EOD` 跳过；**2** 为来源、配置、并发或恢复阻断。每次输出一行 JSON。`watch` 每轮使用相同逻辑；没有异常成功的空任务/空候选。

## 本机状态与信任边界

`init` 只新增 git-ignored `state/eod-auto/<name>/` 与 `state/candidates/<name>/`。不可覆盖已有目录、Agent、候选或 observer；失败的部分初始化也不会由下一次 init 重建。`config.json` 固定 `snapshot_store_name`、相对 `agent_dir=agent`、同名 registry、`mode=local_fake`、版本化 policy 与来源身份 SHA。`enabled=false` 保存于原 Agent SQLite，不能靠重新启动自动变成 ON。

触发意图、归档 SHA、Owner enable/pause 均存入原 Agent `meta`；原 `tasks/calls` 是任务与研究事实的唯一来源。`status.json` 只保存最近运行原因，不作为是否调用/归档的依据。来源身份包含原绑定的 genesis、模式、来源 kind/本机路径身份；CLI 只输出其 SHA，不输出绝对路径、账户数据、凭据或原始行情。

同一自动目录持有 OS 生命周期 `once.lock`，Agent 仍持有原 `agent.lock`。两进程不能同时执行一次链路，进程退出后 OS 释放锁。任务创建事务中重新检查 enable/pause，与 Owner 控制串行。Owner 控制不等待正在运行 fake 的 Agent 锁；自动库的 SQLite 写入等待为 5 秒，并缩短控制写事务，避免控制写与结果保存竞争造成存储失败；旧 Agent 保持 500ms 等待。

PR #44 的 P1 修复增加跨名称归属：`state/eod-auto/.bindings/<binding_sha256>.json` 持久记录唯一实例，首次 enable 在同 binding 的 OS 锁下原子保存。相同 store 可 init 多个默认 OFF 目录，但只有归属实例可以 enable/once；Python 与 Rust 任务桥都校验它。竞争时返回 `EOD_AUTO_BINDING_BUSY`，其他实例返回 `EOD_AUTO_BINDING_OWNED`。disable、退出或重启不释放归属，不能换名称重做同源日研究；不同 binding 独立。

新入口遇到尚无归属记录的旧目录，只读核查相同 binding 的原 Agent：只有一个实例已有意图/任务时保留它的归属，即使它已关闭；多个旧实例都有意图，或相关旧状态无法核实，返回 `EOD_AUTO_BINDING_REVIEW_REQUIRED`，不迁移、删除或重写旧库。`status` 只读显示 `binding_owner/ownership_state`；没有新增自动接管/转移入口，也不向 observer/snapshot store 写归属信息。双实例进程 E2E 与修复前反例见 [P1 补充证据](evidence/m2-pr07/p1-cross-instance/README.md)。

`eod-auto-agent` 是仓库内固定 argv 桥，不执行 shell。只有新 `init` 写入 `Settings::fake()`。每次操作先检查所有 model 都是 `kind=fake`、无 endpoint/key、价格及预算均为 TST；真实 Provider、真实币种或其他非 fake 配置直接 `EOD_AUTO_LOCAL_FAKE_ONLY`，发生在 DNS、Key、真实预算预留和 Provider 前。仍调用原授权与 Budget Gate，旧 grant/暂停/取消/预算不足继续有效。自动路径不启用 fake 的安全重试场景；失败/未知结果需要人工检查，不另造当天任务。

原 `paper_summary_v1` 报告型 EOD 调度仍由原开关控制；原快照手动入口仍为 `EOD_SNAPSHOT_MANUAL_ONLY`。本次仅把旧报告的过期取消限定到原 `eod-v1:` 键，防止误取消独立 `eod-auto-v1:` 任务。没有新 HTTP 路由或远程权限。

## 时间、唯一触发和恢复

唯一键为 `eod-auto-v1:<绑定来源/所选store/policy的SHA>:<源日>`，不包含 snapshot SHA、随机 run 名或触发机器日期。输入在意图与原任务中冻结；同源日重新同步、修订 SHA 或重启都不能再研究一次。

每次新研究先复用 PR33 Python reader 和 Rust `SnapshotSource::read` 的 WAL、版本、SHA、权限、质量及 24h 检查，再以原只读 verifier 核对 observer 与最新发布内容/源文件 SHA，拒绝 sync 后发生的未发布变化。自动入口还在 SQLite 打开前拒绝缺 SHM、损坏 WAL 头，避免 SQLite 忽略坏 WAL 后返回旧主文件。WAL 的提交/未提交视图仍由 SQLite 管理。

判断采用真实进程时钟的 Asia/Shanghai 当天与原 `observed_at/received_at/available_at`，不采用 `verified_at` 代替市场时间。晚补、隔日、过 24h、未知日历或缺有效日均不会建立新研究。Python 与 Rust 的生产入口均没有测试时钟或 `--now` 参数。

| 已保存节点 | 重启行为 |
| --- | --- |
| 已记录意图，未建任务 | 以同一冻结意图及 trigger_key 建原任务；源日过期则保留 `MISSED_OR_STALE` |
| 原任务已排队，未研究 | 当前来源仍等于冻结输入且仍为当天才调用原 `tick`；不替换输入 |
| 原任务已完成，未登记 | 直接读原 completed/calls/result，重校来源后登记；不重跑 fake |
| 登记已完成，尚未写回 SHA | 按真实冻结任务定位内容寻址登记，校验后补记原 SHA；不再次登记或刷新登记时核验等级 |
| SHA 已保存 | 校验原任务与登记，返回 `ALREADY_ARCHIVED_INPUT_FROZEN`，0 新任务/调用/登记 |

来源已变化/过期而原结果尚未登记时，保留 `SOURCE_CHANGED_REVIEW_REQUIRED`。运行中/失败/取消/未知结果不会冒充 completed；`status/task` 提供人工复核材料，不盲重试或删库。错过的旧日意图/排队任务保留原因，旧排队工作取消而不补跑；后续真正观测到的新日仍可继续，旧复核标记保留。

## 归档与资格

自动归档只从本绑定 Agent DB 导出实际 completed 任务，核对 frozen input、fake result、真实 settled call 和来源。公开入口不接受外部 `result.json` 或 `--agent-task`。已有 `task-export.json` 每次从真实 DB 重建，伪造文件不能驱动自动归档。

调用原 `Registry.register`，保存实际 task ID、输入版本/源日/snapshot SHA、model/provider 版本、调用明细与 `registration_sha256`。`candidate` 是冻结研究文本与来源查询，没有策略 freeze/evaluate/执行。保持 **RESEARCH_ONLY / NOT_EVALUATED / ELIGIBILITY_DENIED**；`SNAPSHOT_CONTENT_VERIFIED_AT_REGISTRATION` 只指登记时本机来源内容匹配，原 `TASK_ORIGIN_NOT_ATTESTED` 标签不被升级。

`synthetic_test`、`forward_observed_eod`、`historical_replay` 与 `EXPLORATORY_EX_POST` 不互相改写；`eod_eligible=false / can_execute_forward_paper=false / live_allowed=false`。没有新增前向提案、持仓、盈亏、Paper 财务或交易许可。
