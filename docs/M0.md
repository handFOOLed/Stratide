## Goal

Establish a small cross-platform repository that Codex can operate in after `grill-with-docs` settles trust boundaries and the first production strategy contract.

## What this scaffold includes

- Cargo workspace with tiny `stratided` and `stratide-cli` placeholder binaries and shared `contracts` library.
- Product principles, open architecture proposal, risks, and Codex agent guardrails.
- A focused `grill-with-docs` decision agenda.
- No runtime service, trading features or live credentials.
- No adaptive strategy budget or decay-detection module (ADR-025); only simple paper accounting/risk contracts now. Implementation of dynamic sizing is a future separately tested phase.
- ADR-026/ADR-027 strategy registry, shadow-observer pool, historical failed-strategy lookup, log archiving and model retrieval are excluded from M0; start with the existing single paper strategy.
- ADR-028 is a **future initial-live boundary** only: dedicated broker account, not routine mixed manual/automated trading. M0 does not select brokers, open accounts or implement live reconciliation.
- ADR-029/ADR-030/ADR-031 define future Owner emergency takeover: explicit handback; Keep, red Attempt Cancel and opposite-side Cancel controls; and extra inline acknowledgement when cancelling protective orders. M0 has no manual execution control, broker cancellation or live management UI.

ADR-032/ADR-033 document future manual-trade suspense and explicit Owner assignment to groups; neither adds implementation or UI to M0.
ADR-035 defines future automatic record-date dividend and bonus-share attribution, not a corporate-action engine to build in M0.
ADR-036 adds future Owner-gated voluntary rights and issuer elections, without an approval UI, subscription or broker interface in M0.
Owner clarified the initial live account is automation-only with no routine manual purchases; no separate permanent manual portfolio or mixed-trading feature is required (Q34).

## Approved execution priority and handoff (ADR-037)

M0 is the **minimum deterministic paper trading core** and should be completed before any new speculative architecture debate. Once accepted, M1 will provide forward paper observation with authenticated, provenance-tagged market data and daily reports, not just replay of historical inputs. Full PR order and Sol/Terra/ChatGPT handoff gates: [PAPER_TRADING_ROADMAP](PAPER_TRADING_ROADMAP.md). GPT-6.1 Sol implements; GPT-6.1 Terra independently tests and merges after ChatGPT code review and resolved blockers; the Owner approves scope and observes results. No M1 market feed, live broker, AI researcher or dashboard inside M0 by default.

## Actual M0 implementation exit criteria (next phase)

1. Resolve minimum proposal, portfolio, risk and order contracts including stable group, version and deployment attribution fields (ADR-019/ADR-020/ADR-021/ADR-022/ADR-023/ADR-024). M0 remains one paper group and one strategy, without multi-group funds accounting, cross-group order netting or virtual reference-price attribution.
2. Implement one **paper-only** order-intent → risk decision → simulated order → shared-cash/positions ledger path, with an explicit Owner-authorized starting-principal cap (ADR-008) and narrow execution-time/fill/cost policy compatible with ADR-007; do not claim a complete daily market simulator.
3. Show deterministic replay of that path for a fixed input, including one realistic risk rejection.
4. Persist paper-order/risk/ledger state involved in the vertical slice under a single-writer simulation authority; test a focused crash/restart and no-duplicate simulated-order case (ADR-017). Include a **small cash-flow-adjusted portfolio-equity valuation and unrealized-loss breaker rejection/persistence test** (ADR-018), without building a general live valuation engine. No real broker reconciliation is claimed.
5. Run local basic verification on Windows and a Linux build smoke test; if unavailable, mark unverified.
6. Finish when acceptance criteria pass and no known material financial-integrity risk remains in the implemented scope.

## Explicit exclusions

No real broker, no cross-machine trading failover or distributed leader election (ADR-017), no market subscription, no AI strategy generation, no autonomous promotion, no full local/remote Worker or OS sandbox implementation (ADR-014), no Data Manager/provider-integration platform (ADR-015), no mandatory WASM, no remote web endpoint, no polished dashboard, no multi-agent framework, no broad validation matrix, no paid CI.
