# UI 产品化改造总结（按页面）

> 基线：`70b2828`（feat/ui-product-ux 起点）。本轮只改前端展示层：文案、布局、
> 交互、组件与样式；未改后端 API、数据语义、风控与账本逻辑。术语口径见
> `docs/UI_TERMINOLOGY.md`；截图见 `docs/ui-evidence/README.md`；
> 需要后端的部分见 `docs/UI_BACKEND_REQUIREMENTS.md`；遗留问题见
> `docs/UI_KNOWN_ISSUES.md`。

## 0. 全局

- 新增共享状态体系 `lib/status.ts` + `components/ui/StatusBadge.tsx`：只保留
  正常/进行中/需要处理/出错/未设置 5 态，图标 + 颜色 + 文字，禁止页面直接渲染后端枚举。
- 新增 `components/ui/Diagnostics.tsx`：所有技术信息统一下沉到默认收起的“诊断信息”，
  带“复制诊断信息”按钮；删除全部“见技术详情/不调用模型/不发起推理”等开发者话术。
- 新增 `components/ui/Checklist.tsx`、`HealthBar.tsx`、`InfoHint.tsx`；
  新增 `lib/copy.ts`（术语/通用文案/空状态）与 `docs/UI_TERMINOLOGY.md`。
- 侧栏：品牌只出现一次、导航 5 项（总览/交易记录/AI 研究/通知/设置）、底部单一简洁用户入口；
  删除重复的账号菜单与“Paper workspace / 本机 Owner”。
- 顶栏：原“服务在线”弹层改为可点击的系统状态胶囊（正常/需要处理/出错/检查中），
  异常变色，点击进入“系统与诊断”。
- 统一金额（¥ + 千分位）、数量（countText + 单位）、时间（Asia/Shanghai）。
- 响应式：1280 / 1440 / 1920 与浅色/深色全部巡检通过，无横向溢出；表格数字右对齐、
  文本左对齐；每页最多一个主按钮；不可逆操作二次确认。
- 4 个核心概念增加“?”悬浮说明：总资产、交易保护、数据日期、研究预算、模拟成交假设。

## 1. 总览（`#overview`）

改造前：风险提示大卡片写“此快照未记录风控锁/账户锁 0/估值有效”，首屏被技术徽标
（合成测试、读取于）占据；“接下来会发生什么”写着 84 个交易日与风控术语；持仓/成交
各占一张空卡；数量词混用“0 条 / 共 2 笔 / 0 只”。

改造后：
- 顶部健康条：模拟账户 | 数据更新至（+最后有效估值日附注）| 系统状态 | AI 研究状态，
  后两项可点击进入对应页面。
- 第一屏：总资产大字 + 今日盈亏 + 累计收益；可用资金/挂单冻结资金/累计费用/最大日回撤
  降为次级；资产曲线有效点 < 2 时隐藏区间切换，改为一句提示。
- 交易保护：无触发时折叠为一行绿色“交易保护正常”；触发时在资产卡前展开橙色卡，
  显示中文原因（当日亏损/回撤/订单不确定/人工暂停）与“需要人工处理，不会自动恢复”；
  `null` 记录显示灰色“交易保护状态未记录”，不冒充安全。
- “接下来会发生什么”替换为「上手清单」：完成首次设置、配置行情数据源、启用行情自动采集、
  历史行情补录、设置 AI 研究；状态全部来自真实 API，全部完成自动折叠。
- 历史补录口径按 `remaining==0` 判定，显示“历史行情已就绪（N 个交易日）”，不再与
  “84 个交易日”混用（84 的三种语义见后端需求文档 B4）。
- 持仓与成交都为空时合并为一个紧凑空态；去掉“每页 5 笔”等噪音；分页仅在多页时出现。
- PaperPortfolioPanel 重写为普通用户可读的“模拟交易规则”，批次/冻结/拒绝只进诊断区。

## 2. 交易记录（原“历史报告”，`#history`）

改造前：5 个 Tab（成交/订单/逐日核对/策略档案/研究档案）；“源日、逐日核对、隐含持仓、
外部净流入、初始净值、原始原因”等内部词直出；状态列与原因列直接渲染枚举/原码。

改造后：
- 标题“交易记录”，Tab 精简为 成交 / 订单 / 每日账本；策略版本移入页底默认收起的
  “高级记录”，研究报告只留在 AI 研究页；旧 hash 自动收敛到成交，不白屏。
- 成交：空态“还没有成交。系统会在通过交易保护后，按次日开盘价模拟成交。”；
  列名中文、数字右对齐；移除内部策略 ID 列（进抽屉诊断）。
- 订单：状态统一徽标，原“原始原因”改“原因”，已知原因中文映射、未知“原因未记录”，
  原始 reason 只进诊断。
- 每日账本：摘要 4 项（报告区间/交易日数/初始资金/资金转入转出）；表格 7 列，
  数字右对齐；只有 valuation_error 时显示橙色“数据缺失”，正常行不出现孤立破折号。
- 高级记录：策略版本仅作记录 + 快照/meta 诊断；四个抽屉去开发者文案，模拟成交明确
  “这是模拟成交，不是券商真实成交”。

## 3. AI 研究（原“Agent 管理”，`#agents`）

改造前：页序为运行状态/预算/模型/任务；EOD、Worker、Provider、fake、Token 等内部词直出；
任务名带 #编号与模型 key；失败任务无一句话原因；预算同时出现 CNY 与 ¥；“研究模型
已安装/重新安装”混淆云端 API 与本地模型。

改造后：
- 页序：运行状态与主操作 → 任务列表 → 预算 → 模型设置（默认折叠）→ 研究报告。
  页面唯一主按钮为“新建研究”；无运行中任务时不显示“暂停”。
- 任务：名称改“2026-11-05 · 任务名”；状态用统一徽标；结论/原因列展示真实结论或
  可读失败原因，未知写“失败，原因未记录”；取消走二次确认；`provider_id=
  market-research-status` 的阻断通知归类为“研究未运行”（橙色、附原因），不冒充失败任务。
- 预算卡：今日已用 ¥x / ¥5.00、本月已用 ¥x / ¥100.00 + 进度条；未结清预留/调用尝试/
  Token/用量估算收进“用量明细”；预算只读并注明“预算上限由本机配置维护，页面暂不支持
  修改”（没有写接口，见后端需求 B1）。
- 模型：默认折叠；备用模型仅在可选项 ≥2 时显示；云端只写“研究模型配置”，不再出现
  “安装/重新安装”；本地预测引擎（WSL）归入系统页。
- 任务详情抽屉：结论/原因 → 做了什么 → 花费 → 诊断信息（默认折叠）；
  本地测试结果不再把 fake/内部字段展示在主区。
- 研究报告区：重命名并重排，技术字段（PIT/Registry/融合/评估指标/hash）全部下沉诊断。

## 4. 通知（`#notifications`）

改造前：只显示“任务 #id · 状态”，未读是一段文字，“标为已读”会在 5 秒后把全部
通知（含未看过的）自动标记。

改造后：每条通知 = 标题（研究任务已完成/研究未运行等）+ 一句话结论/原因 + 时间 +
“查看任务”跳转（打开对应任务详情）；未读用圆点；“全部标为已读”与单条“标为已读”
都调用真实接口立即生效，不再有延时/批量误标；空态与诊断折叠区齐全。

## 5. 设置（`#settings`）

改造前：分组为 外观 / AI 服务 / 运行与安装 / 数据连接 / 关于；运行与安装页是内部术语
重灾区（Supervisor、EOD watch、WSL、BLOCKED、PID、Token）；数据连接页直接显示
snapshot_id/sha256/evidence_class/PIT/daily.open；关于页是技术栈、N100、备份脚本路径。

改造后分组：外观 / AI 服务与预算 / 数据与行情 / 系统与诊断 / 关于。
- AI 服务与预算：服务商/API Key/测试连接就地反馈；预算与 AI 研究页共用
  `agent.status.budget` 同一数据源（只读）；Key 掩码与端点只进诊断。
- 数据与行情：首屏 3 句人话（Tushare 盘后、每交易日收盘后更新非实时、按次日开盘价
  模拟成交）+「数据完整性」状态行 + 默认收起的「数据质量详情」（全部技术字段）；
  数据日期用 `last_day`，`as_of` 更早时附“最后有效估值日”。
- 系统与诊断：顶部「整体状态」卡（一句话 + 状态灯 + N/7 项正常）；7 个依赖合并为
  一张清单（统一 5 态 + 一句话原因）；首次设置完成后整块折叠；历史补录按
  `remaining==0` 判定完成，完成态提供“重新补录”二次确认；日志默认折叠且
  ISO UTC 时间统一转为 Asia/Shanghai；新增“复制诊断信息”（不含 token/Key/日志正文）；
  保留“检查更新”，并严格区分 有新版本/已是最新/暂时没有/无法检查。
- 关于：只保留版本、检查更新、GitHub Issues 反馈入口；技术栈/N100/备份路径/构建 SHA
  移到 `docs/TECHNICAL_NOTES.md`。
