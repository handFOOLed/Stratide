## 可运行闭环

```text
显式冻结 schema3 synthetic fixture / source SHA
  → 新建 ledger v4（沿用原 events/checkpoint / 单写入者 / 原子事务）
  → record：收盘后按权威整数持仓锁权益
  → ex：应收税前股息 + 同一应收覆盖的扣税负债
  → payment：应收/负债清零，cash 增加净额
  → 统一 Risk/NAV / 原六报告 + cash-dividends.json
  → Python 从源事件、输入价格和成交独立复算
  → 各自独立的买入持有及现金基准 v4 账本、报告和复算
```

本模块为 **P0** 财务改动。普通沪市 `60xxxx` A 股、一个账户/策略组、整数分和整数股；不增加外部入金、Fill、券商功能或 forward schema。CLI 显式 opt-in `paper-dividend-*`，仅接受 `synthetic_test`。底层契约还区分显式 `historical_ex_post_assumption / EX_POST_MODEL_ONLY`，永远 `historical_pit=NOT_VERIFIED / real_account_eligible=false`；本 CLI 不开放真实历史事件注入。

V1 支持同一证券按时间排列、生命周期不重叠的事件。重叠/同日多份事件、重复 ID、混合送转/配股、ETF、未知税或币种均拒绝；需先取得并明确规范化事件，不能把中间不完整应收配上全部除息价格后错误触发金融锁。没有公司行为全类型框架。

## 冻结契约与财务语义

机器输入见 [fixture](../samples/cash-dividend-v1.json) 和 [人工合成源](../samples/cash-dividend-source-v1.json)，类型在 `crates/ledger/src/cash_dividend.rs`。

- 每个事件绑定完整 genesis payload、`event_id/version/source_sha256`、模式、公告/来源可得时间、登记收盘及锁定时刻、除息和支付时间、CNY 金额/单位、税规则和模型身份。源 SHA 是完整性标识，不认证真实公告、账户或 PIT。Python 另核验所给人工源文件的实际 SHA 和事实；不联网认证。
- `cash_amount_fen` 只允许整数分。`per_share` 原样使用；`per_ten_shares` 必须可被 10 整除，拒绝分数分。先按权威持仓各 lot 累加整数股，再按事件计算税前额；扣税按 `ceil_per_event_fen_v1` 对每事件向上取整到分。金额和累计总额溢出拒绝整个事务。
- 税务规则必须明确版本和 `modeled_withholding_only_not_real_account` 身份。合成 20%、0%、100% 都是实验假设；V1 仅支持由同一股息全额覆盖、到账时扣缴的税负。未知或递延实际税负没有零填充路径。
- `record_at > record_close_at`，登记日 15:00 上海收盘之后才锁股数。登记日当天已完成会话的模拟成交可进入权益：`simulated_at` 是盘后记账时间，权益截止用会话收盘/可得性。后续买入不追认，卖出不删除权益。无法按冻结时序处理就拒绝，禁止晚到后回填。
- 除息和支付命令必须恰在冻结时刻，随附完整、当时可信的未复权持仓估值；除息不能使用更早的未除息价。CLI V1 将两者安排在显式人工 opening，登记安排在可核验 EOD 后；不在无序全日 OHLC 中插入盘中会计。
- 除息确认 `receivable=gross`、`liability=modeled withholding`；到账 `cash += gross-tax`，同笔应收/负债归零。税的投资损益在除息确认，付款不再计收益。负债由同一应收覆盖，不能单独变成可交易资产。
- `NAV = settled_cash + Σ(shares × trusted unadjusted mark) + receivable − liability`。买单可用资金仍为 `settled_cash − pending buy reservations`。应收不增加现金支出能力、授权本金或 exposure 上限。
- 风险观察、订单接受、执行前复查、费用后观察、跨日基准都使用同一应收净资产。`RiskKernel::with_dividend_assets` 仅接受可信账本投影，不持久化第二本资金账；负债超出应收即拒绝。Risk peak/日亏损/金融锁持续使用既有逻辑；支付、跨日、重启不会解除锁。
- 除息前旧挂单到期释放预留并记录原因；不自动调价/调量。除息前旧提案不能换 ID 再提交，须除息后重新决策。没有伪造取消券商委托的含义。

## 持久化、报告和独立评价

只有 `Ledger::create_cash_dividend_v4` 可首次创建新 v4，沿用唯一权威 reducer / events / checkpoint / FULL synchronous 原子事务和本机写锁。分红内容冻结在新 genesis；三个 `Command::CashDividendV1` 都参与状态 hash。相同外层事件 ID、相同完整命令重试返回 false；不同 payload 或重复阶段拒绝。

旧 `Ledger::create` 仍生成 v3；v3 的 State 序列化不包含 `cash_dividends`，digest 域仍为 3，既有 JSON、六报告和 hash 不变。`open/history` 按数据库版本重算完整链，校验 checkpoint；不会迁移、覆盖或重建旧本。v3 不接受分红命令；分红 CLI 拒绝旧账本，旧 replay/report 拒绝新输入。没有读取或写入任何原金融数据库以“修复”兼容性。

新 `report_schema=2 / ledger_schema=4` 保留六个文件并增加 `cash-dividends.json`，全部由 `Ledger::history()` 重建、一次原子目录发布。日报/事件包含应收、负债、税前收入、税费和到账净额；公司行为明细附冻结事件、源 SHA、三阶段时刻、权益股数、ledger digest、现金/NAV 和估值状态。FIFO 成交盈亏与股息收入/税分别列示，三者相加解释净资产差额；股息不进入成交手续费或 Owner flow。旧模式输出的字段/文件格式不变。

`cash-dividend-independent-accounting-v1` 从冻结 event、输入 opening/close、实际模拟成交列表独立计算现金/股数/FIFO 成本/应收/负债/收入/税及每阶段 NAV、日初基准、peak 和金融锁；用 Decimal 取税整，不调用 Rust 会计算法。只读备份用户给定 SQLite，在新副本上真实运行 `paper-dividend-report`，逐字节核对七报告，再用 Python 核对事件/日表/CSV。原 `m1-pr06-research-v1` 原样保留并明确拒绝分红报告。评价器从实际独立基准账本核对现金/持有基准，不把旧无分红近似基准当新结果。

另有 [有理数逐笔财务反证](../scripts/cash-dividend-counterproof.py)，不导入评价器/reducer；手算固定例子的资产变化，排除漏应收、漏税、支付重复获利和把股息当 Owner 入金的错误模型。
