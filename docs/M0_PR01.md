# M0-PR01：Paper 契约与独立风控入口

本页记录 Issue #1 的实现与 Sol 自测，**不代表 Terra 独立验收、完整 M0 或持续模拟交易完成**。
基线：`main@866ad552e778e088cac5e0d4482b52be02c305b6`。

## 已实现的边界

```text
显式账户/风险配置 ──> 新建内存模拟账户
交易提案 + 可信快照 + 可信规则/费用证据
                └─> RiskKernel::review
                       ├─> Accepted（绑定原提案、快照版本、审查时间）
                       └─> Rejected（提案 ID + 结构化原因 + 中文解释）
```

- 复用 `contracts` 和 `stratide-cli`，新增实际工作的 `stratide-risk` 小库；无第三方依赖。
- 人民币以 `Cny` 的非负 `i64` 整数分表示，股数为整数；乘法、费用相加、预留、估值和股数汇总使用检查运算。负金额在构造边界拒绝；负数/零股数在审查入口拒绝。当前不支持小于一分的报价，不会静默取整。
- `account_id`、`group_id`、`strategy_id`、冻结版本、部署 ID 和非零 `u128` 提案 ID；当前只承认配置中的一个部署实例。重复审查不会消费 ID。全生命周期唯一 ID 分配和历史去重由 PR-02 的持久账本负责。
- 决策时间、数据 `available_at`、最早执行时间、到期时间使用 UTC Unix 毫秒。最早执行必须晚于决策；这里只记录执行下界，**没有实际执行时间或成交事件**。该检查不证明市场存在可成交时段。
- 现金不足（含全部费用预留）、无持仓/超持仓卖出、已有资金/股份预留、账户/策略订单和敞口上限、非法值及运算溢出均拒绝。
- 可卖数量按可信规则选择 `TPlusOne` 或 `SameDay`；未知规则拒绝。`TPlusOne` 仅允许早于当前交易日取得的股数，扣除已预留卖出份额；不会把审核通过的买单当作新持仓。
- 接受结果构造器私有、不可克隆，绑定完整提案与快照版本；**审核通过既不预留也不扣款，不增减股份，不是成交或执行许可**。

## 信任与市场证据

`OrderProposal` 是策略输入；`PaperAccountConfig`、`AccountSnapshot`、`ReviewContext` 和冻结管理只能由可信核心提供。当前没有 Worker、IPC、网络接入或安全沙箱，Rust 类型不是 OS 安全边界。

证券代码仅校验六位数字语法；真实上市身份、市场归属、品种、交易日历、停牌、买卖单位、价格单位和价格带必须来自可信的逐证券/交易日规则证据。缺证据、身份不符、时间过期、停牌或未知交收规则均保守拒绝。交易日由可信调用者提供，当前不自动推算交易所日历或校验 UTC 时间与交易日映射。规则的 `source` 是来源/版本记录，**有字符串不等于完成了外部来源核验**。

费用由可信上下文提供绑定提案的全额上界，包含适用费用/税费；它不是策略自己声明的可用资金。当前不内置真实市场费率，也不假设 ETF 与股票有相同交收规则。实际品种规则、生效期与来源核验须在 PR-02 的窄范围成交路径落实；证据不足时不得开启该路径。

`cash` 包含已预留资金；可用现金 = `cash - pending_buy_reservations`。持仓市值只来自完整、新鲜、带来源的持仓估值；不使用新提案的限价为旧持仓定价。敞口保守使用“当前持仓市值 + 未完成买单全额预留 + 本提案全额成本”，不提前计入预期卖出所得。卖单只能减少可信已有可卖多头，不能做空；当前卖单只预留股份，因而费用上界超过卖出所得时保守拒绝，避免额外消耗未经预留的现金。

## 最小 NAV 与冻结契约

当前只有一个策略拥有全账户，不创建第二份策略现金或虚拟本金。账户与策略使用同一完整 NAV，分别执行显式限额。

```text
NAV = 现金（含预留） + 所有已有股份的可信市值
日内可比权益 = NAV - 当日净外部现金流
历史可比权益 = NAV - 初始化以来净外部现金流
日亏损 = max(0, 日初权益 - 日内可比权益)
回撤金额 = max(历史可比权益高水位, 当前历史可比权益) - 当前历史可比权益
```

这些是绝对人民币金额阈值，当前不计算百分比业绩或时间加权收益。日初基准、外部现金流及历史高水位由可信账本提供；Risk Kernel 额外保留已观察高水位，不能靠更低输入重置。现金已反映历史实付费用和已实现结果，股份市值变化包含浮亏。外部入金不算利润，出金不算亏损；股息不应作为外部本金输入。未知/陈旧/冲突估值或不可比较基准不能视为零损失。

达到日亏损或回撤金额阈值后，相应账户/策略锁会锁存。恢复估值、跨日或内存检查点重建不能清除已触发财务锁；没有自动解锁 API。财务锁下只可能批准经独立核实的可卖持仓减仓，仍检查规则、资金、费用和预留。订单不确定或人工冻结保守拒绝买卖两侧。不自动清仓，不承诺损失上限。

`RiskState` 是不透明的内存检查点契约。`clone` → `RiskKernel::restore` 测试仅验证锁、高水位和身份保留，**没有序列化格式、磁盘写入、进程崩溃或真实重启恢复**。

## 可复现 CLI 示例

在已配置 Rust/MSVC 的 Windows 终端中运行（参数单位均为分，无默认本金/风险阈值）：

```powershell
cargo run -p stratide-cli -- risk-demo --initial-cash-fen 1000000 --max-order-fen 500000 --account-cap-fen 800000 --strategy-cap-fen 500000 --daily-loss-fen 100000 --drawdown-fen 200000
```

以上金额仅是调用者显式选择的测试输入，不是 Owner 的生产限额。程序每次新建独立内存样例，固定 `2026-10-28 10:00:00 Asia/Shanghai`，人工假设证券 `Shanghai/600000`、价格 10 元、费用上界 5 元、T+1、100 股交易单位和 9～11 元价格带。**全部为 `synthetic_test`，不是该证券当日真实行情/规则/费率或成交证据。** 不读写账户数据文件，无真实市场盈亏。

实际输出的关键部分：

```text
显式本金：10000.00 元；初始 NAV：10000.00 元；持仓：0 股
买入申请 #1：接受提案；不是成交；最大现金支出 1005.00 元
重复审查：结果一致
超现金买入 #2：拒绝：可用资金不足：需要 11005.00 元，扣除预留后仅有 10000.00 元
无持仓卖出 #3：拒绝：持仓不足：申请卖出 100 股，扣除预留后仅有 0 股
冻结后买入 #4：拒绝：账户风险冻结（人工冻结），该提案不获许可
审查后现金：10000.00 元；持仓：0 股；未完成委托：0；审查未改变资金或仓位
```

同一参数两次独立启动的 stdout 由 CLI 集成测试比较。小本金/较低风险限额可以使第一笔也被拒绝，这是配置结果，不会补充虚构本金。

## 文档解释与下一阶段依赖

`docs/M0.md` 和 ADR-017/018 描述**完整 M0** 的成交/持久化/恢复目标。按最新已接受 ADR-037、路线图与 Issue #1 的分 PR 顺序，本轮只实现 PR-01；未修改既有 ADR 或其目标。

PR-02 必须新增权威单写入者账本、完整唯一 ID 历史、原子预留、模拟成交与费用落账、持久风险锁/高水位/日初基准/现金流、故障恢复和幂等。执行时重新审查最新快照并在同一受控事务中预留，校验完整原提案、有效期、快照版本、冻结状态与可执行时段；不能把多个相同旧快照上的 `Accepted` 相加当作多个可花资金。当前没有可消费批准结果的执行器，避免将未实现的原子性宣称为安全保障。

PR-03 才提供真实来源历史数据回放、事件日志与可读取报告；PR-04/M1 才接真实数据进行前向观察。真实券商、AI、多策略分配、动态预算、GUI 均未实现。

$env:LIB = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\14.44.35207\lib\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\ucrt\x64'
