## 架构

```text
桌面/开始菜单 shortcut
        │
        ▼
stratide-launcher.exe  (GUI subsystem, per-user)
  ├─ 默认：--no-browser? 健康探测 → 已运行则开浏览器
  │         未运行则启动 supervisor → 轮询 /api/health → 开浏览器
  ├─ --background：唯一 Supervisor（文件锁 + Job Object）
  │     ├─ stratided.exe --port ... --assets-dir <app>\dashboard
  │     │     --runtime-home <home> [--agent-dir/--paper-ledger 若已配置]
  │     └─ <app>\runtime\python\python.exe -B scripts/eod-operator.py market watch
  │           （原 #82→#83→#84 工作流；TimesFM 经有界桥接进入 Owner 现有 WSL2 venv/模型）
  ├─ --stop：写 stop.request → 等待 Supervisor 停止自己的子进程
  ├─ --autostart enable|disable|remove|status
  └─ --configure（安装器写入 runtime.json；已存在不覆盖）
        │
        ▼
stratided 的 /api/runtime/status 与受限写接口
  （读诊断、autostart、Tushare 凭据、EOD init/enable/disable、setup-complete、shutdown）
```

### 目录布局

- 程序：`%LOCALAPPDATA%\Programs\Stratide`（Inno 可改）。
- 用户数据：`%LOCALAPPDATA%\Stratide\data`（安装时可改），含 `state\`、Paper 账本、行情仓库等。
- 运行：`%LOCALAPPDATA%\Stratide\runtime\`（supervisor.json、runtime-token、stop.request、锁、setup-complete）。
- 日志：`%LOCALAPPDATA%\Stratide\logs\`。
- WSL2 工作树/模型：不在安装目录内，安装/升级/卸载都不修改。

## 关键决策与复用

1. **Inno Setup 而非 Tauri/Electron/WiX。** 现有栈已有 Rust GUI-subsystem launcher 与静态 Dashboard；Inno 产出单 exe 安装器、卸载器和快捷方式，最小依赖，不需 Node/Rust/Python 运行时在用户机器上。
2. **嵌入式 CPython。** research/scripts 实际只依赖标准库 + tzdata；随包附带 CPython 3.12.10 embeddable，避免“本机 Python 版本不对”导致 EOD 不可用。WSL 的 TimesFM Worker 仍使用 Owner 自己的 venv。
3. **Supervisor 不是第二调度器。** 它只启动既有 `market watch` 并保证单实例；交易日、16:10–18:00 窗口、去重、预算、未知结果恢复全部沿用原实现。
4. **Windows Python 路径改造。** 原 research 栈以 `git rev-parse` 定位 `state/`，并硬编码 `target/debug`。新增 `research/stratide_paths.py`：设置 `STRATIDE_STATE_ROOT` 时使用 Owner 数据目录；未设置时保持原 Git 行为。二进制通过 `STRATIDE_BIN_DIR` 指向安装包 `bin\`。Git 忽略校验在安装模式替换为“必须位于数据根内”。
5. **登录自启两级机制。** 优先 Task Scheduler（可延迟、可禁用、IgnoreNew）；沙箱/策略禁用任务计划程序时回退 HKCU `Run`。两者都只对当前用户、无需管理员。状态页显示实际机制。
6. **单实例与崩溃一致性。** Supervisor 锁阻止第二个后台；Job Object 在 Supervisor 被强杀时结束 service/watch，避免下一次登录产生第二套 Agent/Ledger writer。service 异常退出由 Supervisor 退避重启；重复双击由 launcher 健康探测短路。
7. **停止路径。** `stop.request` → Supervisor 停止自己的子进程，并用 runtime token 请求 `/api/runtime/shutdown` 让 dashboard 优雅退出；不按端口或未知 PID 杀进程。`--delete-user-data` 也先停止后台再确认删除。

## 安装态 TimesFM：接入 Owner 现有 WSL2（R2）

Windows 侧始终保留唯一的调度、Agent DB、预算闸门和 Paper 账本；它只把**已冻结的数值输入**交给 Owner 已有的 WSL2 CPU Worker 推理，再把结果交回原研究链。安装包不下载、不打包模型，也不把云端凭据搬进 WSL。

### 入口与配置

- `runtime.json` 新增可选 `wsl` 段：

  ```json
  "wsl": {"distribution": "Ubuntu-24.04", "workspace": "/home/owner/Stratide",
          "python": ".venv/bin/python", "model": "models/timesfm-2.5"}
  ```

- Dashboard「设置 → 运行与安装 → WSL2 TimesFM 桥接」可保存并用「检测 WSL Worker」执行真实前置探针；保存后 Supervisor 重启唯一 `market watch`（保存相同配置不重启）。
- Supervisor 只向那一个 watch 进程注入 `STRATIDE_WSL_DISTRIBUTION/WORKSPACE/PYTHON/MODEL`；这些都不是凭据，也没有新增第二套调度或账本。

### 桥接过程（每个任务）

1. `wsl.exe -l -q` 确认发行版存在，否则 `TIMESFM_WSL_DISTRO_MISSING`。
2. 用配置的 venv Python 在 WSL 内运行安装包自带的 `research/timesfm_cpu/wsl_bridge.py`：
   - 把**安装包里的** TimesFM 代码复制到 `~/.cache/stratide/timesfm/run-*`，确保跑的是同一版本代码，而不是 WSL 里另一份检出；
   - 以**硬链接**把 Owner 的模型目录放进 staging（不复制 GB 级权重、不改动原文件，跨文件系统时明确失败而不是静默复制）；
   - 仍由原 `runtime.py` 的 systemd-cgroup v2 + bubblewrap 隔离执行 Worker。
3. 校验身份后才写入结果：代码包 SHA256、`request_sha256`、`model_revision`、`weight_sha256` 与前置清单一致，任一不符即 `TIMESFM_WSL_CODE_MISMATCH` / `TIMESFM_WSL_PROTOCOL_INVALID` / `TIMESFM_WSL_*_IDENTITY_MISMATCH`。
4. 结果回到原有 `risk-portfolio` 冻结/评估/Gate 链；云端研究仍受原外发授权、DeepSeek ¥5/日与 ¥100/月预算约束。

### 失败语义

| 情况 | 结果 |
| --- | --- |
| 未配置 WSL | `TIMESFM_WSL_NOT_CONFIGURED`，研究/Paper 保持 BLOCKED |
| `wsl.exe` 不可用 / 发行版不存在 | `TIMESFM_WSL_UNAVAILABLE` / `TIMESFM_WSL_DISTRO_MISSING` |
| venv 或模型缺失/损坏 | `TIMESFM_WSL_VENV_MISSING` / `TIMESFM_WSL_MODEL_MISSING` / `MODEL_NOT_PROVISIONED` |
| 超时 | `TIMESFM_WSL_TIMEOUT`（默认 900 秒，`STRATIDE_WSL_TIMEOUT` 可调 1–3600） |
| 协议/身份不符 | `TIMESFM_WSL_PROTOCOL_INVALID` / `TIMESFM_WSL_CODE_MISMATCH` / `TIMESFM_WSL_*_IDENTITY_MISMATCH` |
| Worker 异常 | 该任务记为 failed，不伪造结果、不发起云调用 |

以上都只阻断**当日研究**（写入 `BLOCKED` 并进入 600 秒冷却，避免每次 watch 轮询都重试），**不会停止下一交易日的 EOD 采集**：`market watch` 里 research/paper 是采集提交后的独立失败边界。冷却到期后同日再试一次，仍不会新建云端任务。

## 安全与资金边界（未改变）

- 仅 Paper；没有 broker adapter、真实资金、实盘晋升或自动交易解锁。
- DeepSeek 日 ¥5/月 ¥100 和 Agent Budget Gate 未改变；安装器不会提高预算或代为授权。
- 真实行情云外发默认 `REAL_MARKET_DATA_EGRESS_DENIED`；首启向导只显示既有状态，不授予外发。
- 安装后未配置/未授权：无 Tushare 请求、无云调用、无模拟订单；Dashboard 可读并显示具体下一步（诊断页/既有设置）。
- Tushare token：仅由受限 helper 从 stdin 写入当前用户 Credential Manager；不回显、不进 argv/日志/安装包/页面状态。
- runtime token：`runtime\runtime-token`，仅本用户可读；写接口要求精确匹配，GET 诊断同样要求 localhost 同源。
- Supervisor/launcher 以当前用户最低权限运行，不安装 Windows 服务、不请求管理员。

## 已知限制（必须随本 Draft 一起评审）

1. **安装态链路已接通，但端到端付费云研究仍未实测。** Windows `market watch` 在配置 WSL 后会自动走 TimesFM → 冻结候选 → 原 Paper 判定；本轮用真实 WSL2 CPU 推理验证到“可信结果回到原 Agent/研究链”，但真实 Tushare EOD、真实 DeepSeek 外发授权与 Paper 成交仍是 `NOT_RUN`（需 Owner 的付费/外发授权）。模型与 WSL 环境仍由 Owner 提供，安装包不伪造“全离线一键安装”。
2. 真实 Windows 登录自启、快捷方式和卸载器注册表项需 Owner 在正常桌面会话做一次实测；当前沙箱只验证了同一 Inno 脚本的 `[Files]/[Code]` 测试变体。
3. 安装包未签名；SmartScreen 可能提示。Inno Setup 6.7.4 的编译器输出声明“Non-commercial use only”；本项目为个人非商业使用。
4. 立即停止正在进行中的 EOD 可能留下未知的付费/行情结果；沿用既有 journal 与“不盲目重发”原则，但不在本模块新增优雅 drain。
5. 保存 WSL 配置会重启唯一 watch；若恰好在 TimesFM/采集执行中被杀，该任务按既有“未知本地结果不盲目重发”规则记为失败并阻断当日研究（不会重复付费或成交）。保存相同配置不会触发重启。
6. 冷却期按 `blocked_at` 计算，进程重启后仍生效；它只针对 `TIMESFM_WSL_*`/`WORKER_*` 这类本地 Worker 失败，不会掩盖云端授权/预算阻断。
7. 未做代码签名，未做 N100、Linux 主机、公网部署或大规模 UI 重设计。
