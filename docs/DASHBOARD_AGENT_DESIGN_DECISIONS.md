## 0. 阅读规则与产品边界

- **Owner 已选**：以下写明“确定”的产品交互意图，不要在后续对话里反复重问。
- **实现未定**：数字阈值、具体 API、数据源、认证方式、技术栈与何时上线等，除明确指定外均待设计/验证。
- **架构冲突**：现有 Accepted ADR 优先级不能被此访谈静默覆盖；需要提出显式 reconcile/ADR 变更并取得 Owner 决定。见第 9 节。
- **财务安全**：任何前端操作均须走可信后端；云端 Agent 不拥有券商密钥、下单权限、风险配置写权限或增加资金/费用硬上限的权力。M0/M1 paper 证据不可冒充实盘。
- **账户**：未来实盘使用 Stratide 独立专属券商账户，不与 Owner 日常手动投资混合；无日常人工买卖 UI。例外的人工接管/对账遵循 ADR-028–033，不能从“只监控”推断可跳过券商对账。
- **风险优先**：确认收益之前必须保留账户级熔断、未知订单冻结、数据有效性、现金/仓位一致性和 Owner 控制权；模型研究结果本身不等于独立准入证据。

## 1. 产品定位与首页（Q01–Q16）

1. 核心是 **A 监控 + C 必要控制**，不是 Stockie 式证券终端/人工日内交易台。Owner 主要看账户净值、策略、持仓、费用与系统状态。
2. Dashboard **只显示 Stratide 专用账户**；不做个人账户切换器或合并个人投资组合（已有 ADR-028）。
3. 1920×1080 **桌面优先**，移动端基本可用，不额外投入复杂移动设计；内容可以自然纵向滚动，**不为了满屏牺牲可读性**。
4. **首页左上**突出总资产/账户净值（现金 + 按有效数据估值的持仓）；次要展示可用资金、今日盈亏和累计盈亏。**首页右上**为主要资产表现图。
5. 图表指标支持 **总资产（人民币）、累计收益率（%）、累计盈亏（人民币）**切换。不要将现金流误作利润；必须显示有效估值时间，不能暗示 EOD 是实时行情。
6. 下方显示**运行策略**（状态、绩效、回撤）与**当前持仓**（证券、市值、浮动盈亏、迷你走势），可查看关联详情；系统健康状态有轻量入口。
7. 正常系统不使用常驻醒目横幅；仅真正的账户/风控/订单/数据严重异常才采用高优先级警报。普通策略亏损不等于系统事故或 Owner 必须停止策略。
8. 财务/行情以 **EOD** 为初始更新节奏；Agent、任务及风控/服务健康状态可较及时刷新。**系统在线 ≠ 行情实时**；日内行情成本/合规/安全与刷新节奏暂不承诺。
9. 策略可见概览与明细，明细可包含运行行为、收益/回撤、决策时依据、持仓及交易；不在第一版建设完整研究实验可视化台。
10. 研究费须有 Owner 设定的**每日 + 每月硬上限**。Budget Gate 在付费调用前以并发安全的预留/账本控制额度，处理重启及跨周期计费；供应商账单可能延迟，不可承诺外部费用绝对零超额。研究预算耗尽不会停用必要的账户风控/对账/交易安全服务。每日硬上限原由 ADR-012 确定；**每月上限是本次设计新增要求，尚待架构更新与实现**。
11. Agent 可申请增加研究费用上限，说明金额与预期价值；**只由 Owner 授权**，不能自动生效、自动充值或绕过 Budget Gate。
12. 预算申请进入 Dashboard 审批，且可邮件提醒；**邮件只提供安全通知/链接，不直接授权**。审批需经过鉴权，敏感变更按需二次验证。
13. 远程访问目标是个人网站的 **HTTPS 私有子域名 + 登录认证（含 2FA/敏感操作再次验证）**，无需依赖 VPN/Tailscale；浏览器不会直接访问券商或秘密凭据。实际远程暴露须在部署安全验证后进行。
14. 支持**浅色/深色/跟随系统**模式，记忆选择。视觉参考 **DeepSeek Platform Usage**：轻量 SaaS、合理留白、清晰对齐，不套用复杂金融工作站 UI。浅色灰白蓝、深色灰蓝/青色为方向，不是定稿色值。
15. **点击策略和持仓打开右侧详情抽屉**，用于快速查看信息；需要认真填写和提交的操作使用 Modal；不在首页横向展开大量行内容。
16. **Paper-only** 时明确标注模拟数据。未来 Owner **单独授权**真实账户并合规上线后，默认首页展示真实专用账户；模拟、回测和研究数据转至「历史与报告」等独立界面，绝不能混入真实净值。

## 3. 通知、审批与全站可撤销交互（Q32–Q34、Q51–Q52）

- **Q32**：分级告警。普通异常只写入 Dashboard「通知」；严重的资金、订单不确定、冻结等事件同时写入 Dashboard **并**发送邮件。邮件失败不能导致事件丢失或安全检查失效；重复事件去重，恢复事件更新状态并保留历史。
- **Q33（修订）**：「通知与审批」不是两个切换 Tab，**桌面端双栏并排：通知占 60%，审批占 40%**。通知和审批项均使用较高行距/行高，显示**摘要标题 + 正文前 1–2 行**；点击查看详情。审批条目**最右侧**有 ✓ 快速通过与 ✕ 快速拒绝图标按钮，配悬停提示及明确可访问性名称。
- **Q34**：快速审批采用**单击即给视觉反馈 + 底部 5 秒 Undo Snackbar**，不反复弹阻断性确认。对**提高预算等不能保证事后撤销**的动作，采用**延迟实际授权/提交**至撤销期结束，期间可撤销；敏感权限仍要完成身份验证。不能把已发生 API 费用伪装成可退款。
- **全站补充规则（Q50 后追加）**：凡 Owner **手动改变业务状态**，均应给统一的“操作结果 + 5 秒撤销”反馈。可逆 UI/业务动作可以恢复旧状态；有外部不可逆影响的动作应尽可能延迟提交并提供取消窗口；无法可靠撤销的订单、费用及即时安全操作**不能误标可撤销**。纯查看、页面导航、表格排序不需要 Undo。Owner 手动紧急停止必须立即生效，恢复不允许由 Snackbar 绕过安全流程。
- **Q51（B+C）**：正常的策略资金扩容做**每日 EOD 简报**（有变动才生成）；普通扩容异常即时进入通知页；严重异常同步邮件；完整资金变更仍留历史审计。
- **Q52**：扩容被阻止，**按原因处理**：资金暂不足等暂态问题后续交易日自动复查；风控冻结/对账异常等安全问题持续阻止，直到可信后端确认恢复条件；去重并避免重复执行同一阶段。

## 4. Agent 管理与研究任务（Q35–Q44，Q60–Q62）

- **Q35**：「Agent 用量」更名为**Agent 管理**，同时承担 Agent / 模型配置、快速下拉切换、费用与研究任务观察。默认主视图显示**今日/本月消耗与剩余额度、预算、费用趋势、按服务商/模型汇总的 Token 与费用明细**。费用估算与确定账单须区分。
- **Q36**：**V1 单模型优先，兼容未来多模型**。可保存多个 Agent/服务商/模型配置，通过下拉选当前**默认**配置。切换只影响**新任务**，不中断正在执行的任务。用户尚未确定具体 Agent 供应商；**不要误认为必须有编程模型**。研究 Agent 的职责是量化研究/策略假设/评估/复核，交易由可信程序控制；自动生成代码的可选能力受现有隔离 Worker/评价门禁约束。
- **Q37**：基础设置（服务商、模型、密钥、必要连接项、测试连接）+**折叠高级选项**（仅列服务商真的支持的参数）。不堆滑块；密钥仅可信后端存储，不在前端明文回显。
- **Q38**：Agent 状态 + 最近研究任务列表；每项显示任务名、状态、执行耗时、费用和**简短结论**；点击右侧**详情抽屉**。不在第一版做完整任务控制台。
- **Q39**：自主研究持续进行，也可手动启动研究或重试失败任务。**「自定义任务」按钮放在研究任务列表标题区域右上方**，不放在整个页面顶部。手动研究与自动研究共用 Budget Gate，不授予下单权。
- **Q40**：点击「自定义任务」采用**居中 Modal 的结构化表单**，不是抽屉或聊天；字段初步为名称、目标、研究证券/范围、数据时间区间、可选单任务预算（都需实际校验，细节未定）。约定：**抽屉浏览、Modal 完成专注操作**。
- **Q41**：手动提交任务**资源与预算允许尽快并行启动**，不足则自动排队；不可抢占风控资源，使用并发安全预算预留。
- **Q42**：研究结果**不自动写长报告**；任务列表点开只显示轻量摘要抽屉：目标、简短结论、关键依据/指标、状态、耗时、费用。**打开抽屉只是读取已保存结果，不额外进行 LLM 总结调用**；后端仍保留验证和审计必要证据。
- **Q43**：Agent 采用**每日 EOD 常规研究 + 重要事件触发研究**；日常状态监测由普通程序负责，**不高频调用 LLM**；事件去重、冷却与预算控制。
- **Q44**：事件研究触发以**固定客观规则优先**，其他潜在机会由低频的日常 Agent 研究评估。交易风控和研究触发器独立；风险处置不能等待研究完成。
- **Q60**：研究任务发生临时故障时，仅在**确认安全可重试**（不会导致无法核实的重复执行或失控计费）前提下，**最多自动重试一次**；状态不确定、原请求可能已执行/计费、预算不足、身份/权限错误、无效配置或永久性错误，不自动重试。重试同样须经过可信 Budget Gate、幂等/调用状态验证及必要的预算预留，失败与重试均记入任务记录。此规则与券商订单重试不同：**未知券商订单绝不可盲目重发**（ADR-003）。
- **Q61**：为未来单模型优先的研究 Agent 配置一个**Owner 预先指定的备用 Agent/模型**。当主配置持续不可用时，后续**新研究任务**自动转用已保存且已授权的备用配置；已运行任务不强行迁移，也不将状态不确定的付费请求盲目复制到备用模型。主模型恢复后依健康检查/防抖规则切回，具体判定阈值实施时确定。备用服务商的数据共享目的与范围需要符合持久化 Owner 授权（ADR-013），所有研究调用共用每日/月度 Budget Gate，不能通过切换供应商或模型绕过预算、权限或可信交易风险门禁。无可用或已授权备用配置时不自动新增外部供应商。
- **Q62**：研究任务支持**单任务优雅取消**，不同于 Q58 的全局研究暂停。排队任务可直接取消且不再启动；已运行任务**不强行中断已提交的外部模型调用**，在当前不可中断调用/步骤完成后的安全检查点停止后续步骤，尽量减少新费用。保留当前已得到的研究结果、费用、取消请求时间、实际终止时间和最终状态，避免把“已申请取消”误报成“外部调用已经停止”。取消入口在任务行/任务详情的轻量按钮。遵循 Q50 的 5 秒 Undo 交互仅限实际可撤销的待处理状态；不能承诺已发生外部费用或者已终止执行可以复原。取消操作不能影响风控与实盘交易。

## 5. 自主部署与策略资金管理（Q45–Q54，Q63–Q64）

- **Q45**：未来经 Owner 单独启用实盘并授权资本/风险边界后，Agent **自主提出候选、组织验证、在已有授权范围内申请自动部署**；正式晋升仍须经**独立 Strategy Evaluator / Promotion Gate / Risk Kernel**，不可由 Agent 自己批准，也不要求对每个合格候选逐一人工签字（对应 ADR-009/011）。未验证代码不得直接进入可信实盘进程。
- **Q46**：新策略**小额启用，逐步扩容**；任何额度不突破 Owner 授权本金、账户级/策略级风险硬约束。具体初始金额/阶梯**未定**。
- **Q47**：Owner 选择**按预设交易日时间表逐级扩容**，同时要有**可配置 UI 入口**。示意的 0/30/60/90 天和金额只是草图，不是生产默认。达到时间是“可重新评估扩容”，**不绕过**所有已有风险、资格和资金限制。
- **Q48**：**全局扩容时间表 + 每策略覆盖**；默认继承全局，单策略在详情抽屉内可个别调整，Owner 可恢复继承。账户硬上限始终不可覆盖。
- **Q49**：全局配置变化**默认只影响新策略**；提供显著的「**一键全局应用**」操作，统一更新所有**仍继承全局规则**的存量策略，**不覆盖**明确自定义过的策略。应用前呈现影响范围/数量，敏感修改进行鉴权；批量实施必须有安全校验，不能重复超额扩容。
- **Q50**：扩容计时采用**对应 A 股交易所实际交易日**，非自然日；休市日不计。交易日计数不代替对数据有效性、风险条件的必要检查。
- **Q51**：正常配额变动日报汇总，异常即时 Dashboard 通知，严重异常同时发邮件（见第 3 节）。
- **Q52**：按阻止原因区分自动复试与安全阻断；不盲目重试（见第 3 节）。
- **Q53**：配额**双向管理**。普通亏损/市场波动不轻易关闭策略；风险显著恶化时可暂停扩容或缩减配额；严重风险由独立 Risk Kernel 启用保护。
- **Q54**：配额下降**不等于立刻卖出**。轻微风险限制新增仓位，显著风险经可信执行策略逐步减仓，严重风险执行合法可行的保护措施；必须尊重 T+1、停牌、涨跌停、卖出可用数量和券商真实成交确认。无法成交时如实持续记录风险。
- **Q63**：选择 **C — 分阶段混合扩容门槛**：策略仍按 Q47/Q50 的预设**交易日**时间表触发下一档评估。**小额早期档位**可在独立的基础资格、风控、账户资金和数据有效性检查通过后，按时间晋升；达到**预设较高资金档位**后，必须额外通过可信且独立的**实际表现/风险证据验证**（如稳定性、回撤、交易成本/执行质量，具体指标及样本规模尚未定义）。不要求每个低档位都取得短期正收益；也不能以时间达标代替安全或真实成交能力。阶段分界与金额、观察期及评估阈值须由 Owner 预授权配置；Agent 不得修改。**与 Accepted ADR-025 的适用范围仍需正式协调后才可实现实盘扩容**。
- **Q64**：选择 **A — 按扩容阶段定义从哪一档开始强制独立表现验证**。在全局「设置 → 资金与风控 → 策略扩容」里提供一个明确的**起始验证档位**（例如“第 3 档”只是解释例子，**不是默认值**）；之前的早期小额档位遵照 Q63 的交易日与基础安全门槛，达到起始档位及之后的高档位必须通过独立表现/风险证据门槛。Q48 单策略覆盖与 Q49 批量应用规则仍有效；Agent 不得修改这些 Owner 授权条件。实际起始档位、金额及指标阈值待 Owner 配置并在正式协调 ADR-025 后实施，不能因为尚未配置而自动假定安全扩容。

### 与现有 Accepted ADR-025 的协调状态（Q63 新增）

**Owner 已确定产品方向：** [ADR-025](adr/0025-adaptive-risk-budget-decay-quality-gates.md) 的总体目标是双向风险预算、审计与可信验证；Q47–Q50 选择交易日阶梯，**Q63 进一步选择“低档位时间 + 基础安全门槛；高档位时间 + 独立表现证据门槛”**。这解决了原来“是否每次都按表现扩容”的意图歧义，却**尚未正式修订 Accepted ADR-025**（原文强调持续风险/收益/执行证据方可逐步扩容），两者在早期档位是否可省去表现证据方面仍存在规范差异。

正式实现前需 Owner 明确确认对 ADR-025 的变更或兼容解释，并规定分界阶段、初始/最高配额、最低交易日、基础门槛、进阶表现证据、数据不足及降档条件；都不能由 Agent 自行提升额度/改变门槛。**在这一协调与独立验证完成前，不准据本设计直接上线自动实盘扩容；既有 ADR 与所有账户/策略 Risk Kernel 强制约束仍有效。**

## 6. Owner 紧急控制与 Agent 暂停（Q55–Q59）

- **Q55**：**全局紧急停止新增交易 + 单策略停止新增交易**。全局入口在右上系统状态菜单；单策略入口在策略详情抽屉。停止新增风险，不代表一键清仓；必要风险处置与券商对账逻辑应独立保持（与 ADR-029 的“人工接管全停单”区分）。
- **Q56**：由 **Owner 亲自发起**的停止必须由 **Owner 再次亲自发起恢复**，后台/Agent/重启/连接恢复不得解除；Owner 先完成敏感身份验证，可信后端核对对账、未决订单、各风险锁后**分阶段恢复**。全局和策略停止各自持久化，解除一项不连带解除另一项。Owner 人工接管锁始终受 ADR-029/030/031 更严格的专门流程约束。
- **Q57**：**交易与研究独立停止/恢复**。停止交易默认不停止研究；「暂停 Agent 研究」独立存在，也可以两者分别操作。任何停止都不能停掉必须的风控、账户对账和安全恢复机制。
- **Q58**：暂停 Agent 研究使用 **A 优雅暂停**：**阻止新的研究任务启动，允许正在运行的任务完成**；不强杀已提交调用。暂停状态跨重启持久化；Owner 发起暂停后，只有 Owner 主动恢复。待运行的研究任务保留队列状态，具体保留/重排/超时策略尚需实现时明确。
- **Q59**：研究暂停期间错过的**周期性 EOD 研究**不逐日补做、不堆积多个相似任务。Owner 主动恢复研究后，使用**最新可用市场数据**合并安排一次综合研究，记录跳过的周期并受到统一 Budget Gate 约束；不得把旧数据分析伪装成当日研究。此项不授权绕过暂停期间已经存在的安全锁，亦不自动执行过期的研究任务。事件型/用户自定义任务是否可合并应按其独立语义审查，不能静默丢弃用户提交的任务。

## 7. 交互设计通用规范

- 参考 **DeepSeek Platform Usage** 的轻量排版，不照搬品牌 UI。数字区域小、折线图大；左侧图文导航，不采用四张等尺寸 KPI 卡片。
- 所有货币与金额对齐使用等宽数字；稳定列宽，避免异步更新造成布局跳动；亏损/盈利必须同时依靠正负号与颜色。
- **Drawer**：快速浏览策略、持仓、研究任务细节。**Modal**：创建任务、敏感配置编辑等聚焦输入。通知审批清单不为普通操作增加多层嵌套弹窗。
- 列表以可读字号与较高行距为优先；收起 5 行固定高度，展开后随页面滚动。列头排序保留可见的未激活/升/降箭头；不要重复引入曾被 Owner 明确撤回的 Filter。
- 具有外部不可逆作用的操作不能做“假撤销”；**先挂起外部提交，再给 5 秒取消窗口**的场景须与后台幂等、计费、权限检查一起设计；不能用前端计时当作安全控制。立即停止类动作优先安全，**只能重新验证后主动恢复**。
- 所有显示的“运行正常”必须基于有时效的真实状态；EOD 市值/收益须标明最后更新时间，避免静态指标带来“实时”的假象。

## 8. 实现优先级与非目标

1. **不改变当前 paper-first 里程碑**，该文档仅作为未来前端和 Agent 产品规格输入。等 M0/M1 证据足够、Owner 提议开始 Web 设计时再将其拆分为可执行任务与验收。
2. V1 先实现单 Agent、低成本用量/任务观察、简洁 Dashboard，控制边界可信后端落实；不强求编程模型、完整 IDE、研究文档库、全功能金融交易 UI、多 Agent 编排。
3. 非目标：由 Web 直接下单、让 Agent 改 Risk Kernel、凭回测宣称盈利、让展示 mock 数据冒充真实净值、将费用/订单/已生效权限宣称可以轻松 Undo。
