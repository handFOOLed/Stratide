## 修复结果

- **P1-1：** Owner 单独批准 `unverified_eod_assumption` 后，原真实 EOD schema 可以经原 Runner → CLI → 唯一 Ledger 产生 `EX_POST_OPEN_ASSUMPTION` 模拟成交。`corporate_actions_verified` 保持 false；收据明确 `CORPORATE_ACTIONS=UNVERIFIED`。要求支持的成熟普通主板、冻结 T 收盘与次日 `pre_close` 连续、有效复权因子相同、非停牌/ST/异常、原费用和限价有效。已有假设持仓以原买入收据因子为锚，不能通过新研究重置已检出的公司行为变化。假设有 Owner 另设的总敞口上限（编译与执行均检查），整批最多 100 股；原账户/策略风控始终独立执行。缺少许可仍 NO_FILL。
- **P1-2：** `RecoverPortfolioValuationV1 / NO_TRADE_REBASE` 独立恢复当前完整持仓估值，不补历史价格/成交、不改股数/现金/手续费。先用旧基准和高水位检查跨缺口损失，再重设后续日初基准。亏损、回撤、人工锁及 Owner 暂停均保留；缺口与恢复日当日 PnL 仍不可用，历史未知 NAV 不改写。原 Runner 在研究前处理恢复，之后仅允许新日期新候选。
- **容量：** 新配置显式 `capacity_scope=Batch`，冻结容量在全部证券之间只消耗一次。无此字段的既有事件保留旧每单历史语义/收据，序列化新增字段缺省省略，不改旧 SHA；UI 区分新旧语义。
- **可选隔离：** Paper 模块导入、初始化及运行都进入独立边界。故障产生 BLOCKED、原 watch 继续轮询；`KeyboardInterrupt/SystemExit` 仍传播。

完整准入、示例配置、限制和运行方式见 [M3_PR03](../../M3_PR03.md)。本次未替 Owner 给实际账户批准假设或修改设置。
