# Time-Series + Fusion 双模型协同研究 V1

Issue [#51](https://github.com/handFOOLed/Stratide/issues/51)，基于 PR #50 合并后的 main `c3904a5eb31f40209b32beba559e82ba4e47fd8a`。本分支为开发实现与自测，**独立验收 NOT_VERIFIED**。默认 OFF、纯本机、`RESEARCH_ONLY / ELIGIBILITY_DENIED / can_execute_forward_paper=false / live_allowed=false`。

## 实际链路

`PR33 原 Snapshot/原 observer 只读核验 → 冻结实验 → Naive/EWMA 基线 → 独立 TimeSeriesAdapter → 原 Rust Agent Fusion fake task/call/Budget → 原 Candidate Registry → 原 #46 Inbox`。

Python 不直连模型 HTTP、不运行生成代码。Rust 的原 `Store / Agent / Provider / Budget Gate` 保存唯一任务、调用、预留与结算；没有新任务队列或费用账本。#50 Operator 的接线是 Issue 中的可选部分，本期保持显式 CLI `once`，未修改采集器或 Operator。行情采集许可不授予 LLM 外发许可。

## 本机操作

先准备**已有且已发布**的 PR33 store。当前真实源只有两日，执行 `once` 会返回 `INSUFFICIENT_FORWARD_HISTORY`，不会自动填入 synthetic 历史。

```powershell
cargo build --workspace
python -B scripts/multimodal-research.py --name research-v1 init --snapshot-store <已有store>
python -B scripts/multimodal-research.py --name research-v1 status
python -B scripts/multimodal-research.py --name research-v1 enable
python -B scripts/multimodal-research.py --name research-v1 once
python -B scripts/multimodal-research.py --name research-v1 history
python -B scripts/multimodal-research.py --name research-v1 verify <task_id>
python -B scripts/multimodal-research.py --name research-v1 report <task_id>
python -B scripts/multimodal-research.py --name research-v1 disable
```

成功的研究登记出现在原 Inbox，需 Owner 显式选择模板才可进入原独立评价：

```powershell
python -B scripts/research-review.py --multimodal research-v1 inbox
python -B scripts/research-review.py --multimodal research-v1 status <registration_sha256>
# 显式 Owner 操作；once 不会执行此步骤：
python -B scripts/research-review.py --multimodal research-v1 review <registration_sha256> --owner-input research/synthetic-candidate.example.json --evidence-class synthetic_test
```

切换时序入口或做无 Fusion 对照，需要**显式新实验**；旧实验保持可读：

```powershell
python -B scripts/multimodal-research.py --name research-v1 experiment --time-series-model local-test-momentum --label momentum-v1
python -B scripts/multimodal-research.py --name research-v1 once
python -B scripts/multimodal-research.py --name research-v1 experiment --label no-fusion-v1 --without-fusion
python -B scripts/multimodal-research.py --name research-v1 once
```

`external` 入口固定拒绝为 `EXTERNAL_TIMESERIES_NOT_CONFIGURED`。没有已采购、已授权或已接通的外部时序模型，也没有 TimesFM/Chronos 权重或本地 LLM。V1 不接受任意模型可执行文件、动态模块、URL、clock override 或命令。

## 数据与数值契约

- 复用 #48 的原 observer/PR33 内容 SHA 核验、原交易日历、当天上海时间 16:00 后、原 on-day 版本与连续窗口规则。只取最近 **21 个连续有效会话**，不按周一至周五构造日历。单位为 OHLC 整数 CNY fen、成交量整数 shares、未复权 `unadjusted_cny_fen`；保留原源日、观察/收到/可得时间、journal identity、源 SHA 与窗口 SHA。
- 未来、过期、缺口、晚补和修订输入拒绝。未知公司行为/PIT 不变成有效价格证据：forward 不足 21 日返回 `INSUFFICIENT_FORWARD_HISTORY`；即使日数足够，当前 PR33 未提供公司行为 PIT 认证，仍返回 `CORPORATE_ACTION_PIT_NOT_VERIFIED`。本期能产生数值结果的完整 E2E 均为 `synthetic_test`。
- `historical_replay` 入口明确拒绝为 `HISTORICAL_REPLAY_EX_POST_ONLY`；既有 68/77 日历史及已曝光 holdout 保持 `EXPLORATORY_EX_POST`，不转成新的前向或盲测材料。
- 目标固定为 **下一交易会话 close-to-close return ratio**，horizon=1；实际可交易时刻为 `UNKNOWN_OPENING_SOURCE_BLOCKED`。这些数值是实验信号，不代表下一开盘可成交。
- Naive 预期变化为 0。EWMA 使用 20 个相邻收盘收益、λ=.94，报告加权均值和零均值基准下的 RMS 风险统计。`local-test-shrinkage` 独立计算 20 期均值的 `n/(n+20)` 收缩预测及样本标准差；`local-test-momentum` 使用最近五期平均收益的一半和全窗口 RMS。基线与 Adapter 是两个实际调用入口，均不拟合后续标签。
- 基线采用 Decimal；时序 Adapter 用有限有界浮点，另以独立 Decimal 公式复算（绝对误差 ≤2×10⁻¹²）。比例以最多 12 位小数字符串序列化，范围 [-1,1]、波动非负；非有限数、缺失、错误单位或 next-day label 字段拒绝，不插值。

`ExpertResult V1` 使用 `schema_version=1 / contract=expert-result-v1`，严格字段：专家种类、模型 ID/版本、role、实验 task_id、输入 mode、instrument、target/horizon、输入 Snapshot SHA、source identity、UTC `as_of/observed_at/generated_at`、训练区间、units、missing_policy、result/output SHA、uncertainty、evidence_refs、quality、limitations、cost、authority。时间、身份与权限由可信运行器生成。每个结果 ≤8 KiB，Fusion 摘要 ≤20 KiB，冻结材料 ≤2 MiB，每实例最多 256 个实验；缺失以明确失败或 nullable cost/token 字段表示。未知版本直接拒绝，无原地迁移或旧证据改写。`text_event` 预留为未来专家种类，本期不抓公告/新闻、不实现文本专家。

新对象采用排序、紧凑、UTF-8 canonical JSON 和 SHA-256；`output_sha256` 只标识该专家的数值 result，完整结果另有 SHA。原 Registry/task-detail 继续使用原来的带缩进及换行的 SHA 协议，不混用两种编码。`UNKNOWN_UNCALIBRATED` 不等于概率；没有 `calibrated_interval`、回测胜率或 alpha 认证。

## Fusion、预算和权限

Fusion 接收验证过的两个专家、冲突、质量阻断、不确定性和有限证据引用，不含原始 bars、observer 路径、凭据或账户明细。输出有 `hypothesis/evidence_for/evidence_against/risks/falsification/next_experiment/limitations`；原 Research 的兼容字段保留，新增结构位于 `research.fusion`。严格拒绝额外交易/资金/风险/预算/工具字段，命令、脚本、路径、URL、超长文本和缺失字段。自由文本只存档，不解释为代码或策略参数。

新 scope 为 `multimodal_research_v1`；旧 `forward_eod_research_summary_v1` 的 `LOCAL_FAKE_ONLY` 逻辑保留。当前没有指定真实接收方和外发字段：即便手改匹配 grant，新 scope 的云 Provider 也会在密钥查找和 DNS 前拒绝。原 Rust Provider 的 fake 真实走任务创建、预留、dispatch、输出校验与结算；时序端为 `LOCAL_NO_BILLING`。fake 的 token 来自原 Provider 的字节上界，费用是 **TST 合成账本单位**。报告包含各专家耗时、Fusion 开始/结束/耗时、token、price_version、maximum/settled/usage；云费用为 `UNKNOWN_NOT_BILLED`，不是“已验证零美元”。

所有实例共用 Git 主目录下 gitignored `state/multimodal/.agent` 的原 Agent SQLite/预算，不能通过改名新建预算。source identity 持久绑定一个 Owner 实例；停用不会转移归属或清空历史。各实例冻结材料位于同目录 `<name>/experiments/<task_id>`；原候选 Registry 位于所属 checkout 的 `state/candidates/<name>`。config 绑定 checkout，不接受自选费用数据库。

唯一键含 source identity、Snapshot SHA、源日、target/horizon、基线/时序/融合冻结版本、Provider fingerprint、policy 和显式实验 label。同源日/同计划的后续修订不会悄悄追加调用；模型/price/grant 指纹变化需显式新实验。日/月限额与未决预留均由原 Budget Gate 检查，未更改预算算术或结算语义。

## 重复、停用、恢复和报告

### PR #52 P1 修复：精确领取与实际任务门禁

初始 HEAD `be37953` 的 bridge 校验 B 后调用全局 `Agent::tick`，可能实际领取队头 A。按 [P1 审查](https://github.com/handFOOLed/Stratide/pull/52#issuecomment-6558243819) 修复后，bridge 使用原 Agent 的 `tick_task`，在同一原 SQLite claim 事务内同时匹配 **task ID + trigger_key**；没有匹配或暂停就明确阻断，不回退到队头。其他任务保持自己的状态，等待各自处理。

原 `run_task` 在预算预留前及 dispatch 事务内，针对**实际领取的 multimodal task**，重查其 namespace/持久绑定、source identity、最新已核验 PR33 Snapshot SHA、输入 mode/source_day、上海当天 16:00 门禁和原 on-day 时间。即便通过原全局 `Agent::tick` 领取，也受同一检查。检查失效就持久取消该任务；若在预留后失效，保留原 call 并按确认未 dispatch 的 `no_charge` 记录，不发送。原非 multimodal 调度与预算算术不变。

Python 的原 observer/窗口重查失败时，也通过原 Rust Store 终止**对应的 queued intent**，避免只在研究审计里标失败。该操作按 ID/trigger 且只处理未 dispatch 的 queued 状态，不删除任务、不改已完成/未知费用结果、不重试。已完成且未归档的原结果仍可只读恢复登记。修复复现、跨任务 SQLite 事实与回归见 [P1 证据](evidence/m2-pr10/p1/README.md)；原开发证据继续保留。

`once` 使用共享 OS 生命周期锁；原 SQLite trigger_key 再约束唯一任务。Owner enable/disable 写原 meta；create 和 dispatch 事务内复查 enabled。已经进入 dispatch 的本地 fake 可以结束，停用不会伪造取消或重试。

冻结、专家、排队、Fusion settled 四阶段后突然退出可继续同一实验；特别是 settled 但尚未登记 Candidate 时只读取原任务，再登记，不二次调用。源已变或超时的 queued 任务不能绕过时间门禁。专家/格式/预算/撤销/未知结果保存失败，重复 `once` 保留终态；需要新的研究尝试时显式 `experiment`，仍受原账户的已结算/未决预算约束。

`status/history/verify/report` 使用原严格只读 SQLite reader，不打开 Agent、不恢复事务、不创建锁或 sidecar。`verify` 复核冻结内容、原 PR33、Decimal、原 Agent task/call 和原登记 SHA；失败报告明确 `FAILURE_PRESERVED_NOT_SUCCESS`。报告并排显示数值与 Fusion 假设，后者不计价格预测正确率。

synthetic walk-forward 固定使用 21 日前缀，先产生两种预测，再揭晓后一会话标签；报告 Naive/时序 MAE、拒答率和样本数。25 日输入有 4 个可核对后续标签。它是已曝光合成材料上的前缀检查，**不是独立 holdout 或策略收益比较**；不做不存在的文本专家消融。
