- **Owner**：决定产品方向、UI 意图与最终合并授权。
- **Sol Max — 工程实施**：完成 Rust 服务、Agent 任务/预算/权限、版本化 API、后端及关键功能测试；允许提供可操作的基础前端，但**不进行独立的视觉精修或全站设计系统重构**。应给 DeepSeek 可直接消费的 API 契约、状态/错误/空值和启动方式。
- **DeepSeek（DS）— UI/UX Owner**：负责**信息架构、页面布局、字体、按钮、动效、共享组件和整站前端最终实现**，包括修复跨页面信息重复与布局跳变。必须提交可运行前端而非只有设计图；不得绕过后端 API、伪造财务/Agent 记录、修改风控/账本/预算或擅自新增远程写入权限。

## 信息架构：每类内容有且只有一个主要归属页

| 页面 | 唯一主要职责 | 明确不应该出现 |
| --- | --- | --- |
| **总览** | 账户 NAV、现金、持仓、主要资产曲线、账户风险和最近最多五笔成交摘要 | Agent 消费明细、研究任务控制台 |
| **历史与报告** | 完整订单/成交、逐日可追溯核对、独立研究/回测档案 | 复制总览的资产数字大卡片、相同资金 KPI 或相同整张 NAV 曲线 |
| **Agent 管理** | 任务创建/状态/取消/暂停、模型、日/月费用预算与 Token、研究结果详情 | 账户资金/持仓/盈利大卡片 |
| **通知与审批** | 真实异常、待办及已授权的操作 | 其他页面的数据看板 |
| **设置** | 用户配置、外观、模型/数据连接等设置 | 重复的资产/研究统计 |

- 先提交**信息清单与页面归属矩阵**；对重复元素逐项说明保留/删除原因。允许同一底层数据在必要上下文用于核对，但**禁止整块重复卡片/图表**。现有「历史与报告 → 账户表现」应重新定义为具有独立目的的**逐日明细/核对**，而非复制首页净值图；变更已选 Q66 的布局需记录取舍。
- 左侧导航已承担页面切换：删除总览「查看全部 → 历史」及 Drawer 中同目的「查看完整订单/交易记录」等**冗余跨页 CTA**。内容区只保留实际操作、过滤或局部展开；点单行显示本页 Drawer，复杂表单用 Modal。
- 不为填空间造假的数据、不可用模块或无效按钮。Agent 费用、NAV、成交与市场时效必须保留真实来源/空值/失败信息。

## 统一布局：彻底消除滚动条和页面切换跳变

- 定义**唯一 App Shell 与主滚动容器**（Sidebar / Topbar / Content / Overlay 共享结构）；所有页面同一 content 宽度、标题基线、左右对齐和响应式 Grid/Flex 规则。
- 主滚动容器明确使用 **`scrollbar-gutter: stable`** 或等效稳定 gutter；避免长页面有滚动条、短页面没有时列宽偏移。Dialog/Drawer 的 body-scroll-lock 不可导致标题/侧栏跳动。不要用某页面专属 `margin-left`、手调 `padding-right: 17px` 或其他魔法像素去补偿布局。
- 同类元素必须由**同一个共享组件**负责：Button、Tabs、PageHeader、Table、Badge、Field、Empty/Error/Loading、Drawer、Modal、ChartFrame。页面通过内容槽配置，不再各自重新发明 CSS。
- 浏览器实际对比：1920×1080、1366×768、375px；有/无纵向滚动条、深/浅主题、Dialog 开关、无数据/长表格、页面切换。检查左缘基线、表格列、金额等宽与焦点/滚动位置；保存测试截图与必要的短录屏/数据证明，无浏览器则写 NOT VERIFIED。

## 视觉与动效

- 方向：**Linear 的克制、Vercel 的字体和细节、DeepSeek Usage 的简洁信息密度**，不是 Three.js 炫技金融大屏。
- 统一设计 Token（字体系、字号/字重、留白、色彩、圆角、阴影、按钮层级）。中文可评估思源黑体/Noto Sans SC，英文/数字可评估 Inter；字体须合法使用、可离线降级，不随意复制不明授权字体。金额和表格使用 `font-variant-numeric: tabular-nums`、稳定列宽、充分对比度。
- 按钮区分 primary/secondary/ghost/danger；Hover/Pressed/Disabled/Loading/Focus-visible 真实可用。动效按按钮 120–160ms、导航 180–240ms、视图 200–280ms、Drawer 240–320ms、Modal 180–240ms 作为起点；平滑但不得延误操作，并支持 `prefers-reduced-motion`。
- 现有 `apps/dashboard/src/app.js` 大量 `root.innerHTML` 重建可能导致状态/焦点/动画不连续；DS 自选**React + TypeScript + Motion** 或更轻的可维护方案，需说明取舍。框架迁移不是目的：修复交互才是目的，**不得影响已稳定的 Rust API 和真实业务语义**。

## 交付方式与 Done

1. 在 #22 接口冻结后读取最新 main、`AGENTS.md`、`docs/DASHBOARD_API.md` 与 Agent 新 API。先提交简短的设计系统、页面归属矩阵和组件交互规范，再实际改造整个站点。
2. 统一五项导航、总览、历史、Agent、设置及现存通知功能；保留已有真实业务路径，不要把 Agent 的取消/暂停/预算错误隐藏在动效下面。
3. 实测主要功能、滚动条消失/出现切换、Modal/Drawer、页面过渡、主题和 reduced motion。留比较证据，避免无意义的大型 UI 测试矩阵。
4. 以**一个完整 Draft PR** 交付界面与关键测试、截图和问题修复清单；DeepSeek 不自行合并。**DoD：没有跨页重复资产模块、没有多余“查看更多”跳转、没有滚动条宽度引起的跳变，组件/字体/按钮/动效一致，同时原有真实数据和功能正常。**

**安全边界**：只允许 Web 前端和必要的 UI 文档/测试。若需新增 Agent 写接口或变更后端数据契约，必须由 Sol 另行完成窄范围工程修改并复核，DS 不直接改 Risk、Ledger、budget gate、云密钥或交易权限。
