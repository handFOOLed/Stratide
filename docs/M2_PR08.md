# M2-PR08：自动研究 Inbox、Owner 模板关联与独立评价

对应 [Issue #45](https://github.com/handFOOLed/Stratide/issues/45)，固定 base `9a981e5e115164b73fe5756d0c8ebb8547a8b3f6`（PR #44）。Core-only；一个功能提交、一个 Draft PR，不自行 Ready 或合并。开发自测不等于 ChatGPT 固定 HEAD 复审或独立验收。

本模块把 **原 #44 已归档研究来源** 与 **Owner 显式选择的既有固定模板** 关联，复用 [原 Registry、冻结器与独立 Evaluator](M2_PR04.md)。评价只说明固定模板在指定数据上的结果，`agent_hypothesis_validation=NOT_ESTABLISHED`；不说明 LLM 生成了策略或其假设得到验证。

```text
原 Agent SQLite 已归档 SHA → 只读 Inbox
  → Owner 固定模板 JSON → 派生 registration（保留 Parent 与原任务）
  → 原 freeze → 原 evaluate / DATA_BLOCKED → 持久报告
```

## 使用

从本 worktree 根目录运行，Python 3.12+、已有 Rust/MSVC 工具链，无新依赖或网络请求：

```powershell
$env:CARGO_INCREMENTAL = '0'
pwsh -NoProfile -File scripts/with-msvc.ps1 build --workspace --locked --offline

# --auto 是已经由 #44 创建、拥有来源归属且已有归档的名称。
python -B scripts/research-review.py --auto owner-auto inbox
python -B scripts/research-review.py --auto owner-auto status
python -B scripts/research-review.py --auto owner-auto status '<原registration SHA>'
python -B scripts/research-review.py --auto owner-auto report '<原registration SHA>'

# 一条命令完成关联、冻结、评价及持久报告。Owner 必须先明确选择模板。
# 下面仅为仓库固定 synthetic 工程样例，不计真实前向日数。
python -B scripts/research-review.py --auto owner-auto review '<原registration SHA>' `
  --owner-input research/synthetic-candidate.example.json --evidence-class synthetic_test

# 历史模板必须使用另行冻结的原目标来源；不使用 EOD 摘要作为历史价格。
python -B scripts/research-review.py --auto owner-auto review '<原registration SHA>' `
  --owner-input research/fixed-candidate.example.json --evidence-class historical_replay `
  --source-dir '<既有冻结原始来源目录>'
```

`inbox/status/report` 严格只读，不获取 writer lock，不启动 sync、Agent、模型或 replay，不写原 Agent、observer、snapshot 或财务账本。它们输出同一可复核结构；`report` 包含全部审阅版本及摘要。列表按原 SQLite 归档源日排序，版本按首次保存时间排序。只读查询不会把磁盘上额外的任务 JSON、registration 文件或目录当成新的归档成果。

| 状态 | 含义 / 下一步 |
| --- | --- |
| `AWAITING_OWNER_TEMPLATE` | 只有已归档自然语言研究，`NOT_EVALUATED`；Owner 尚未选择固定模板 |
| `DATA_BLOCKED` | 已保存明确关联和原评价器的阻断收据；查看原因，补齐来源后形成新版本 |
| `EVALUATED` | 固定模板的原评价已完成，读取工程、研究、数据及资格各维度 |
| `REVIEW_REQUIRED` | 来源/材料完整性失败或审阅中断；保全材料并处理原因，原输入可恢复 |

退出码 **0** 表示只读查询成功或结果已真实持久化，包含 `AWAITING_OWNER_TEMPLATE`、`DATA_BLOCKED` 和研究不足；**2** 表示输入、完整性、并发或执行阻断。必须读取 JSON 状态，不能把退出码 0 当成策略合格。

## Owner 选择与数据证据

Owner 输入沿用原 Registry 的精确五字段 JSON：`schema_version/template_id/parameters/hypothesis/limitations`。只接受原 allowlist 的两个模板及其 exact parameters；没有默认模板，不从 Agent 的 hypothesis/evidence/next_steps 提取参数或代码。额外 exe、shell、endpoint、资金、风险、holdout 或资格字段会被拒绝；自然语言始终只保存为文本。Owner 权限沿用原 CLI 的本机文件系统控制，不新增远程授权入口。

- `synthetic_test`：原 `first-buy-second-sell-third-risk-probe-v1`，仓库固定人工数据和原风险参数，只证明工程闭环；新增真实前向日数恒为 0。
- `historical_replay`：原 `sma5-20-cross-fixed100-v1`、5/20/100 固定参数、原冻结目标查询与协议。现有合格本地来源产生 68 日、47/21 分界和 `INSUFFICIENT_EVIDENCE`；已公开 holdout 明确为 **EX_POST**。缺失、质量不足、短区间目标不符或 synthetic 原始源均得到真实 `DATA_BLOCKED`。
- 原 `forward_observed_eod` 或 synthetic EOD 是研究来源，保留原模式；评价数据另有独立 evidence class、冻结 SHA。PR #42 的 77 会话 `EXPLORATORY_EX_POST` 不被接成历史 PIT 或可交易回测。

已登记快照的 `SNAPSHOT_CONTENT_VERIFIED_AT_REGISTRATION` 只指 **Parent 登记时** 的核验。报告保留 Parent SHA、源日、task/input/model/provider/快照 SHA 与原标签，并明确 `current_source_verification=NOT_RECHECKED_OFFLINE_REVIEW`。原 observer、snapshot 变化、过期或缺失后仍可审阅已登记内容；本入口不做任何“当前来源仍已验证/仍新鲜”的断言。`TASK_ORIGIN_NOT_ATTESTED` 始终保留。

## 持久材料、幂等与恢复

所有新状态都在原 git-ignored `state/candidates/<auto>/`，不接受 `--review-dir`、registry 重定向或任意可执行文件：

```text
registrations/<SHA>.json                  # 原 Parent；新 Owner 显式关联版本
reviews/<review SHA>/plan.json            # Owner 精确 JSON/规范化 SHA、Parent、数据文件 SHA、协议/二进制 SHA
                    source/              # 新审阅自己冻结的本地历史原始源副本（如提供）
                    attempt-NNNN.json     # 开始/阶段/失败原因；旧尝试保留
                    result.json          # 原子发布的只读脱敏报告、报告 SHA 及原始引用
candidates/<candidate SHA>/...            # 原 freeze/evaluate 材料、独立 Paper 测试账本、评价收据
```

Owner JSON 以原 Registry 的 canonical JSON 保存和计算 SHA，字段顺序/空白不产生新模板选择。审阅身份包含 Parent/Owner/数据文件内容/协议/二进制，不包含源路径或随机名称。相同文件换目录复用原结果；Owner 选择、数据或可信环境改变形成新版本，旧报告不覆盖。即使移走 review 元数据，原内容寻址 registration/candidate 与评价 receipt 仍复用，不能借重命名增加一次评价。

原 Registry OS writer lock 串行保护关联→freeze→evaluate→发布；并发竞争返回 `REGISTRY_BUSY`，进程退出释放锁。每个自动来源最多列 512 条归档，每个 Parent 最多 128 个审阅版本，每个审阅最多 32 次尝试；Owner 文件上限 32 KiB，单个历史原始文件上限 4 MB。保留原评价器的有限执行超时，不新增服务或调度器。

| 实际中断点 | 相同输入重启 |
| --- | --- |
| plan 已保存，新关联登记前 | 校验 plan，生成同一内容寻址关联 |
| freeze 后 | 复核同一冻结候选并继续 |
| evaluate 前 | 在原候选下运行原评价器 |
| 评价成功、审阅 result 尚未写回 | 验证并复用原 receipt，不新增评价/账本，补齐审阅报告 |

中断尝试保留 `REVIEW_INTERRUPTED_OR_ACTIVE` 及最后已保存阶段，失败记录确定 reason。评价器自身执行失败沿用原 attempt/新独立账本规则，不把半成品当成成功。已完成审阅或评价被篡改时只报错，不能靠重新运行覆盖坏报告。

每次读取/复用会重验本机 auto 绑定与跨名称归属、原 `eod_auto_archive`、原 intent、实际 SQLite completed task 与唯一 settled fake call、Parent 内容寻址、派生关联、冻结数据、协议、原评价 artifact/receipt/handoff 和审阅摘要。复用 #44 和 #30 校验，不接受外部“completed task JSON”取代 SQLite。文件路径拒绝 junction/symlink。SHA 与本机权限用于完整性和来源复核，不声称能阻止同一 OS 用户同时恶意改写程序与全部证据。

资格始终 `RESEARCH_ONLY / ELIGIBILITY_DENIED / forward_paper_allowed=false / live_allowed=false`，没有消费者接入 Paper order path。独立 Evaluator 是原可信算法角色；开发自测、真实 Provider、PIT、alpha、真实前向开盘和另一审查者验收分别记录，不互相替代。
