## 官方 Skill、单位和来源

实施前实际加载官方 [waditu-tushare/skills](https://github.com/waditu-tushare/skills) 对应的本机 `tushare/SKILL.md`（1.1.12）与 `tushare-data/SKILL.md`（1.1.16），并读取两者的接口索引。Codex 中两个已安装条目的 metadata 名都显示为 `tushare`；以实际目录和版本区分，没有另装或重复下载。Skill 的取数流程在本任务内只采用字段解释、缓存复用和缺失说明；Issue 明确规定 **0 行情 API / 0 Token 读取**，因此没有执行凭据检查、SDK 取数或 API 冒烟。

复用 PR62 已准入的 PR58/60 标准化来源。核对 [daily](https://tushare.pro/wctapi/documents/27.md) 的未复权价格、盘后更新、成交量「手」、成交额「千元」及停牌缺行；核对 [daily_basic](https://tushare.pro/wctapi/documents/32.md) 的盘后指标、PE/PB 无量纲口径和 NULL。`amount` 特征用千元，不能误当元。收益/波动率为小数比率，rank 为横截面分位，PE/PB 只消费正且非 NULL 的已完成会话值，缺失拒绝证券，不填零。

复权因子、沪深来源日历、停牌、涨跌停、元数据的字段和限制继续沿用 [M2_PR14](M2_PR14.md)；`raw_price × 同日因子` 是事后调整价格近似，不是 PIT 总回报。昨日完整数据在今日假设开盘前使用，未来锚点与次日全天成交量不进入信号。当前幸存目录不定义历史 Universe，缺日清空暖机，BSE/身份冲突继续排除或标未知，零停牌事件不能证明可成交。

依原个人本机使用授权和[数据服务协议](https://tushare.pro/document/1?doc_id=405)边界执行；没有新接收方或再分发授权。真实行情、逐行引用、信号、完整报告和本机路径只留 ignored `state/`，Git 仅保留代码、合成测试和少量脱敏聚合/哈希。

## 策略契约和自主性

`research/autonomous_dsl.py` 定义强类型 JSON AST：

| 类型 | 节点与约束 |
| --- | --- |
| 数值 | `feature(returns/volatility/amount/pb/pe)`、`negate`、横截面 `rank`、同单位且权重和为 1 的 `blend` |
| 布尔 | 带单位、方向和值的 `threshold`、`and`、`or`、`true` |
| 组合 | `score` + `filter` + `top_k` + `exposure` + 固定调仓/最短持有会话数 |

最多深度 8、48 节点、窗口 60 会话、8 候选/轮；默认每轮提出 4 个，最多 2 轮。所有 feature 固定 `lag=1`，含义是「t 收盘已完成值，最早 t+1 假设开盘使用」。窗口以源会话计，金额单位、收益方向、阈值、缺失策略均显式校验。未知字段、重复 JSON key、非有限数、未来 lag、自由 Python/Shell/SQL/URL/路径、越界窗口/仓位都拒绝。AND/OR 任一必要特征缺失也拒绝该证券。

初始四类分别为：正收益延续、逆向收益、低波动与流动性交集、收益/低波动 rank 加权且带 OR 筛选。Seed 只在固定的 10/15/20/30 会话选项中选择收益窗口，不遍历直至获利。跨轮已接受 AST 哈希重复会归档 `DUPLICATE_CANDIDATE`；失败提案同样计入累计 trial。开发段出现预定的大回撤可以将下一轮新提案敞口降至 0.5。验证段仅采用事先冻结的「全部候选无验证会话则停止」诊断；评价段不反馈。来源/评价 SHA 仅作绑定，**不成为随机种子或调参输入**。

## 复用 Agent 和研究 Inbox 的边界

已核查原 Rust `Research`/fake 仅输出 hypothesis/evidence/risks/next_steps，PR52 使用原队列精确 `task ID + trigger_key` 领取并经预算/来源门禁；它们不能直接产生本期 AST。PR30 Registry 的正式 freeze/evaluate 只接受已有固定模板，PR46 Inbox 延续 Owner 显式模板选择。

本期采用 Issue 允许的**等价可信本地提案来源**，没有触碰原 Rust Agent、AgentDir、任务队列、价格/授权或收费账本。每份提案经 `structured-research-proposal-v1` 字节解析，严格绑定本机 producer 代码 SHA、冻结 seed、实验/轮次 task_ref 和 `RESEARCH_ONLY`，随后独立验证 AST。旧文本、伪造 Agent/source 和升级 authority 均拒绝。这不是声称原云 Agent 已能将自然语言自动编译成策略。

`report` 暴露窄只读消费契约 `autonomous-research-inbox-v1`：实验/轮次、AST/评价 SHA、研究报告、累计 trial 与失败限制；复用原 `candidates.handoff()` 的资格拒绝投影。新 AST 存独立研究档案，不伪装为旧 SMA 模板，也不写原 Registry/Inbox 数据库。真实 Provider 的新字段/接收方/grant/价格/预算没有授权，不提供调度入口；云请求、外部模型推理和新增付费均为 0。

## 评价和基准

直接复用 PR62 `Dataset.read_day`、只读锁/SQLite immutable/query_only、`Features` 的日历/身份/流动性暖机、`Portfolio.step`、费用与统计函数。每个源日同时评价所有候选与基准，交易顺序为「前一完成会话的 pending → 今日假设开盘 → 今日收盘记值 → 更新特征并生成下一会话信号」。没有新资金核算引擎。

PR62 增加两个可选、默认保持旧行为的限制：最短持有会话、实际持仓数量上限。默认新研究为 5 会话调仓/最短持有、最多 50 个证券。某个旧持仓因停牌/缺来源不能减少时，占用持仓名额，新买入不能借此超过上限。每个候选的自定义最短持有值被执行，基准固定采用同一默认约束。

基准为现金、按代码确定选择同一上限的等权、简单正收益筛选；它们消费同一每日合格集、费用、延迟、持仓上限和执行规则。所有候选同时报告 gross/base/stress、全期/开发/验证/重置 Walk-forward、回撤/波动/Sharpe/换手、成本/拒绝、stale 权重与期末零回收敏感性。极端亏损或高 stale 日保存主要价格贡献、残存暴露、估值日期和行 SHA，以便定位失败，不构造虚假卖出。

结果是从 1 开始的**无量纲分数价格暴露指数**，没有人民币本金、真实股份/成交/NAV；未认证 100 股整手、最低佣金、真实冲击、可变现价值或实际分红税。2021–2026 已曝光，尤其 PR62 2024–2026 不属于新盲测：固定 `EXPLORATORY_EX_POST / REUSED_EXPOSED_PERIOD`，多次比较和选择偏差必须保留。

## 持久控制、资源和恢复

`init` 一次记录固定版本边界、源/查询/代码/配置/seed SHA、窗口、零付费本地授权；输出目录相同而计划不同则拒绝，变更版本/代码/成本须新实验。计划、提案、分段 commit、已发布结果不可覆盖；控制状态和未提交分段可以原子替换。每轮最多 3 次显式本地尝试，无自动 retry。

```text
state/autonomous-research/<experiment>/
  plan.json / authorization.json / locators.json / frozen-source/
  control/            # 持久 pause/resume/cancel，独立控制锁
  status.json         # 可恢复的状态投影
  events/             # 不覆盖的生命周期和失败事件
  round-01/           # round-02 同结构
    proposals.json    # 评价前冻结；AST/来源/反馈/round SHA
    attempts/         # 每次开始、终止、失败与实际资源/零请求/只读收据
    chunks/0000/      # compressed 日账/目标信号/特征及持仓 checkpoint/commit
    results.json / feedback.json / archive.json
```

单 worker/单线程，默认 1800 秒/次、512 MiB 实测峰值、256 MiB 新档案、每 100 会话提交 checkpoint，最多 1500 源会话/20000 实测代码/25000 行每分区。达到时间/内存限额保存 `PARTIAL_RESOURCE_LIMIT`；磁盘达到限额保留最后已提交 checkpoint 和失败原因，不丢旧档案。

`once` 只推进下一轮或恢复当前轮，不需要人工指定策略参数。恢复只读取未完成分段所需的历史数据；已提交日段不重新执行。kill 于 freeze 可直接重用提案；kill 于 evaluate 重做未提交小段；publish/archive 中断重用已完成日账，不重扫行情；archive 已写而 status 未更新时仅恢复状态。原 Agent 没有 dispatch，因此本地计算中断不被错误标为模型账单 `OUTCOME_UNKNOWN`。如果未来增加真实 Provider，必须沿用原 Gate 的未知结果语义，本期不实现。

`pause` 停止后续源日/新轮次并提交已完成小段；`resume` 解除暂停，随后显式 `once` 继续。`cancel` 持久终止，不删除证据，不能 resume。并发 once 被同一实验的 OS writer 锁拒绝；控制命令可在运行时生效。`status/history/report/verify` 不打开原库、运行 Agent/HTTP、迁移或重写状态。`verify` 检查新档案/代码/来源绑定哈希、封存尝试审计、日账现金+暴露=指数、逐日收益递推、成本/仓位/信号方向并由日账重建统计；不重验 25m 旧行情/raw，也不是独立验收或 PIT 认证。

## CLI

python -I -B scripts/autonomous-research.py once --out state/autonomous-research/<new-experiment>

python -I -B scripts/autonomous-research.py report --out state/autonomous-research/<new-experiment>

可用 `--config <local-json>` 提供 `research_config`（PR62 支持的边界/窗口/成本字段）与 `limits`（只能在代码固定上限内缩小）。短窗必须明确给出开发/验证/评价的有序非重叠窗口；不能暗中截短五年后仍声称全量。只读 `report --full` 包含失败归因；默认摘要含同源基准、分窗和 SHA。真实运行数量、资源、失败及平台未验证范围以本期证据为准。
