# M2-PR12：A 股历史数据仓库 V1

Issue [#57](https://github.com/handFOOLed/Stratide/issues/57) 的第一阶段，仅供本机个人历史研究。独立于原前向 Observer、Snapshot、Agent、Risk/Ledger；没有 UI、策略优化、Fusion 接线或交易入口。实际取数、命令、源码 SHA 和缺口见 [本次证据](evidence/m2-pr12/README.md)。

## 范围和解释

默认区间为北京时间 **2021-11-01～2026-10-30**。V1 将此授权区间写为明确上界，拒绝今天和范围外日期；扩展到后续日期须先明确新的已收盘、已发布终点。只调用 Tushare `stock_basic`、`trade_cal`、`daily`，不查询第二阶段接口，不购买服务。

```text
显式前台 preflight / backfill / resume
  → 本机既有凭据 → 固定 Tushare HTTPS（拒绝重定向）
  → 请求审计 + 原始响应 SHA / gzip
  → 生产 Decimal 解析 / 质量校验
  → 一日全部版本行 + 来源 manifest + checkpoint 同事务
  → 只读 plan / status / report / verify / query
```

以下结论在下载完整时也不改变：

- `data_mode=historical_backfill_ex_post`，不是前向观察。
- `obtained_at` 是实际下载结束时间；历史 `received_at`、供应商历史发布时间未知，保留 null。
- `historical_pit_status=NOT_VERIFIED`，`forward_research_readiness=BLOCKED`。
- `paper_allowed=false`、`live_allowed=false`；不会生成提案、订单、成交或 NAV。
- 证券名称、上市状态是当前目录快照；不是每个历史日期当时可知的证券名录。没有独立完整历史名录，**全市场 coverage 保持 PARTIAL/UNVERIFIED**。

`COMPLETE` 日期只说明该次按日响应低于行上限、通过当前字段校验，并已把全日数据与 checkpoint 一起提交。它不证明全历史证券身份、停牌、公司行为、PIT、交易可行性或收益。空的应交易日、疑似截断、来源字段缺失标为 `PARTIAL`。

## 操作

Python 3.12 标准库即可；不编译 Rust、不启动原服务。以下命令在**本 worktree 根目录**运行。

```powershell
# 严格离线，不读取 Token，不初始化目录、不修改 checkpoint
python -I -B scripts/historical-warehouse.py plan

# 有网络：先目录多状态、日历、窄权限探测，再五个分散日期
python -I -B scripts/historical-warehouse.py preflight

# 试采通过后：上限默认由实际剩余交易日 + 10% 请求余量（至少20次）计算
python -I -B scripts/historical-warehouse.py backfill

# 显式续传；已有 COMPLETE 日期跳过，失败日期默认不重试
python -I -B scripts/historical-warehouse.py resume

# 先检查前次失败原因；在同一总预算内显式重试失败日期
python -I -B scripts/historical-warehouse.py resume --retry-failed

# 严格只读
python -I -B scripts/historical-warehouse.py verify
python -I -B scripts/historical-warehouse.py status
python -I -B scripts/historical-warehouse.py report
```

凭据默认依次读取进程 `STRATIDE_TUSHARE_TOKEN` 和原 Stratide 仓库绑定的 Windows Credential Manager，均不写回。未取得凭据时 **0 请求**，不会创建仓库。不要把 Token 放在参数、PR 或聊天中。

本次还提供 `--credential-source existing-tushare-mcp-config`：显式只读复用本机已连接 Tushare MCP 配置中的同一账号 Token，限定为 Tushare 自己的 HTTPS `/mcp/` 配置，随后通过原始 HTTPS 数据接口采集。配置 URL 和 Token 只存在于采集进程内，不保存到仓库、环境变量或日志；不修改 Codex 配置。MCP 自身的转换文本不是原始 HTTP 字节，不能拿它替代 HTTPS 原响应证据。

可选控制：

```powershell
python -I -B scripts/historical-warehouse.py preflight `
  --credential-source existing-tushare-mcp-config `
  --max-calls 32 --total-call-cap 1600 --rpm 10

# 示例值须以 plan 的实际估算和已消费数为准
python -I -B scripts/historical-warehouse.py resume `
  --credential-source existing-tushare-mcp-config `
  --max-calls 100 --total-call-cap 1355 --rpm 10
```

默认每分钟 10 次，硬上限 **30 次/分钟**，单 worker；不能据此推定账号有更高权限。首次未知接口最多一次窄权限探测。权限/鉴权拒绝持久化，后续不会再次请求这个 API；没有自动续费或自动权限升级。默认预检最多 32 次，初始仓库总上限 1,600 次；首次正式回填使用试采计算的上限，也可显式降低。后续 resume/preflight 默认沿用已持久批量总上限，**不随已消费数自动追加额度**。每个实际尝试都计数，包括错误和未知结果。`--max-calls 0` 无效，不能借此变成无限制。

每个请求前按已有实际请求时间限速，检查总/本轮上限和可用空间。试采后的正式运行还须留出估算的剩余落盘量及默认 1 GiB 余量。429、供应商频次限制、网络结果未知、权限错误会停止本轮，不内部自动重试。429 的数字 `Retry-After` / 默认 60 秒冷却跨进程保留。恢复须显式运行，原尝试和 raw 不覆盖。

## 目录和持久契约

```text
本 worktree/state/historical-warehouse/<store>/   # 已被 /state/ ignore
  warehouse.sqlite      # schema 2012，WAL，synchronous=FULL
  writer.lock           # 仅本仓库的 OS 进程锁
  raw/00000001.json.gz  # 原 HTTP body；SHA 针对解压后的原始字节
```

`--store` 默认 `main`，只能是简单名称；没有任意目录参数，也不跨 worktree 复用 Git common root 的真实状态。CLI 拒绝根目录链接逃逸。不会迁移或打开旧 Observer/Agent 财务数据库的写连接。

SQLite 主要关系：

| 表 | 作用 |
| --- | --- |
| `meta` | 固定来源/字段版本、单位、模式和资格契约及 SHA |
| `runs` / `attempts` | 参数、凭据来源标识、授权来源、起止时间、HTTP/供应商码、返回数、可能已发送、raw/canonical/元数据 SHA、结果分类 |
| `objects` | 每次实际取得的证券目录/逐日日历及来源版本；旧快照不覆盖 |
| `daily_rows` | `(ts_code,trade_date,row_sha)` 不可变行版本；精确数值文本与完整原返回行 |
| `day_versions` / `day_rows` / `day_sources` | 每日发布版本、内容 SHA、原尝试绑定、来源修订关系 |
| `checkpoints` | 一日发布版本指针，与该日完整行集合在同一事务提交 |

有证券时间窗索引和交易日索引。按日处理，SQLite 行版本校验流式执行，不把五年数百万行一次载入内存。重新下载同一当前内容不会重复行；供应商修订产生新版本，manifest 明确 `revision_of_version`，即使价格改回更早数值也产生新的观察版本。旧 raw、行版本和 as-of 视图保留。

raw 在标准化之前落盘，保留下载失败/坏数据证据。开始请求前持久记录 `may_have_sent=true`；若进程中断留下 `SENDING`，下次显式写入恢复为 `NETWORK_OUTCOME_UNKNOWN`，不计成功。进程在日期事务中途终止后，SQLite 回滚该日行及 checkpoint；此前 raw/尝试仍在，重试产生另一条尝试。

只读命令只读打开既有锁和 SQLite immutable/query-only 视图，不创建 WAL/SHM。下载正在持锁或存在未恢复 WAL 时返回忙/需要恢复，避免读取过期或半提交状态。恢复只发生在显式 `preflight/backfill/resume` 的写路径。

## 数据校验和缺口

来源约定参考实施时核对的官方 [daily](https://tushare.pro/document/2?doc_id=27)、[stock_basic](https://tushare.pro/document/2?doc_id=25)、[trade_cal](https://tushare.pro/document/2?doc_id=26)。账号权限以实际响应为准。

| 字段/类型 | 处理 |
| --- | --- |
| OHLC / `pre_close` | 未复权元；校验正数、有限值、low ≤ open/close ≤ high，不比较跨日价格是否相等 |
| `vol` / `amount` | 分别为手（100股）和千元，非负有限 Decimal/精确字符串 |
| 整数转换 | `exact_scaled` 只接受可精确表达的分/股/元，不四舍五入；查询保留原单位 |
| `pre_close=null` | 原样保留 NULL，标 `PRE_CLOSE_UNVERIFIED_NULL_FROM_PROVIDER`，该日 PARTIAL，不推算昨收 |
| 重复/范围 | 同键相同行合并并计数，冲突重复拒绝；校验代码、日期、分区、交易所、上市状态 |
| 当前目录特殊项 | B 股、区间前已退市证券只保留 raw；北交所 `symbol`/`ts_code` 可不同，保留两者，不捏造代码变更历史 |

`stock_basic` 按 SSE/SZSE/BSE × L/D/P/G/UN 查询。原始字段、状态组合、行数和响应 SHA 均保留。不能只凭 L 名单宣布历史全市场完整。过去已退市而仍在区间内的证券不会因今日不在 L 名单被删掉。今日快照不证明历史每日名称/状态可知。

沪深日历分别取得完整区间逐日 open/closed 和 `pretrade_date`。当前文档未列 BSE 参数，V1 **不伪造 BSE 逐日记录，也不按星期几补齐**；报告保留 BSE 日历缺口。已知沪深开放日的 daily 响应仍可保留北交所代码，但不据此宣称北交所历史覆盖完整。

daily 原响应达到 **6,000 行**即疑似截断。若有可分区代码，将已知有效目录与返回代码并集按每组 200 个 `ts_code` 重查，保留所有尝试，合并去重并要求原返回行可一致重现。即使分区成功，缺乏可信全历史名录时仍为 `PARTITIONED_KNOWN_UNIVERSE_UNVERIFIED / PARTIAL`；不会将可能遗漏的历史代码排除后宣称完整。目录达到上限也保留疑似截断记录及 UNVERIFIED 结论。

证券缺行仅在 COMPLETE 日期上按当前目录可核对的上市区间和实际日历做候选缺口统计，名称为 `MISSING_OR_NOT_TRADING_UNVERIFIED`；PARTIAL 日期另列，缺 BSE 日历时其预期/缺行数为 null。没有停牌接口、历史代码映射及公司行为证据，不能据缺行认定停牌，不补零、不复制价格。

`verify` 校验 SQLite integrity/foreign keys、契约、请求元数据哈希、原响应字节、canonical 行、按日行集合与 manifest，并从原 HTTP 响应复算发布版本。它验证**存储/来源绑定**，不是独立 PIT 或策略合格认证。

## 可复现研究查询

```powershell
# 固定20个实际交易日；输出三个证券的精确值和实际取得来源
python -I -B scripts/historical-warehouse.py query `
  --start 20211101 --end 20211126 `
  --symbols 600000.SH,000001.SZ,600519.SH --limit 100

# 按某日扫描全市场（V1 每次最多10000行，超出会给出 has_more）
python -I -B scripts/historical-warehouse.py query `
  --trade-date 20261030 --limit 10000

# 固定已下载版本边界，用于保留某次研究的历史输入
python -I -B scripts/historical-warehouse.py query `
  --start 20211101 --end 20211126 `
  --symbols 600000.SH --as-of-version 5 --limit 100
```

`version_id` 是本仓库发布序号，不是当年可得时间。冻结研究应保存实际 query 输出 SHA 和 as-of 边界；后续下载修订不会更改该版本。公开 Git/PR 只保存脱敏摘要、命令、哈希；实际 OHLCV、全量目录、SQLite、raw、请求审计和私有路径留在 ignored 本地目录。
