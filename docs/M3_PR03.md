## 冻结契约

```text
#82 原 MarketDaySnapshot + #83 原 Agent task / Registry（只读）
 → 独立 fixed-ticket-paper-v1（Owner 首次显式批准）
 → FreezePortfolioV1：完整批次 + 确定顺序 + Risk 审批/预留，同一 SQLite 事务
 → trade_cal 的下一实际交易日，盘后实际取得 daily
 → ConfirmPortfolioV1：整个账户同一假设开盘估值 → 原 fill_order → 原 Ledger
 → EX_POST_OPEN_ASSUMPTION / NO_FILL，剩余预留释放，同一事务
 → 原 /api/v1/account、positions、orders、fills 与 Dashboard
```

不增加财务数据库、账户、券商适配器、付费调用、后台服务或安装包。原 `ledger.sqlite` 的 OS writer lock、原 SQLite FULL 同步事务、事件去重、校验链、现金/股份/手续费守恒、账户及策略 Risk 锁继续生效。`portfolio` 只在显式配置后出现在原 State；未配置的旧 V1 事件序列化和 SHA 保持兼容。不打开或改写已有真实本机账本。配置后的账户拒绝旧 Submit/Match/EOD 路径，不能绕过组合冻结。

### Owner 首次授权与确定性策略

先显式设置原账户本金、账户/策略风险限额及身份，再批准 `fixed-ticket-paper-v1`。Policy 是不可修改的原账本事件，含证券宇宙、每证券目标金额、最大持仓数、每日订单数、候选数、单笔股数、整批共享撮合容量、每证券金额上限、每日费用上限、价差容忍、最低 T 日成交额及逐证券适用费率。没有隐含本金、注资、杠杆或风险默认值。配置后仅允许暂停/恢复新的意图；已冻结事实与到期结算仍运行。

准入要求同一 T 日 READY 实收快照、原 Agent 完成结果与 Registry 精确一致、原筛选代码/规则/84 会话来源可重现。研究旧字段仍是 `RESEARCH_ONLY / ELIGIBILITY_DENIED / can_execute_forward_paper=false`；单独的 `UNVERIFIED_PAPER_HYPOTHESIS` 不授予任何正式交易、历史 PIT 或盈利资格。模型文字与模型权重不进入编译器；配置中 `approve_fixed_baseline=true` 明确批准固定目标金额基线，不能把它解读为模型 Alpha。

对原确定性 shortlist 中证券按 T 收盘价向下取整至百股，目标金额来自 Owner Policy；已持有但未入选的证券目标为零。每笔变化受单笔股数上限限制。卖单在前，然后市场名/证券代码升序，整批在 T 冻结。资金不足的后续证券由原 Risk 拒绝，绝不虚构卖出所得来资助尚未发生的买入。最大持仓名额保守计入已有持仓和新买入预留，不提前借用尚未卖出的名额。

当前撮合支持成熟、普通沪深主板 A 股的百股/T+1/一分 tick 假设。ST、上市不足 180 日、停牌、退市、BSE、STAR、ChiNext 或无法确认的规则在原市场覆盖中保留，在 Paper 编译中明确 `UNSUPPORTED_PAPER`。没有为未支持证券套用普通主板规则。交易范围有限是本版本明确限制。

### 时点与跨日

T 日上海时间 16:00 后才能冻结，真实墙钟由 CLI 接收时赋值，不能通过 JSON 回填。源、日历、研究 `generated_at/finished_at`、登记与估值均须已取得；研究完成不得晚于冻结或 T+1 开市。跨日补跑不能生成过去 T 日订单，时点反例保留 `LATE_RESEARCH_ONLY`。不足 84 个 READY 全市场会话时继续等待/空仓，不借历史或录制输入补足真实暖机。

原两次 `trade_cal` 请求的结束日扩展为当天后 40 个自然日，原 `objects` 保存实际收到的未来日历；行情采集及缺口报表只到当天。T 到下一开市日的每一个自然日均需 SSE/SZSE 一致且不缺日。不能用普通工作日推算，缺日历记录 BLOCKED/空仓批次。修改不直接运行新行情请求、不读取凭据，也不扩大历史行情授权。

T+1 上海 16:00 后实际取得的日线才可提交确认，固定 18:00 截止（与 #82 默认窗口一致）；迟到、缺行情、停牌、价格带边界、未获显式假设许可的公司行为不确定或费用不确定均 NO_FILL。开盘加/减一分不利 tick，撮合容量只取 Owner 前一天冻结值，余量 IOC 释放。批次内先用所有已持仓证券的同一假设开盘估值通过账户 Risk，再按冻结次序执行；收盘价只在全部执行后更新 NAV，不能用次日高低收或实际日成交量择单/排序。来源返回乱序不改变优先权。未知全账户估值不授权新增风险。

**R1 真实 EOD 假设路径：** 默认仍只接受公司行为已核验输入。Owner 可在首次冻结 Policy 中单独设置下列对象，批准仅用于 Paper 的 `no-detected-action-mainboard-v1`；`approve_fixed_baseline` 本身不代替这个许可。本次开发不替 Owner 修改现有账户或授予许可。

```json
{
  "capacity_scope": "Batch",
  "capacity_shares": 100,
  "unverified_eod_assumption": {
    "version": "no-detected-action-mainboard-v1",
    "max_exposure": 500000
  }
}
```

以上是需合入完整 Policy 的**说明性合成配置**（金额单位分），不是 Owner 本金/限额设置。Owner 须自行给定 `max_exposure`，不可超过原策略/账户上限；编译预留和开盘执行都再次检查该独立上限。此路径整批最多 100 股，另受原仓位、费用、现金、T+1 和所有风险锁限制。新 Owner CLI 配置必须显式 `capacity_scope=Batch`，容量按冻结顺序在全部证券之间共享，不从次日日成交量推导。不带该字段的既有 PR88 事件保持原历史每单语义和 SHA，Dashboard 明确标为旧策略，不静默修改历史。

Runner 冻结 T 日真实 `adj_factor`，T+1 要求：支持且状态正常的成熟普通主板；复权因子有效且与冻结值完全相同；`daily.pre_close` 等于冻结的 T 收盘价；开盘及不利一跳严格处于声明的主板 10% 假设带、原限价内。某证券缺因子、因子变化、昨收断裂、缺报价、停牌/ST/新股/不支持规则时单证券 NO_FILL。所有已有持仓须有可用假设估值，否则仍拒绝全部新增成交。不会把次日高低收或成交量用于选择成交。没有另购接口或新增采集请求。

上述连续性只表示**未检出公司行为**，不证明没有分红、税费或股权变动。`corporate_actions_verified` 始终保持 false，成交明确记录 `CORPORATE_ACTIONS=UNVERIFIED / EX_POST_OPEN_ASSUMPTION / no-detected-action-mainboard-v1`；Dashboard 显示批准的假设及独立金额上限。这是隔离的模拟模型，不能当作真实股息/公司行为总收益、历史 PIT 或可交易性证据。可信完整公司行为输入仍可走原核验路径。

每一笔输出保留 `OPENING_OBSERVED=NOT_VERIFIED / HISTORICAL_PIT=NOT_VERIFIED / REAL_TRADABILITY=NOT_VERIFIED`。这是日线事后模拟，既不声称开盘时实收，也不是实时前向盈利记录。

### 未知 NAV 的跨日恢复

上一批缺持仓报价后，先终结 NO_FILL、释放预留、保留未知 NAV。新的完整 EOD 到达时，原 Runner 在研究前自动提交独立 `RecoverPortfolioValuationV1 / NO_TRADE_REBASE` 事件：仅允许当前真实墙钟日期盘后、无活动订单/待确认批次，所有实际持仓均有当前同源报价和可用核验/已批准假设输入。假设恢复须与最后冻结的持仓复权因子一致；发生因子变化则等待可信公司行为处理，不能凭新价格假造股数。

恢复不修改旧批次、订单、成交、现金、股数或手续费，不回填缺口价格/收益。先用**旧亏损基准和原高水位**检查跨缺口损失，再把当前已知 NAV 设为后续日初基准；已有或新触发的亏损、回撤、人工锁一律保留。缺口及恢复日的当日盈亏继续不可用，API/Dashboard 显示恢复收据；下一份新研究仍需独立满足原时点和准入条件。即使暂停新意图，估值恢复也继续，但不自动解除暂停。

### 事务与故障

整批 Freeze/Confirm 各只有一个原 Ledger 事件。每 T 日只准一个冻结批次；确定性 proposal ID 绑定 Policy/源日/证券/方向；原事件重试不再预留、成交或收费，换事件 ID 也不能重放已消费批次。事务中途会计失败整批回滚；进程退出后先读原 SQLite 事件/尾标恢复，不能用 RAM 猜提交失败。部分证券缺行情可以和其他证券的假设成交在同一事务中终结。

原 EOD watch 先完成采集持久化，再处理上一批确认/到期，随后可选研究，最后读取原研究冻结新批次。研究或 Paper 模块导入/初始化/运行异常只在本轮输出明确 BLOCKED，后续采集继续；下一轮先读原账本，不自动重发未知事件。没有后台调度器。¥5/日、¥100/月与原外发许可路径不变，Paper 不调用模型、不读 key，也不能修改 Agent 预算。

## 本机运行

```powershell
.\scripts\with-msvc.ps1 build --locked -p stratide-cli -p stratided --bins
# 复用已显式创建的 current Paper Ledger；不把研究 NAV 导入账户
python -B scripts/paper-portfolio.py bind --ledger <原Paper账本目录>
python -B scripts/paper-portfolio.py configure --input <Owner-Paper-policy.json>
python -B scripts/paper-portfolio.py status
python -B scripts/eod-operator.py market once
# 原 watch 会持续消费；也可只消费本地已有来源：
python -B scripts/paper-portfolio.py once
python -B scripts/paper-portfolio.py pause
python -B scripts/paper-portfolio.py resume
# Dashboard 必须指向同一账本
target/debug/stratided.exe --paper-ledger <原Paper账本目录> --assets-dir apps/dashboard/dist
```

未建立账户时，使用原 `paper-eod-init <新目录> <Owner-PaperAccountConfig.json> <来源版本ID>`，Owner 显式提供全部资金/风险数值。不得为避开旧余额再建第二个交易账户。绑定文件只存原账本路径；Policy、自动开关和批次财务事实在原账本。已冻结的旧策略不自动取得新假设许可。`configure` 的 JSON 精确字段见 `crates/ledger/src/portfolio.rs::Policy`，逐证券费用沿用 `FeeSchedule`；字段不允许模型扩写。此 PR 不替 Owner 配置本金/开启自动化。

Dashboard “当前账户”继续只读原 Ledger；新增卡片显示策略开关/固定金额、冻结源日→目标日、原候选任务、Policy/来源 SHA、编译拒绝、原订单风险拒绝/模拟成交和 NO_FILL。列表最多最近 30 批次，完整历史在原账本；不混入研究 NAV。普通持仓/成交/现金/收益/手续费/回撤依旧使用原权威 API。
