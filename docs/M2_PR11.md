# M2-PR11：Cloud Risk Expert + Autonomous Portfolio Fusion V1

Issue [#55](https://github.com/handFOOLed/Stratide/issues/55)，实际 base 为 PR #54 合并后的 `main a27f466e643cb7dd05e3be72b83402a4599a301f`。本模块通过两种生产 API 协议生成风险证据和自主股票/现金目标组合，接入原 Rust Agent、Budget Gate、Registry 和 #46 Inbox。运行证据见 [m2-pr11](evidence/m2-pr11/README.md)。当前交付为离线可运行的 Draft；真实云请求、费用完整性和预测能力均未验证。

## 运行

Windows 使用已有 Rust/MSVC 和 Python 标准库；不安装模型、GPU、Google SDK 或新依赖。

```powershell
scripts/with-msvc.ps1 build --workspace --locked --offline
python -X utf8 -B scripts/risk-portfolio.py init
python -X utf8 -B scripts/risk-portfolio.py models
python -X utf8 -B scripts/risk-portfolio.py status

# 只启用本机 synthetic/recorded 工程实验；不是云付费或数据外发授权。
python -X utf8 -B scripts/risk-portfolio.py enable
python -X utf8 -B scripts/risk-portfolio.py --name rp-example-calm synthetic-freeze --scenario calm --strategy-version idea-v1
python -X utf8 -B scripts/risk-portfolio.py --name rp-example-calm once
python -X utf8 -B scripts/risk-portfolio.py --name rp-example-calm verify
python -X utf8 -B scripts/risk-portfolio.py --name rp-example-calm report
python -X utf8 -B scripts/research-review.py --risk-portfolio rp-example-calm inbox

python -X utf8 -B scripts/risk-portfolio.py --name rp-example-stress synthetic-freeze --scenario stress --strategy-version idea-v2
python -X utf8 -B scripts/risk-portfolio.py --name rp-example-stress once
python -X utf8 -B scripts/risk-portfolio.py history
python -X utf8 -B scripts/risk-portfolio.py disable
```

首次 `init` 默认 OFF；重复初始化复用原状态。`models/status/history/verify/report/inbox` 只读，不启动 Rust writer、恢复、推理或费用预留。`once` 是前台一次运行，没有后台服务。重复同一批次复用终态，不重发失败/未知调用；被杀进程通过原 Agent 恢复。旧任务、审批和预留不覆盖。

所有工作树/批次/两家 Provider 固定使用 Git common root 下 `state/risk-portfolio/.agent/agent.sqlite`，与原 Agent 完全相同的 `tasks/calls/meta`、排他锁、SQLite 事务和预算实现。没有供应商独立预算；旧 fake-only 实验没有迁移或放宽。`GIT_DIR/GIT_WORK_TREE/GIT_COMMON_DIR` 不能重定向这份云研究权威，复制/重命名批次不能重复领取同一冻结输入。新目录不是清除旧跨期预留的方法。

## 新数据与权限契约

```text
risk_portfolio_v1 冻结数据、代码/Prompt SHA、模型配置、策略版本
  → 原 Agent risk task / reserve / dispatch
  → BigQuery AI.FORECAST 的真实请求构造和响应解析
  → RiskExpertResult V1 + Naive/EWMA 数值基线
  → 原 Agent fusion task / reserve / dispatch
  → DeepSeek Chat Completions 的真实请求构造和响应解析
  → TargetPortfolioProposal V1 / 策略产物 SHA
  → 原 Registry → 原 #46 Inbox → Owner 显式关联/独立冻结评价
  → RESEARCH_ONLY / ELIGIBILITY_DENIED
```

这是单一研究批次的两个原 Agent 持久任务，两次调用都进入同一日/月预算及调用审计；Fusion 必须绑定实际已完成风险任务的原 SQLite 结果 SHA。原 PR52 Schema 1 的 `next_session_return_ratio` 与字符串假设契约保持原语义。`multimodal_research_v1`、`forward_eod_research_summary_v1` 的 `LOCAL_FAKE_ONLY` 未改变。

新 Grant 的 purpose 为 `risk_portfolio_v1`；各 Provider 分别只接受 `[risk_portfolio_v1, risk_timeseries_v1]`、`[risk_portfolio_v1, portfolio_fusion_v1]`。receiver、字段白名单、模型版本声明、策略/Prompt/Adapter SHA、计价来源/版本和调用上限固定在配置与冻结输入中。receiver/字段/版本变更必须新冻结；旧 grant 改名不能授权新协议。每阶段最多一次调用，批次最大两次；没有模型 fallback。

当前输入只能是明确标记的 synthetic，包含三只股票、84 个历史收盘点和独立 20 会话合成交易日历。84 closes → 83 returns → **64 个 rolling-20 RMS 风险观测点**；PR54 的 21 个前向有效日门槛不能替代模型 context。真实/历史输入不能靠自报 readiness 或拼接事后行情绕过门禁。真实来源重审仍为两日、`BLOCKED / INSUFFICIENT_MODEL_CONTEXT`，见 [真实只读审计](evidence/m2-pr11/real-audit.json)。本期没有实现可放行真实/历史数据的来源认证桥。

## 两套云协议

| Adapter | 实际构造/校验 | 当前状态 |
| --- | --- | --- |
| BigQuery `AI.FORECAST` / `TimesFM 2.5` | 固定 `jobs.query` endpoint、project/dataset/location、参数化 `UNNEST`、固定 SQL/model/列/20-step horizon、有效行数和 `maximumBytesBilled`；验证 job/schema/status/行数/序列/有限数值/预测时间轴 | recorded + libtest loopback 完整运行；真实付费 `BIGQUERY_BILLING_BOUND_NOT_VERIFIED` |
| DeepSeek `deepseek-flash` | 官方 `max_tokens`、`thinking.disabled`、`response_format.json_object`；无工具；验证 model、单 choice、stop、usage 上限和严格组合 JSON | recorded + libtest loopback 完整运行；真实接收方/Key/价格/授权未验证 |

BigQuery 只接收 instrument、session index 对应的时间轴和 rolling-20 RMS 比率，不发送原始 Tushare payload。模型使用连续的 ordinal 日时间轴；返回时间必须逐步对应该轴，再显式映射到已冻结交易会话，不能把模型自然日当 A 股交易日。没有任意 SQL、建表/导出/公开表接口、自动 job 重发或工具调用。未完成/异常 job 保留失败与未知费用，不伪装成云结果。

BigQuery 的 Bearer 凭据是按 Google 官方 OAuth2 机制取得的 access token，经专用环境变量提供；DeepSeek 使用其 Bearer API key。程序不调用 gcloud、不读取任意凭据文件，不在 argv/配置/日志中放凭据值。recorded 模式完全不读取真实 Key，使用固定假认证头。HTTPS 生产传输强制 TLS 校验、固定官方 URL、校验并固定解析后的公网 IP、禁代理/重定向/自动重试、有限超时及 64 KiB 响应；loopback/故障注入仅编入 libtest，不存在于生产 CLI。

官方协议依据：[AI.FORECAST](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-forecast)、[jobs.query](https://docs.cloud.google.com/bigquery/docs/reference/rest/v2/jobs/query)、[Google 身份验证](https://docs.cloud.google.com/bigquery/docs/authentication)、[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。供应商可能修改别名指向；`deepseek-flash` 的声明版本是本机策略版本与 Provider alias，**未证明供应商权重不可变**。

## 数值与组合语义

风险目标为 `rolling20_rms_daily_return_ratio`：逐会话收益比率的 20 会话 RMS，再预测未来 5/20 会话对应风险代理的均值。Naive 为最后一个代理值；EWMA 使用 λ=0.94。没有年化；不是未来价格/收益分布。输入可用时间、顺序、缺失、公司行为标记、异常跳变、snapshot SHA、context、calendar 均有门禁。风险状态由独立版本规则按 daily ratio 0.025 分为两种实验状态，该阈值不是交易 Risk 配置。

VaR/ES/尾概率、置信区间、校准及跨标的协方差保持 `UNKNOWN_UNCALIBRATED / UNKNOWN_INSUFFICIENT_EVIDENCE`。生产报告缺未来结果时误差为 UNKNOWN；测试另用没有送入模型的独立合成后缀和 Decimal 算法计算 Naive/EWMA/录制响应误差，同时分别记录延迟、TST 费用及拒答情况。不能据此声称真实模型优势或 alpha。

组合严格验证字段、有限长度、非负整数 bps、去重证券、股票+现金恰好 10,000；允许 100% 现金。策略可以是新的可证伪假设，不强制 SMA。代码/URL/工具/预算/Broker/执行许可字段及非法目标整份拒绝，不归一化权重。`strategy_hash` 绑定策略版本、模型/Prompt/Adapter 计划；可信封装另计算整个实际建议的 `strategy_artifact_sha256`。模型自报置信度不构成评价。

有证据证券才能进入持仓目标；额外发现只登记 `DISCOVERY_UNVERIFIED`，不进入执行候选。无可信账户持仓/现金时，换手/费用为 null（UNKNOWN），没有伪造调仓单或账户 NAV。原 Inbox 可做显式模板关联和原独立冻结评价；本期接线测试只评价原固定 synthetic 模板，**不代表新组合策略已具可执行实现或独立资格**。

## 费用门禁与停止条件

P0 为费用/凭据/外发，P1 为数据与研究真实性。两套 Adapter 复用原 `budget::reserve` 和调用表；当前设置复核、输入/receipt/模型 pin、enable/撤销检查在 reserve 与 dispatch 都执行，dispatch 还按最新日/月上限复查现有承诺。两阶段最大费用之和须不超过冻结批次上限。日/月、调用上限和未结算预留不能由模型修改。

BigQuery 计价单位为 query bytes、prediction bytes、storage byte-seconds；`maximumBytesBilled` 或 dry-run 不能证明其他维度的完整硬上界。本模块**没有可信真实报价/上界**，因此代码直接拒绝其 HTTPS 授权；不使用 token 单价冒充 query 完整预算。DeepSeek 使用原 token Price/日月预算，但也不能绕过整个批次的 BigQuery 门禁。默认 TST 的 1,000/81,920 最大预留仅为合成计量测试，实际账单始终 UNKNOWN/NOT_BILLED，不是供应商价格。

dispatch 后超时、HTTP 错误、schema/usage 异常或 kill 均保留最大预留，状态 `OUTCOME_UNCERTAIN`，不自动重试或换模型。失败保存安全错误码、请求/响应 hash、模型与调用引用；不存错误原文或敏感头。已结算后中断也不二次计费。真实费用只能经原可信账单对账路径处理，模型没有释放预留权限。
