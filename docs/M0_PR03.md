## Windows CLI 完整闭环

在仓库根目录运行。需要 Rust stable、现有 MSVC 工具链；若 Developer PowerShell 已配置，可把 `./scripts/with-msvc.ps1` 换成 `cargo`。下面的目录名是示例；账本一旦创建就不能清空或当作新本金重建。报表目录也不会覆盖不同内容。

```powershell
python samples/generate_m0_pr03_synthetic.py
$input = 'samples/m0-pr03-synthetic.json'
$sha = (Get-FileHash $input -Algorithm SHA256).Hash.ToLowerInvariant()
# 已提交样例的 SHA-256 应为 e6897a41eedf0a49ea36c4870586cae9b964e05799d4010fd34adcb57fefb5fe
./scripts/with-msvc.ps1 run --locked -p stratide-cli -- paper-replay $input state/my-pr03-ledger state/my-pr03-report --sha256 $sha --initial-cash-fen 1000000 --max-order-fen 500000 --account-cap-fen 800000 --strategy-cap-fen 500000 --daily-loss-fen 100000 --drawdown-fen 200000
./scripts/with-msvc.ps1 run --locked -p stratide-cli -- paper-status state/my-pr03-ledger
./scripts/with-msvc.ps1 run --locked -p stratide-cli -- paper-report $input state/my-pr03-ledger state/my-pr03-report --sha256 $sha
# 重启新进程、重复同一命令：输出逐字节一致，账本不新增经济事件。
./scripts/with-msvc.ps1 run --locked -p stratide-cli -- paper-replay $input state/my-pr03-ledger state/my-pr03-report --sha256 $sha --initial-cash-fen 1000000 --max-order-fen 500000 --account-cap-fen 800000 --strategy-cap-fen 500000 --daily-loss-fen 100000 --drawdown-fen 200000
Import-Csv state/my-pr03-report/daily.csv | Format-Table
Import-Csv state/my-pr03-report/orders.csv | Format-Table
Import-Csv state/my-pr03-report/fills.csv | Format-Table
```

`--initial-cash-fen` 等六项资金和风险阈值均由运行者显式提供。样例中的 1,000,000 分为**人工模拟本金**，不是实际投入或默认授权。`paper-report` 重新校验输入哈希、配置与权威账本事件，只有全部冻结命令已提交且无额外事件时才导出。若中途退出，可用原 `paper-replay` 继续；已提交事件用相同 ID/内容去重，冲突会拒绝。`paper-status` 展示完整当前账本状态。

### 中断后的恢复

| 中断时的状态 | 操作与结果 |
| --- | --- |
| 尚未创建账本目录 | 用原命令首次创建；本金仍须显式传入 |
| 已有可校验的 genesis 和部分事件 | 用原命令、原输入/配置和原目录续算；已提交事件不会重新成交 |
| 所有事件已提交，报表尚未发布 | 用原命令、原报表目录重试；报表先写到同级 `.目录名.stratide-*` 暂存目录，六文件写完、同步并校验后才改名发布 |
| 旧版本在最终目录留下顺序一致的部分文件 | 若此前完整文件及最后一个截断文件的字节与本次结果前缀吻合，程序先将旧目录完整改名为 `.目录名.stratide-*.interrupted`，再发布完整报表；输出归档路径，原部分证据保留 |
| 既有报表内容冲突、顺序异常或有未知文件/链接 | 拒绝恢复，保留原目录；核对来源后显式指定新的报表目录 |
| 首次初始化只留下空/截断 SQLite 或不能核验的 genesis | `paper-status`/原命令会拒绝恢复；保留整个账本目录及 journal/锁文件，停止使用该目录。若无法恢复可信账本，Owner 可显式选择**新目录**和本金参数开始一份独立模拟；这不是旧账本续算，两个账本不能合并成重复资金 |

不要通过删除数据库/锁文件或清空原目录绕过本金初始化检查。报表暂存目录和 `.interrupted` 是未完成副本/原始证据，不是成功发布的报告；进程强杀后可能留下它们，原命令重试不依赖也不删除这些旧副本。六个最终报告的内容和 v3 账本语义不因本次修复而改变。这里验证的是进程中断；物理断电、磁盘满与文件系统故障仍未验证。

## 输入和时间边界

提交的 [人工输入](../samples/m0-pr03-synthetic.json)由[生成脚本](../samples/generate_m0_pr03_synthetic.py)明确构造，没有下载市场数据。生成器按 UTF-8/LF 写原始字节，`.gitattributes` 固定 Windows/Linux 检出换行，以保持 SHA-256 可复现。JSON schema v1 要求单只证券、`synthetic_test` 或 `historical_replay` 模式、来源/许可/版本、`Asia/Shanghai`、`unadjusted_cny_fen`、完整日线 OHLC/容量/停牌核验、明确费率及其有效期，以及每个会话的 `opens_at`、`closes_at`、`available_at`。本窄范围只接受本地常规 09:30 开盘、15:00 收盘时段。可选的 `opening` 是**独立开盘价和规则证据**；没有它就不在该日模拟成交。程序校验实际 SHA-256、日期顺序/重复、上海本地交易日与时段时间、已知时间顺序、价格带/单位/容量，不用事后完整 OHLC 倒推开盘可得性。

固定演示策略版本 `first-buy-second-sell-third-risk-probe-v1`：首日完整日线实际可得后发出 100 股买入提案；第三个有效会话收盘后发出 100 股卖出提案；第四个有效会话后发出明显超资金的买入提案以展示拒单。提案限价使用**该日已可得**收盘价，最早执行时间晚于决策，先由 Risk Kernel 审查，再由原 PR-02 日线引擎在后续会话独立开盘证据下保守撮合。未核验状态的会话不发基于该日收盘的提案；该日 NAV 标为不可用。限价严格穿越、开盘方向、价格带、停牌、容量、订单覆盖全时段的到期条件都沿用 v3 模型。`simulated_at` 是收盘证据取得后的入账时间，**不是交易所成交时刻**。

任何自填 `historical_replay` 数据的可得时间与来源仍只是输入方声明，报表固定标记 `exploratory_historical_replay_not_pit_verified`。本 PR 没有授权、许可和真实历史逐时点可得性已被独立核验的数据包；**不能把随仓合成结果当作真实历史表现，也不能据此晋升或宣称策略盈利。** 数据缺口字段 `unobserved_calendar_days_including_weekends` 包含周末，没有外部交易日历，不宣称是缺失交易日数。

## 实际导出与金额核对

本机用上述冻结样例运行产生了[完整报告 JSON](evidence/m0-pr03/sample-report/report.json)、[逐事件命令和状态摘要](evidence/m0-pr03/sample-report/events.json)、[每日净值/资金/持仓 CSV](evidence/m0-pr03/sample-report/daily.csv)、[订单及拒单 CSV](evidence/m0-pr03/sample-report/orders.csv)、[实际模拟成交和费用 CSV](evidence/m0-pr03/sample-report/fills.csv)、[末期持仓 CSV](evidence/m0-pr03/sample-report/positions.csv)。金额均为**人民币整数分**，收益及回撤为整数基点；负数 P&L 是损失。

| 样例结果 | 数值 |
| --- | ---: |
| 初始/末期 NAV | 1,000,000 / 992,893 分 |
| 末期现金/持仓/未完成订单 | 992,893 分 / 0 股 / 0 |
| 两笔模拟成交 | 次日 100 股买入 1,000 分；后续 100 股卖出 930 分 |
| 买入/卖出实付模拟费用 | 31 / 76 分，共 107 分 |
| 已实现/未实现 P&L | -7,107 / 0 分 |
| 累计回报/按每日观察计算的最大回撤 | -71 / 71 基点（向零截断） |
| 风控拒单 | 10,000 股买入资金不足 |

净值可复算：`1,000,000 - 100×1,000 - 31 + 100×930 - 76 = 992,893` 分。买入成本 `100,031` 分，卖出净收入 `92,924` 分，已实现 P&L `-7,107` 分。持仓期间未实现 P&L 基于真实**模拟成交**的成本，以 FIFO 消耗且对部分批次按整数分分配；成本不能从现价猜算。若缺可信估值则输出 `null`/空 CSV，不写 0。PR-02 v3 账本已保存全部模拟成交、数量、价格和费用，本 PR 从经过 v3 摘要校验的事件重建成本基础，**不改变 v3 存储 schema、事件或摘要语义**。旧 v1/v2 账本继续由现有打开路径拒绝，不做静默迁移。报告自身为 schema v1，带固定策略说明文本 SHA-256、配置 SHA-256 与账本尾摘要；策略说明哈希不冒充源码签名或独立资格验证。

现金基准仅比较不交易的初始本金。简单买入持有基准只在首笔**模拟买入已发生**时，按相同入场股数/价格/买入费持有到末期收盘；不估算离场费用，不称为独立可执行基准或超额 alpha。有外部出入金时累计收益基点不计算；流量单列，不能当投资收益。样例无外部流量或公司行为。若未来输入包含除权、分红或初始持仓成本缺失，本窄范围契约不能准确归因，应先扩大账本语义并重新验收，不能在报表层补造利润。
