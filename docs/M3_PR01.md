# M3-PR01：全市场 A 股 EOD 与可信覆盖快照

Issue [#82](https://github.com/handFOOLed/Stratide/issues/82)，基线 main `013ff2b`。P1 数据正确性变更；单个 Draft，开发者不 Ready/merge。

证券目录、采集和覆盖门禁已实现。真实全市场覆盖及当前账户接口权限尚未实测；开发测试使用合成 HTTP，不读取凭据，不调用真实 Tushare、DeepSeek 或 TimesFM，不生成订单、持仓或 Paper 成交。Risk/Ledger 和安装包不变。

**PR #86 R1：** 目录范围与目录内行情覆盖率分开准入。三家交易所必须各有非空 A 股 `L` 范围；对比前一版目录，先前 L/P 身份无当前状态记录而消失时保留为 `CATALOG_MISSING`，明确阻断。正常新增、显式退市或状态变化不按缺失处理，不写死证券数量。`catalog_state/catalog_scopes` 独立记录范围证据；即使 `market_coverage_bps=10000`，目录未核验也不能 READY 或进入研究。Dashboard 同时显示目录范围与“目录内”行情比例。

## 复用关系

```text
eod-operator.py market once/watch
  → historical_warehouse：原 HTTPS / raw SHA / attempts / 限流 / writer.lock
  → historical_sidecar：原补充源字段与解析
  → 同一个 warehouse.sqlite：原 day_versions / daily_rows + market_* 元数据表
  → MarketDaySnapshot
      → TimesFM history.market_day：只读源门禁，不触发模型
      → CLI report / Dashboard 研究档案：只读状态与覆盖数量
```

原单证券 Operator、旧历史 V1/V2 和冻结任务不迁移、不重跑。新增增量实例使用既有仓库格式和实现；原生日线版本继续保留历史仓库的 ex-post 合同，当前接收时点和证券池版本由新增 manifest 表达，不把旧历史升级为 PIT。

## 本机操作

默认路径是 Git common root 下 `state/historical-warehouse/market-eod`，同仓库的 worktree 共用单写者和请求日志。`--root` 可显式选择另一个本地实例；Dashboard 读取默认实例。新实例默认关闭，前台运行，不安装服务或计划任务。

```powershell
python -B scripts/eod-operator.py market init --start-date 20261104
python -B scripts/eod-operator.py market enable
python -B scripts/eod-operator.py market once
# 或持续前台运行；关闭/休眠期间不伪造观察
python -B scripts/eod-operator.py market watch

python -B scripts/eod-operator.py market status
python -B scripts/eod-operator.py market report
python -B scripts/eod-operator.py market verify
python -B scripts/eod-operator.py market disable
```

`init` 支持 `--start-at 16:10 --cutoff 18:00 --rpm 10 --min-coverage-bps 10000`。时间均为上海时间，正式起点必须不早于 16:00；默认要求 100% 行情或有源记录的全天停牌解释覆盖。阈值只控制研究源选择，不授予交易资格。交易日历由 SSE/SZSE 的 `trade_cal` 完整返回且相互一致确认，BSE 采用官方说明的参考日历，不虚构独立 BSE 日历接口。休市日不拉证券目录、日线或补充行情。

Token 复用原 `STRATIDE_TUSHARE_TOKEN` 环境或仓库级 Windows Credential Manager。已有 Tushare MCP 配置可显式指定 `once/watch --credential-source existing-tushare-mcp-config`，沿用原仓库的本机只读凭据函数。SDK 非依赖；实现复用原 HTTPS 客户端。凭据不进入参数、日志、SQLite、网页或安装包；不读取旧明文 Token 文档。只使用已有个人账户权限，不升级积分或购买服务。

## 证券池、接口与截断

- 每个实际采集日期刷新一次完整目录版本：SSE/SZSE/BSE × `L/D/P/G/UN`；保存名称、代码、交易所、上市/退市日和来源请求。已退市证券保留，B 股从 A 股视图排除但保留计数和原始响应。旧身份或 BSE 仍保留在覆盖表并标为 `UNSUPPORTED`，不会进入研究准入。
- 普通日使用 `daily(trade_date=...)`、`adj_factor`、`daily_basic` 各一个批量请求；`suspend_d` 与旧 sidecar 一致，分别显式请求 `suspend_type=S/R`，分块也保留原类型。两类成功响应（允许空事件表）及参数/SHA 均绑定快照，缺任一类的成功证据不能标记停复牌源合格。保留原字段/单位与未复权价格，不把 `pre_close` 当普通历史收盘，不把 `daily.open` 当 T+1 开盘时实收价格。
- `daily/stock_basic/daily_basic` 的 6000 行、`suspend_d` 的 5000 行按原始返回数量判定，不能先去重再绕过上限。`daily/suspend_d` 触顶时使用文档支持的多代码分块（每组 200），并与首个响应逐行核对；缺少目录外证券、分块冲突或目录本身触顶均不能宣称全市场完整。`adj_factor` 无文档数值上限，不捏造 6000 截断规则，按证券实际覆盖核对。
- 缺行不等于停牌；日内停牌不能替代缺失的全天行情。`suspend_d` 明确 S 且无日内时段的记录可解释停牌缺行，全部 S 记录都排除研究选样。空停牌表不证明可交易。
- 行情与复权因子、停牌源是本模块研究门禁必需输入。`daily_basic` 是补充核对源；权限不足、截断、缺行均独立显示，不补造指标，也不声明该接口完整。上市当日需后续上下文，不进入选样。缺失上市区间、无效 OHLC、零成交量、未知代码或来源冲突按明确原因拒绝。

本次核对的官方来源：[证券目录](https://tushare.pro/document/2?doc_id=25)、[交易日历](https://tushare.pro/document/2?doc_id=26)、[日线](https://tushare.pro/document/2?doc_id=27)、[每日指标](https://tushare.pro/document/2?doc_id=32)、[停复牌](https://tushare.pro/document/2?doc_id=214)、[复权因子](https://tushare.pro/document/2?doc_id=28)。账户可用性以实际响应为准，不从文档积分要求推断已获权限。

## 快照与失败恢复

`MarketDaySnapshot` 按源日追加版本，绑定目录 SHA、原始响应 SHA、请求元数据 SHA、原生日线版本、规则参考文件 SHA、实际接收/可用时间和拒绝原因。`received_at` 来自实际下载；`available_at` 不早于快照实际建立时间，跨日恢复标为晚到。今日目录始终标记 `CURRENT_DATED_CATALOG_NOT_HISTORICAL_PIT`。

全目录分类总数可解释；已知候选分母 `expected_market` 包括活跃但不支持的 BSE，以及目录异常消失时保留的已知身份。首次某家交易所范围为空时不虚构证券数量，`catalog_scopes` 保留该交易所的 `NOT_VERIFIED` 缺口，`market_denominator_verified=false`。`market_coverage_bps` 仅表示目录内行情/停牌解释覆盖；目录范围与该比例必须同时通过。`actual_quoted` 与已解释覆盖分别显示；研究分母、市场门禁前合格数、最终 `eligible_symbols` 分开保存。目录、市场阈值或必需源不合格时，最终选样为空。规则记录仅引用已有身份/合约实现，不声称已验证全市场交易规则、费用或公司行为。

R1 前未保存目录范围证据的缓存/冻结快照返回 `CATALOG_SCOPE_NOT_VERIFIED`，不重新签署或改写其源证据。此前未进行真实全市场采集，本次也不迁移或重写既有真实库。

复用原 OS writer lock、WAL/FULL 事务、SENDING→未知结果恢复、不可覆盖的 raw 文件和请求 journal。一次调用至多 90 个新请求；每个 API/参数作用域每天至多 3 次，失败或不完整响应的再次取数至少间隔 300 秒，并尊重 `Retry-After`。权限/认证不足不自动重试；限频等待会越过截止时直接停止。watch 每 30 秒检查状态，冷却期间不发请求，避免重启产生请求风暴。

READY 源日冻结后不重新请求；崩溃发生在源提交后、快照建立前，可从已保存源恢复，不重新发送已提交请求。较早交易日有缺口时，后续交易日可继续有界补齐；不改已冻结日期。请求中途强杀留下未知状态，按原日志冷却后有界重取只读市场接口，不复用虚构响应。单写者锁是本机排他，不是跨主机协议。

`history.market_day(root, date, symbols, as_of)` 核对完整性、选样、SHA 和当时可用时间后才返回本地源；不运行模型，不把证券池完整等同于 TimesFM 上下文充分、PIT 或交易资格。原历史 source gate 保留既有约束。
