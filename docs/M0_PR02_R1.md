## 根因和修复

1. 原 `Match` 先写入完整日线的收盘标记并观察锁，再决定该日成交，导致收盘才可知的损失反过来筛选当日结果。现在采用版本化的两阶段模型：**独立开盘证据 → 开盘时点的最新权威账本再风控 → 模型成交及费用观察 → 收盘 NAV／财务锁观察**。只改变收盘价，不改变同日模型成交资格；开盘已知损失仍可阻止买入。
2. 原 `sessions` 无条件记录失败行情，且失败尝试将账户时间推进到收盘，阻止后续补数。现在缺失／未核验／不适用的整段行情只记录原因，不改变账户经济时点或消费会话；重启后可用新事件 ID 补入有效行情。已经有效结算的会话仍拒绝再次消费，即便换事件 ID；失败事件的同 ID 重试仍为无操作。

失败尝试保留账户上次可信 NAV 及其原 `as_of`，不声称它是缺行情时段的当前净值。后续提案仍须在当前时间通过原有快照／估值时效检查，没有延长有效期。

## 输入与模型边界

`Command::Match` 新增可选 `opening: OpeningEvidence`，包含全账户 `PositionMark` 和该证券开盘时已可得的 `TradingRules`。引擎不由 `DailyBar.open` 生成早于日线 `available_at` 的事实；缺开盘输入、未来／陈旧标记、缺全账户估值或不相容规则均不模拟成交。完整日线有效时，其收盘价仍独立进入 NAV 观察并持久化锁。

`synthetic::session` 是人工测试输入生成器，本轮给它明确增加了人工开盘标记和规则。Terra 两个探针的函数体保留；它们现在使用该扩展的 synthetic 输入契约。**这不等于仅凭旧 OHLC 输入就证明开盘成交**：另有回归专门检查省略或延迟开盘证据时零新增成交。

模型继续要求先前交易日接受提案、决策／最早执行不晚于开盘、严格限价穿越、开盘不利跳空拒绝、显式容量共享和整手／T+1 规则。完整日线用于保守的可模拟条件，不能证明真实盘中排队或必然成交；没有从日线推断止损与限价先后顺序。`Fill` 同时保存 `risk_checked_at`（模型开盘风控时间）、`simulated_at`（收盘后入账时间）、开盘输入和完整日线。订单在模型开盘已到期则不成交；模型成交后的剩余部分在期满时释放。

如果已有晚于开盘的经济观察提交，本轮不回溯撤销财务锁或重做过去成交，记录无法回溯的原因。缺开盘输入时已持久观察了收盘，也不允许随后补开盘输入来改写该日结果。这是明确的保守边界。

SQLite `user_version` 和摘要域升为 **2**。旧版 v1 账本明确拒绝打开、不迁移、不重新初始化、不改写金额／持仓／订单／锁。测试检查版本拒绝前后 DB 字节不变。新演示必须使用新目录与显式授权本金，不将新账户冒充旧账户续算；自动迁移不在本次修复范围。
