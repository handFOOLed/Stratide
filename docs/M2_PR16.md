## 完整路径与默认状态

```text
显式 init --source recorded_cloud / 已有隔离 TST Owner AgentDir
 → 同一 Owner 配置、authority_id、原 agent.sqlite
 → 冻结开发摘要 / 模型和价格 / prompt、parser、代码、源版本
 → 原 Store::create_for_model 持久任务
 → 原 Agent::tick_task 精确领取 task ID + trigger
 → 原日/月 Budget reserve → dispatch 门禁 → recorded / libtest loopback
 → 原 usage settlement 或 OUTCOME_UNKNOWN 原额保留
 → 结果与来源 SHA → PR15 parse_proposal / research-ast-v1
 → PR15 评价前冻结 / PR62 多候选一次按日读取、三成本和同源基准
 → 拒绝 / 失败 / 部分成功 / 成功归档、开发段反馈、只读 report / verify
```

`deterministic`、`recorded_cloud`、`authorized_cloud` 是显式、不同来源。默认仍为 PR15 确定性提案；没有静默调用、补足候选、fallback 或覆盖旧实验。`authorized_cloud` 在本期始终返回 `AUTHORIZED_CLOUD_BLOCKED_OWNER_PROVIDER_DATA_PERMISSION_REQUIRED`，在凭据读取、DNS 和外部网络前拒绝。模型名 `recorded-structured-fixture-v1` 只描述合成录制材料，不能证明真实模型能力。

保持 `data_mode=historical_backfill_ex_post`、`classification=EXPLORATORY`、`historical_pit_status=NOT_VERIFIED`、`forward_research_readiness=BLOCKED`、`eligibility=ELIGIBILITY_DENIED`、`paper_allowed=false`、`live_allowed=false`。2024–2026 已曝光，模型训练知识未知，不能当新盲测。收益是 PR62 无量纲分数暴露指数，不是账户 NAV 或交易准入。

## 一个 Owner 和一份收费权威

桥接不初始化 Owner 钱包。`bind` 必须找到既有原 Agent schema、AgentDir、配置和原 authority；`risk_binding::bind_at/read_at` 复用原 Binding 校验，原 PR56 默认入口仍使用原位置。不同实验的绑定文件只是同一数据库的引用，不是新账户或费用库。原默认模型、日/月额度、币种、时区和历史费用保持原值。

开发录制用原 `stratided --agent-init-fake <新隔离目录>` **显式**初始化 TST 测试 Owner，然后 `--configure-recorded` 只向该配置添加 `structured-recorded` 模型。真实 Owner 或非 TST 配置不被转换成测试币种。不提供新的付费队列、Python HTTP、费用计算或自动加额。

新 purpose/scope 为 `cloud_structured_research_v1`。要求精确 receiver、purpose、scope、字段白名单、版本化模型/价格、max tokens、未撤销 Grant 和原预算。原 `paper_research_v1`、PR52 local-fake、PR56 的 Grant 无权升级成此 scope，即使手工补一个 scope 名也拒绝。

每轮只有一个持久 trigger，重复 `once` 读取同一个任务。原 Agent 锁、精确领取、原共享预算事务和日/月跨期未决额度继续生效。最终 dispatch 前重查当前 Grant、配置、预算、实验暂停/取消。确认未 dispatch 的中断记 `no_charge`；暂停后的显式恢复只可重用原安全重试路径。dispatch 后超时、崩溃、响应/用量未知保持 `outcome_uncertain / OUTCOME_UNKNOWN` 和原预留，重复执行不重发、不自动清锁。已完成任务在后续研究恢复时只读消费。

## 有界输入与结构化输出

传输仅消费五个字段：`response_source`、`research_boundary`、`development_summary`、`grammar`、`output_contract`。

- `research_boundary` 冻结数据版本/源 SHA、开发/验证/已曝光评价窗口、原三成本、持仓/候选限制、训练知识未知和 ex-post 标签。完整计划包含大量旧源收据；原任务绑定的是其小型 `cloud/boundary.json` 投影和 SHA，不再次读取全部旧收据。
- 本 Issue 的开发摘要明确为 `synthetic_test`：零观测的合成 coverage/schema，不从真实数据提取或外发统计量。第二轮仅接受 PR15 已生成的开发段 `role/reduce_exposure/evaluated/failed_or_negative`；验证/评价期指标、全结果和 provenance hash 不作为反馈选择输入。recorded 响应不会根据收益自调生成。
- 输入不含逐股票序列、原 Tushare 行、持仓、账户本金、密钥、原库 locator 或本机绝对路径。内部任务 Context 的路径只用于可信本机冻结/控制，不进入请求体。
- 冻结原配置的 max input/output token；请求按字节加协议余量作保守输入界，wire ≤64 KiB，模型 content ≤48 KiB。默认每轮最多 4 候选、上限 8，AST 深度 8 / 节点 48 / 窗口 60 / lag=1。原资源限制和最多两轮保持。

`research/structured-grammar-v1.json` 是 Rust/Python 共用的提示 schema，列出每种节点字段、单位和类型；唯一 AST 行为权威仍为 PR15 `autonomous_dsl.validate`。不编译或运行模型代码。

响应严格为 `cloud-structured-response-v1 {source,candidates,refusal}`。每候选复用 `structured-research-proposal-v1`，增加短 `constraints` 和 `counterexample`；source 必须匹配可信 task_ref、plan/model/prompt/parser/adapter SHA。`authority=RESEARCH_ONLY` 只是必须满足的标签，不授予任何执行权限。反序列化拒绝重复 key、非有限值、未知字段、未来特征、错误单位/股票/日期字段、交易/预算权限、命令/脚本/URL、代码混入、伪造 source 和注入指令。没有正则提取或文本修复。

合法与非法候选可在一轮并存；少于 4 个明确报告 PARTIAL，全拒绝或拒答明确归档。模型用量已知但 AST/内层 JSON 非法仍保留真实测试结算与拒绝；wire/用量未知则保留未知预留。不会为凑 4 个候选放宽规则，也不会把确定性 baseline 冒充云提案。

每轮 `cloud/` 保存输入、录制 wire、Context 和原任务/结果 SHA 收据；PR15 round archive 保存候选与该收据的冻结引用。`verify` 只读核对原 SQLite 的任务/结果/调用、冻结 SHA、AST 准入、研究日账和 post-seal 规则；阻断/等待/未知状态也有只读待处理收据。原 PR15 seed63/两轮/8 AST/旧 archive 不改写。

## 本机运行

Windows 使用已有 MSVC，不安装工具链：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/with-msvc.ps1 build --locked -p stratide-research --bin structured-research-agent
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/with-msvc.ps1 build --locked -p stratided --bin stratided
$env:TEMP = Join-Path $PWD 'state/rust-temp'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/with-msvc.ps1 test --locked -p stratide-research --lib structured_tests -- --test-threads=1
python -I -B scripts/test-cloud-structured.py
```

可执行的合成演示会显式创建 disposable TST Owner、PR62 V1/V2 fixture、四个录制 AST，跑 libtest loopback → 原预算 → 原评测 → CLI 只读命令及重复 once：

```powershell
python -I -B scripts/run-cloud-structured-evidence.py --tag my-synthetic-demo
```

该脚本是开发证据生成器，不是后台研究服务。loopback/fault/clock 控制仅编译在 Rust libtest；安装用的 `structured-research-agent` 无这些环境开关。真实模型调用和外发为 0。

普通 recorded 操作复用原 CLI，需要**已有** TST Agent、显式数据根/版本和新实验目录。第一次 init 后先查看 `cloud/round-01/request.json`，按该 source 制作/审核本机合成录制 wire；响应只从显式文件冻结，后续不能替换：

```powershell
python -I -B scripts/autonomous-research.py init --source recorded_cloud --agent-dir '<EXISTING_TST_AGENT>' --configure-recorded --v1-root '<V1_ROOT>' --v2-root '<V2_ROOT>' --v1-version 1212 --v2-version 4848 --out state/autonomous-research/<new-experiment> --authorize-local
python -I -B scripts/autonomous-research.py once --out state/autonomous-research/<new-experiment> --recording '<SYNTHETIC_RECORDING_JSON>'
python -I -B scripts/autonomous-research.py status --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py history --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py report --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py verify --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py pause --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py resume --out state/autonomous-research/<new-experiment>
python -I -B scripts/autonomous-research.py cancel --out state/autonomous-research/<new-experiment>
```

第二轮需第一轮封存后显式提供新的录制文件，仍受原账户累计费用和候选上限约束。只跑一轮可在 `--config` 中设 `{"limits":{"rounds":1}}`。`status/history/report/verify` 不打开原行情库、不启动 Agent、不恢复费用、不发 HTTP。
