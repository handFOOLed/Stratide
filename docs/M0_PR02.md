# M0-PR02：持久 Paper Ledger 与保守模拟成交

状态：**Sol 开发／自测交付，等待 Terra 独立验收与小猫代码审查；Sol 不合并。**

任务：[Issue #3](https://github.com/handFOOLed/Stratide/issues/3)。开发基线：`98317a9f1cd7e265c2085e5ff24f76cf3cd274aa`（获取时最新 `main`，包含已合并 PR-01）。约束依据为 AGENTS、模拟交易路线图及 ADR-002/003/004/007/008/017/018/019/037。

本轮按 **P0** 处理现金、持仓、财务锁、幂等与数据时序。只支持一个 paper 账户／策略组，未实现实盘券商、行情抓取、研究 Agent、GUI 或后台编排。`stratided` 仍是占位；CLI 在本进程调用可信 Rust Risk / Ledger 模块。

## 运行

需 Rust stable 与 C/C++ 工具链（SQLite 随 crate 编译）。Windows 如未打开 VS Developer PowerShell，可用 `./scripts/with-msvc.ps1` 替代下面的 `cargo`。该脚本仅加载已安装 MSVC 到当前进程；不安装软件、不修改系统 PATH。

在仓库根目录执行，每条 CLI 命令都是独立进程：

```powershell
cargo build --workspace --locked
New-Item -ItemType Directory -Force state | Out-Null
cargo run --locked -p stratide-cli -- paper-create state/paper-demo --initial-cash-fen 1000000 --max-order-fen 500000 --account-cap-fen 800000 --strategy-cap-fen 500000 --daily-loss-fen 100000 --drawdown-fen 200000
cargo run --locked -p stratide-cli -- paper-submit-synthetic state/paper-demo
cargo run --locked -p stratide-cli -- paper-match-synthetic state/paper-demo
cargo run --locked -p stratide-cli -- paper-status state/paper-demo
# 相同事件重试：应返回原结果，不再扣款、预留或收费。
cargo run --locked -p stratide-cli -- paper-submit-synthetic state/paper-demo
cargo run --locked -p stratide-cli -- paper-match-synthetic state/paper-demo
```

`paper-create` 要求目录不存在，不能覆盖已有或初始化中断的目录。再次演示须显式选另一个目录；不要为重跑而删除权威账本。`paper-status`／`paper-apply` 只打开已有账本，没有“打开失败就创建”路径。

固定样例：2026-10-28 收盘后提交 100 股、限价 1,000 分的人工提案；下一模拟交易日的人工 OHLC 为 1,000 / 1,050 / 950 / 1,000 分，成交能力假设为 100 股。初始现金 1,000,000 分，预留 100,200 分。模拟成交后现金 **899,969 分**、持仓 **100 股**、实际费用 **31 分**、NAV **999,969 分**，预留归零。这里的日期、证券示例、价格、容量和费率都是 **`synthetic_test`**；没有抓取真实市场数据。

实际 CLI 生成的 [完整状态 JSON](evidence/m0-pr02/sample-state.json)、[进程退出／恢复／重试记录](evidence/m0-pr02/cli-smoke.txt) 和 [测试输出](evidence/m0-pr02/test.txt) 一起提交，便于 Terra 对照复算；它们属于 Sol 自测证据。

可信本地管理／测试可使用：

```powershell
cargo run --locked -p stratide-cli -- paper-apply state/paper-demo <唯一事件ID> <可信命令JSON文件>
```

JSON 使用 `stratide_ledger::Command` 的 Serde 格式，支持 `Observe`、`Submit`、`Match`、`Freeze`。集成测试 `apps/stratide-cli/tests/paper_ledger.rs` 给出生成范例。这是有本机账本权限的可信调用入口，**不是 Worker API、安全沙箱或对不可信文件的授权协议**。无风险配置改写、换策略身份或解锁命令。外部现金流仅可由可信 Owner 事件提供，不能超过初始授权本金，也不能消耗已预留资金。

## 权威状态与原子边界

```text
可信命令 + 唯一事件 ID
  -> 获取本机 writer.lock，并持有到 Ledger 关闭
  -> SQLite BEGIN IMMEDIATE
  -> 私有草稿：当前账本观察 NAV -> RiskKernel::review -> 原子预留 / 模拟成交
  -> 校验现金、整数持仓、费用与全部未完成订单预留
  -> 追加事件与完整结果状态的 SHA-256 链，更新提交尾标
  -> COMMIT 后才替换进程内权威状态
```

- `crates/risk` 保留唯一提案审查入口；`crates/ledger` 管理执行、会计和持久化。`Approval` 不授予外部花钱权限，执行器只接收提案，不能消费旧 Approval 绕过最新状态。
- 单写入者以**同一权威账本目录**为单位；规范化路径、OS 文件锁及 SQLite exclusive locking 共同约束本机实例。锁文件保留，进程终止后 OS 释放锁；不靠删除锁文件或猜 PID 恢复。复制账本目录不是账户权限迁移；没有跨主机互斥保证。
- SQLite 使用 rollback journal（DELETE）和 `synchronous=FULL`。事件与尾标同事务提交。不存在独立落盘后再补扣钱／再补加股份的窗口。
- 恢复检查 SQLite 完整性、格式版本、genesis、本金与配置、连续事件序列、全部状态摘要、独立提交尾标；重新运行确定性 reducer，并校验资金与持仓守恒。不自动初始化损坏、空、缺失或旧版账本。
- 相同事件 ID／相同命令为无操作；不同内容使用同 ID 明确报冲突。相同订单 ID／完整相同提案也不能重复预留；改证券、价格、数量、方向、时间或身份不能复用 ID。一个证券／交易日的撮合会话只消费一次，换事件 ID 不能复用当天流动性。
- 存储写入或 commit 出现不确定错误后，该句柄停止后续提交；须关闭并恢复 SQLite 权威结果。恢复本身不会重新执行经济动作，只从已提交事件重建状态。
- 这是可信本地账本的完整性校验，不是防本机恶意管理员篡改的外部公证。完整数据库连同尾标一起被回退为旧副本，仍需外部备份／版本管理辨识；本轮不实现防恶意回滚设施。

## 财务与风控

账户本金、交易金额与费用均为非负 `i64` 整数分，股数为整数，关键加乘及资金变动检查溢出；反序列化也拒绝负金额。所有同步策略测试共用一个现金／持仓／挂单账本。

买单预留原限价乘剩余股数加费用上界；卖单预留可卖股份、禁止净支出卖单。卖出按已入账批次顺序消耗可卖持仓，T+1 仅在明确配置的证券规则下生效。当天新买入不会被另一份旧快照重复出售。未成交、部分成交的剩余预留继续有效，到期才释放；到期是明确模拟生命周期，不把存储错误或订单未知状态当成“未成交”。

`Observe` 不需要策略提案，每次可信标记更新都会观察账户权益。提交拒单、撮合未成交和成交后费用变化也会观察并在事件提交中保存高水位、日初基准、外部流量和账户／策略财务锁。缺价显示 `equity: null` 和原因，不填零；估值恢复只恢复可估值性，不解除财务锁。切换交易日以先前可信 NAV 建立新日初基准，锁不清除；前一状态估值未知时拒绝重置基准，须先提供可验证的估值。没有自动解锁或强制清仓。单笔模拟会计失败会回滚该笔资金／股数变动，保留已观察 NAV／财务锁，并持久化人工检查冻结和原因。

费用配置包含证券、版本、来源、有效交易日起止、佣金 ppm／最低佣金、过户费 ppm、卖出税 ppm。每项按分向上取整，每次部分成交分别计最低佣金，成交证据记录分项实际费用。**内置 300ppm／最低 1 分／过户 10ppm／卖出税 500ppm 均是人工测试参数，不是核验后的现行 A 股费率。**

`CostEstimate` 绑定完整提案、完整市场规则、有效截止时间和版本来源。执行上界由冻结费率计算，再次风控时重新绑定最新规则。上界以最坏“每股分别收费”计算，卖出还使用当前价格带上界；这是有意偏严的简单预留，会高估有最低佣金时的占款。实际扣费只记真实发生的模拟成交费用，剩余上界不能转成虚构费用；费率过期或上界不足保持未成交。

## 日线撮合假设与时间

- 数据模式为 `synthetic_test` 或 `historical_replay`，来源版本／数据集标识、`Asia/Shanghai`、未复权人民币整数分语义必须明确。每次提交的原始行情／规则随不可改写事件保留；输入摘要与结果状态参与摘要链。
- 内置 `dataset_hash` 是固定人工数据**生成配方**的 SHA-256；具体每条输入由事件摘要覆盖。它不是第三方数据集核验。历史模式只有显式输入契约，本轮没有历史 CSV loader 或已验真的真实历史样例。
- `DailyBar` 包含开闭市时间、`available_at`、OHLC、总量、保守容量、规则／停牌核验标记。交易日历、时间戳与日期对应关系、品种规则及历史来源真实性由可信输入方负责；本轮没有外部交易日历或第三方认证器。
- 完整日线只能在 `available_at <= now` 后消费，提案决策和最早执行时间须早于该 session 开盘，接受日期须严格早于该交易日。当天收盘信号绝不以当天收盘价回填。
- 仅原限价严格处于当日高低价和价格带内，且开盘没有朝不利方向越过限价时，使用原限价作保守模拟；只有触价、停牌、一字板、过期、缺证据、未来或陈旧行情保持未成交／到期。无开盘价改善，不推断日内先后路径。有效但不能成交的一字板／停牌收盘标记仍进入独立 NAV 观察。
- 由输入方显式指定 `capacity_shares <= volume_shares`，所有订单按接受先后共用容量。可部分成交，但每份数量需满足买卖单位（明确允许的最终零股清仓除外）。不是盘口队列或交易所撮合保证。
- 成交记录的 `simulated_at` 是消费完整日线后的模拟入账时间，不伪造真实交易所成交时刻。策略无法使用未来日线生成先前提案。完整历史策略驱动／回放／绩效报告属于 PR-03。
