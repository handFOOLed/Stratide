## 最小会计方案与明确停止边界

以下是被冻结的缺口设计，**未实现、未通过事件测试**。后续取得事件证据仍须先评估是否能在另行授权的共享财务改动范围内完成。

- 继续用未复权成交价和估值，不把前复权/后复权序列作为真实价格。登记日冻结合资格持股，后续卖出不抹除已确认权益；登记日后买入不补获该次权益。权益数量与买入成交、结算可卖数量分别记录。
- 对已核实的现金分红，在有依据的生效时点确认应收权益；在实际支持的支付时点将应收转为现金，之前不可将未到账款当可用买入现金。税款/递延义务必须有支持口径，未知就 BLOCKED。分红属于投资收益，不是 Owner 外部入金。
- 守恒目标为 `NAV = cash + unadjusted holdings value + verified receivables - liabilities`；到账是资产形式转换，不再次增加收益。不能强制真实市场跨日 NAV 恒等；价格波动、税费仍会改变 NAV。纯合成会计测试才可在固定除息参考价假设下验证等额权益补偿，且不得冒充市场事件。
- 股份类事件若经证据确认，需要记录登记日权益、实际增减股与成本基础、零股/现金补偿和独立可卖日期；不伪造成买卖 fill，不新增本金。未知股份事件直接阻断，不默认用普通买入 T+1 解决。
- 一个事件 ID/修订版本只记一次权益与到账；缺事件、重复冲突或不可确认的修订拒绝。边界开盘撮合前必须处理有效事件和持仓/订单约束；未核实的跨事件挂单不暗改限价、数量或假装成交。

现有实现提供了具体停止理由：

| 现有责任层 | 实际缺口 |
| --- | --- |
| `crates/ledger/src/model.rs` 的 `Command` / `State` | 只有历史开盘、Observe、Submit、Match、Freeze；没有登记日权益、应收、税款或公司行为结算事件 |
| `crates/ledger/src/engine.rs` 的 `nav` / `Observe` / `validate` | NAV 为现金加持仓；现金仅从初始资金、外部流量和成交/费用复算，股数仅从成交复算。直接加分红/股份会破坏原守恒；借 `external_flow_fen` 入账会把投资收益错误视作外部贡献并影响风险基线 |
| `crates/risk` 与 `AccountSnapshot` | 风险使用同一账户估值；在外部 sidecar 另算应收不能纠正核心 NAV/亏损锁或可用资金 |
| `crates/ledger/src/store.rs` | v3 事件/状态参与摘要并在打开时完整重放；新增财务事件不是仅改 Python adapter 即可完成，不应绕过校验或重写旧库 |
| `scripts/research-evaluate.py:verify_accounting` 及六报告 | 独立复算同样只支持成交/费用，且要求本协议外部流量为 0；需与核心一并支持分红收益/应收，不能用第二本账掩盖差异 |

因此按 Issue 第 5 项**停止扩大实现**。未修改共享 Risk Kernel、通用撮合、ledger schema、forward journal 或评价器，没有新账本实现/迁移/格式冒充。即使日后发现支付与除息同日，也不能凭此绕过现有现金与收益守恒模型。
