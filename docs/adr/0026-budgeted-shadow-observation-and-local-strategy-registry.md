# ADR-026：有资源上限的影子观察池与按需本地策略检索

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**方案 B（修订版）**。暂停实盘的策略允许继续影子观察，但不保证所有策略无限期运行；以有上限的存储/计算/检索预算管理观察池，并用本地策略注册表低成本筛选，再按需向云端 Agent 提供有限摘要。
- 关联：[ADR-012](0012-adaptive-research-daily-hard-budget.md) 研究费用闸门、[ADR-021](0021-group-isolation-shared-instrument-attribution.md) 组间数据隔离、[ADR-025](0025-adaptive-risk-budget-decay-quality-gates.md) 策略衰退与质量验证、[ADR-006](0006-independent-validation-isolation.md) 验证证据隔离、[ADR-017](0017-single-writer-durable-recovery.md) 资金相关状态持久化。
- 尚未决定：Owner 的实际磁盘容量与配额、观察池并行数/CPU 限额、数据保留周期、检索条数和单次 Token 上限、归档介质、策略排序与唤醒规则。不得将示例资源额度视为已批准配置。

## 问题

自动研究会积累大量策略版本、实验日志及影子观察记录。若每套策略永久保留全量行情/中间输出，并在研究新策略时把历史库全文输入 LLM，磁盘、CPU、内存、数据源用量和 Token/API 花费会随库规模失控。用户要求既保留必要失败经验又不依赖本地 LLM，且策略组数据不得互相污染。

## 决策

1. **统一公共市场数据、独立私有结果。** 数据管理器按标的、时间、频率、来源与可得时间保存一次可复用的已授权公共行情及快照；策略只引用数据集 ID/版本及自己的实验结果。按 `group_id` 隔离研究成果、私有特征、信号、模型状态和虚拟表现。公共索引不提供跨组私有全文，除非 Owner 授权跨组共享。
2. **分层留存，保护财务安全记录。** 单独维护（a）实际账户订单/成交/持仓/风险/Owner 授权和恢复所必需状态，依一致性、审计与合法保留义务管理；（b）冻结策略工件、版本血缘、独立评估与晋升/熔断的最小可核验证据；（c）可按保留政策压缩、降采样或归档的影子观察明细；（d）可丢弃/重建的缓存与重复行情衍生中间文件。**不能因存储预算而删除唯一的风险/恢复凭证或必要原始评估证据。** 压缩或清理前核实引用、备份完整性及可恢复性；绝不静默删除实际账户关键记录。
3. **预算控制的影子观察池。** 保留有限活动中的影子策略集合，基于观察价值、风险疑点、最近研究使用价值与资源限制进行休眠/轮换。低优先级策略可进入 `dormant` 或 `archived`，保留清晰的证据/版本摘要；它们**不产生未运行期间的连续前向观察证据**，不能事后补写“当时做了哪些真实时间决策”。定期重新评估时须标识观察缺口。已暂停实盘的版本不得因影子表现回升而自动清除财务风险锁或 Owner 否决。
4. **策略注册表先本地检索，LLM 再按需深入。** 使用轻量持久化 `Strategy Registry` 保存稳定的 `family_id`、`artifact_hash`、`deployment_id`、`group_id`、数据输入指纹、策略类别/特征标签、版本血缘、验证状态、失败原因、风险指标、压缩摘要和受控归档定位符。默认本地结构化索引及可选 SQLite FTS5 全文检索与廉价数值相似度计算，**不启用本地 LLM，也不默认建立向量数据库**。哈希一致可定位完全重复工件；不同哈希仍要按证据处理参数微调/相关风险，不能宣称经济独立。
5. **严格控制模型上下文入口。** 可信工具先筛选相关且调用者**有权访问**的少数候选，只传紧凑摘要、文献/试验引用和可验证指标；对完整策略内容执行显式按需展开，并限制单次返回条数、字段、字节/Token、分页深度和重复拉取。不因为注册表有 1 万套策略就把 1 万套描述送给云 LLM。禁止反复分页规避整体检索预算；云端检索/分析仍受 ADR-012 的每日付费研究硬上限和供应商计费不确定性影响。
6. **防止跨组数据泄漏。** 研究 Agent 的查询带明确的授权身份和允许的组别范围，存储/检索网关在返回数据前执行访问控制；公共/全账户统计可以通过可信聚合发布，但其他组私有实验文本、模型参数、信号和日志不能因相似度检索或摘要拼接而泄露。索引不是绕过 ADR-021 的特权。
7. **资源治理优先保护真实交易。** 独立可信 `Storage/Research Resource Governor` 约束活跃影子数、CPU/内存、磁盘数据用量、日志增长和模型检索/API 用量。达到阈值时，依次削减研究缓存、暂停非关键影子/新实验并告警；**不能让磁盘写满后仍继续无法可靠持久化的实盘下单**。为关键账本和事务日志保留空间/容量监测与持久化故障停增仓处理，绝不牺牲 Risk Kernel、未决订单对账及 Owner 控制通路来维持研究任务。
8. **经济性与代码质量评估。** 未来测试要证明：可恢复被保留的工件与必要证据；模拟千/万条元数据时检索结果/Token 数受配置上界控制；索引重建不改变策略资格或风险锁；重复数据/日志不会按策略数量线性复制；影子休眠期不产生伪造绩效；非法组别检索被拒绝；超磁盘预算/磁盘写失败时停止可选研究并安全限制新增真实风险。成本监测区分本地磁盘/CPU、云 Token 和外部数据调用。
9. **限制 M0 范围。** 当前仍以单组单策略、纸面账本/风控闭环为主，不引入影子观察池、全文/向量检索、归档服务、分布式调度器。等到研究 Agent、策略数和真实资源压力出现时，再以 SQLite 元数据和简单清理/检索规则实现最小可测版本。

## 验收摘要

- 只查少量授权策略摘要，不把全集塞入云端上下文；超出记录数、请求深度或预算的检索被拒绝或截断。
- 相同公共行情仅保留可引用的必要版本；跨组私有信号与模型输出默认不可检索。
- 休眠/归档策略不被伪装成持续前向验证；恢复观察时明确数据断档。
- 仓储不足、写入失败、预算超限时先停止非必要研究，真实资金核心拒绝无法可靠持久化的新风险。
- 关键财务状态、Owner veto、冻结版本和必要的风险/资格证据不被自动清理策略误删；保留与备份策略可验证。
- 不保证策略会长期有效，也不保证任何规模扩展都免费；目标是让日常 LLM 上下文和活动计算**由显式配额限制，而非随历史策略库线性增长**。

> ADR-026 是研究资源与数据生命周期的产品/架构决定。Stratide 当前 M0 不具备可用的研究注册表、自动影子策略管理或真实账户保护引擎。
