# ADR-002：同进程独立风控模块与唯一交易出口

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 决策范围：Risk Kernel 与 Execution Engine 的隔离和调用边界
- 不在本 ADR 内：具体熔断数值、风控解锁交互、券商接入、实盘启用

## 背景

Stratide 必须在 Windows 开发机及未来可能的低功耗 macOS/Linux 主机上运行。用户要求工程工作量与真实财务风险相匹配，不为没有明确收益的进程隔离增加通信与恢复复杂度。研究 Agent 和生成策略代码属于不可信环境。

## 决策

1. **Risk Kernel 是独立 Rust 模块，与 Execution Engine 同处可信 `stratided` 核心进程。** 暂不单独部署风险守护进程。
2. 策略（本地或远程）、Agent、Dashboard 只能提交交易提案，不能获得券商密钥、直接调用订单出口或修改生产风控配置。
3. 所有下单路径强制经过统一的 Portfolio → Risk → Execution 流程。Execution Engine 只消费经风险审核、关联对应账户/订单意图且仍有效的内部批准结果；普通提案不具备调用实际下单入口的能力。Rust 模块可见性和受限构造器用于减少误调用，但**同进程不是密码学或操作系统级隔离**。
4. 不可信策略代码绝不加载到受信任核心进程内以任意权限运行；本地计算使用外部隔离 Worker/受限运行时，云端计算只返回验证后的提案。具体策略运行时见 ADR-001 后续实现决策。
5. 熔断、账户状态及关键订单状态应持久化。遇到风控/订单状态不确定时禁止新增风险；对账或按预设规则处理存量仓位。重启不能清除熔断。
6. 最初只实现纸面交易/模拟券商；真实订单功能不得在 M0 中出现。未来实盘前必须审查全部下单入口并进行针对性的 P0 故障测试。
7. 只有出现可信的风险模型、故障证据或券商接口约束，证明进程隔离具有实质收益时，才重新评估独立风控进程。

## 最小验收方向

- 普通策略提案无法直接到达券商适配器；模拟订单必须经过风控。
- 超过仓位/资金约束的订单被拒绝。
- 熔断激活后禁止新增风险，重启后仍保持状态。
- 对普通名称与展示类异常不扩展无关测试矩阵。

## 局限性

同一个 Rust 进程里的核心逻辑错误仍可能绕过预期检查，因此“独立模块”仅表示架构与 API 职责独立，不表示能够从 OS 层隔离核心自身的 Bug；未来实盘必须重点验证订单入口、风控状态和对账。
