# ADR-009：自动策略晋升，Owner 保留随时否决权

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 决策范围：研究策略通过独立验证后进入**已授权实盘范围**的资格与 Owner 否决权
- 方案选择：**以 B（验证通过后自动部署）为开发目标**，但 Owner 可以基于自身原因拒绝/禁用策略
- 尚未决定：具体验证门槛、策略初始资金比例、预部署缓冲期已由 [ADR-010](0010-configurable-deployment-grace-period.md) 确定、Owner 禁用范围与减仓节奏

## 核心区分

本 ADR **不授权 Stratide 当前 M0 自动实盘下单**。未来真实资金功能必须由 Owner 单独启用且先设置账户/本金/仓位/风险上限，交易核心仍需按 ADR-001/002/003/004/008 执行。本 ADR 只确定**在既有实盘授权边界内，新的合格策略不需每次人工逐一批准即可晋升**。

## 决策

1. **默认路线 B：自主晋升。** Agent 自主发现和改进候选；独立 Evaluator 基于可信数据（ADR-005）、验证隔离（ADR-006）、保守且合适的成交评估（ADR-007）以及真实前向模拟证据进行资格判断。正式晋升必须由可信的 Promotion Gate 依据预先确定的规则执行，不能由 Agent 自己修改评估规则或宣布合格。
2. **没有逐策略人工批准这一强制步骤。** 根据 [ADR-010](0010-configurable-deployment-grace-period.md)，在自动部署前默认等待 10 分钟，允许 Owner 在缓冲期取消/否决；截止后仍要重新验证资格与风控。 已启用实盘且设置授权边界后，资格合格、没有禁用记录且符合当前账户风险/资金配置的策略可以被可信核心自动接纳。不得把 Owner 事前逐一确认偷偷设计成唯一入口，以免把 B 变成 C。
3. **Owner 拥有覆盖性的否决/禁用权。** 用户可以基于喜好、主观判断、交易对象、伦理或其他任何理由拒绝候选，或暂停已晋升策略；无需向系统证明“不合格”。否决/禁用状态由可信本地控制接口持久化并审计；Agent 不能自行删除、绕过或通过原样重新提交来规避禁用。是否按策略版本/家族/资产类别进行范围阻断，可在实际产品界面设计阶段最小化确定。
4. **禁用不等于不顾风险立即平仓。** 对已运行策略，禁用应立即阻止新的风险增加；已有订单需核实、撤单必须确认状态，已有仓位的退出依据独立风控、账户状态、适用交易规则（含 T+1/停牌）安全处理。Owner 可选安全减仓/有条件退出，但不得制造重复订单或越过 ADR-003 的未知订单冻结。
5. **自动晋升不得扩大既有授权。** 即使策略再优秀，也不能提高账户本金、风险限额、借贷/杠杆权限、资金可用性或解除熔断；动态资金配置使用共享账本并受 ADR-008 约束。任何扩大风险授权的修改都必须由 Owner 明确批准。
6. **必须有可解释的反馈。** 自动晋升/禁用记录至少能追踪策略版本、评估证据、时间、资金分配和禁用原因（可选）；在 10 分钟默认缓冲期内通知 Owner 并允许撤销，但不把通知回执变为普遍强制审批。用户若预先禁用了某策略，不因新版本或重启自动复活。
7. **无法核实资格则不自动部署。** 持有不合格数据、验证失败、前向证据不足、被 Owner 拒绝、生产依赖不兼容、当前风控冻结，均应保持未晋升状态，而不是向实盘凑足策略数量。
8. **增量开发纪律。** M0 没有真实券商/研究 Agent/自动晋升能力，先做纸面策略授权与 veto 假对象的契约讨论即可；完整 Promotion Gate 在后续单独有明确验收标准的阶段实现。

## P0 验证情景（对应实盘阶段）

- 合格、未否决、受限额约束的策略可以不经逐条人工审批进入已经启用的实盘策略集合。
- Owner 拒绝过的策略（包括规避禁止的相同产物）不允许自动部署；重启之后禁令仍然有效。
- 取消运行策略后立即禁止新增风险，存量仓位不会因自动逻辑盲目重复卖出。
- Agent 无法修改评估结果、风险授权或 Owner 禁用表；无其他已授权范围时绝不自行开启实盘。
- 经评估合格不意味着必然盈利，也不意味着可突破损失熔断。

本 ADR 记录产品方向，**不意味着当前软件可以实盘或已经具备自动晋升**。
