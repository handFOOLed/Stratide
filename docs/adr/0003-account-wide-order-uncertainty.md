# ADR-003：券商订单状态不确定时账户级冻结新增风险

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 决策范围：券商下单超时、未知订单状态及新开仓权限
- 暂未决定：恢复交易时是否需要人工确认、具体探测/重试间隔、券商专有订单标识

## 场景与动机

向券商提交买单后发生超时，系统无法判断券商是否已收到、受理、部分成交或全部成交。此时再发另一个买单可能同样超时，也可能在未知现金占用与仓位基础上扩大风险。异常可能属于账户/连接层而不只是单个标的。

## 决策（方案 B）

1. **对该交易账户立即暂停所有新增风险的订单**，包括其他股票、其他策略和后续开仓；不是只冻结原标的。
2. 把原订单设为待核对（`UNKNOWN / RECONCILIATION_REQUIRED`），持久化订单意图、提交时间与已知请求标识，并保留提交前后可用的证据。**超时不是失败或未成交证明。**
3. 不盲目重发该订单或发送新的增仓单。若券商支持请求幂等键、客户订单号或查询接口，按实际适配器能力使用；具体实现待券商选型。
4. 恢复交易前，应通过可信的券商订单、成交、现金、可用资金及持仓信息对账，确保未知订单和账户风险敞口均已厘清；未恢复连接不能假定可继续交易。
5. 已有仓位不会因为冻结新开仓自动清仓。必要的撤单、风险减仓与存量持仓管理只能在真实状态足够明确、相应操作获风控许可时执行，不得制造重复订单。
6. 冻结标志与关键未知订单状态跨进程重启持久有效；研究 Agent 和 Web Dashboard 不可绕过。
7. 网络/券商异常时避免无限高速重试：以有界查询与退避为原则，并通知所有者。具体间隔、停止条件与人工介入机制留待后续设计。

## 为什么选择账户级而不是单标的冻结？

- 订单是否成交会影响账户共享现金、仓位及风险预算。
- 后续订单可能同样超时；尝试更多订单会累积状态不确定性。
- 对约 10 万元的个人账户，暂时错过机会通常优于在未知资金状态下持续开仓。
- 简化恢复逻辑，避免为极少的并行交易收益引入账户资金预留与复杂冻结管理。

## 有意义的测试（实现券商适配器时）

1. 券商已接受订单但响应超时：账户暂停所有新开仓，不再直接重发。
2. 冻结期间其他标的/策略提交新开仓意图：被拒绝。
3. 程序重启：未知订单与账户级冻结保持不变。
4. 查询/对账成功：能确认实际成交和账户状态，但**是否自动解锁**留待下一项决策。

本 ADR 规定控制规则，不声称当前 M0 骨架已实现下单或恢复机制。
