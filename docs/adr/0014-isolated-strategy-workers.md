# ADR-014：独立策略 Worker 执行（本地或远程），不强制 WASM

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 决策：**方案 A — 独立策略 Worker**；本地受限子进程与隔离远程 Worker 均可执行，统一向本地交易核心提交标准化提案
- 关联：[ADR-001](0001-hybrid-strategy-execution.md) 混合策略执行、[ADR-002](0002-in-process-risk-gateway.md) 本地强制风控
- 尚未决定：具体 OS 沙箱方案、标准提案结构和认证手段、Worker 工件打包与依赖锁定细节。**生产 Worker 网络策略已由 [ADR-015](0015-automatic-data-manager-network-isolation.md) 决定：默认禁用任意外网访问，通过可信 Data Manager 获取数据。**

## 问题

策略探索可能生成 Python / NumPy / PyTorch 或其他语言/依赖代码；强制将每种模型封装为 WASM 会显著限制研究灵活性。另一方面，AI 生成代码不得以任何形式直接在持有券商授权和交易状态的受信任 Rust 核心中加载。

## 决策

1. **执行隔离：** 不可信策略代码在独立 Worker 执行；本地轻量策略使用进程隔离的受限运行环境，复杂或资源密集策略可在远端隔离环境执行。Rust 核心进程 `stratided` 不动态加载或执行 Agent 生成代码；研究编排器也不因会启动 Worker 而获得交易权限。
2. **统一交易提案协议：** Worker 只提交带有策略 ID、不可变版本、输入时间/依据与有效期等可验证元信息的策略提案，由受信任核心按 Portfolio → Risk Kernel → Execution 通路决定是否产生订单。Worker 不持有券商凭据、下单通道、风险配置写权限或生产账本写权限；直接访问 Broker Adapter 必须被拒绝。
3. **自由生态：** 默认允许策略在受限 Worker 内使用实际需要的 Python、科学计算或 ML 库，不要求全部改写成 Rust/WASM。WASM 可以作为未来可选执行技术，但**不是平台必选工件格式**。
4. **进程隔离不等于沙箱：** 启动子进程本身无法阻止文件、环境变量、网络、进程、内存与账户凭据的非预期访问。实现阶段必须为不同 OS 寻找可验证的最小隔离配置（尤其是 Windows 与可能的 macOS ARM64/Linux）；无法兑现约束时不得让不可信代码与资金/券商权限共存，可改在远程隔离环境执行或拒绝该工作负载。
5. **资源限制与失效：** Worker 应有可审计的执行来源、固定工件/依赖版本、受控输入、任务超时、CPU/内存/进程数量限制以及异常退出处理。超时、失联或崩溃不生成交易授权；不得复用已经过期的提案，也不能导致风控内核停止工作。
6. **权限原则：** Worker 按 [ADR-015](0015-automatic-data-manager-network-isolation.md) 默认不能任意连接外网，通过可信 Data Manager 取得所需行情/特征和合规授权数据。云端研究对账户信息的一次性授权（ADR-013）是**数据用途许可**，不意味着 Worker 可取得本地密钥、全机文件系统或直接交易接口。
7. **策略工件与研究证据：** 晋升策略应引用在独立评估时冻结的代码/模型/配置版本（ADR-006）。正式执行使用受控版本，任何变更触发新的验证/晋升判定，不能让 Worker 自行热替换已晋升工件。
8. **工程克制：** 不为 M0 预先实现多语言插件框架、通用沙箱平台、Kubernetes 或复杂调度器。M0 仅需能证明模拟提案无法绕开受信任本地风险与账本；真正的 Worker 沙箱在开始运行不可信代码前落地。

## 风险导向验收（后续阶段）

- Worker 的策略或恶意研究脚本尝试直接调用券商/修改风险策略/读取凭据，均无法获得相应访问权限。
- 同一份 Python 策略以固定工件、固定输入能产生版本化、可重放的提案；提案过期、未认证、未获晋升或格式无效不得开仓。
- Worker 崩溃/卡死或远程失联时，交易核心不失效，不能按过期信号盲目提交订单。
- 不可满足最小隔离条件的平台不应宣传为已安全运行不可信策略代码。

> 本 ADR 是运行时边界决策，不意味着现有 M0 仓库已有 Worker、可信隔离或真实交易能力。
