# ADR-001：混合策略执行与跨平台部署目标

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 决策范围：**策略决策在哪里计算、如何进入交易系统**
- 后续决策：独立策略 Worker 已由 [ADR-014](0014-isolated-strategy-workers.md) 确定；WASM 不再是必选运行时。券商 API 选型、独立风控的进程隔离方式、具体信号数据结构仍未由本 ADR 决定

## 背景

Stratide 必须支持开放式量化研究，允许 Agent 探索传统规则、统计模型和复杂机器学习策略；同时生产端必须极低本地性能门槛，不运行本地 LLM，不依赖 GPU。用户首先在 Windows 上开发和模拟验证，未来若价值足够，可能部署在低功耗的 Linux 主机或 **Apple Silicon Mac mini（macOS）** 上。

## 决策

采用 **混合策略执行（Hybrid Strategy Execution）**：

1. 资源需求低、适合本地运行的策略，在本地隔离策略运行环境中生成提案。
2. 资源密集型策略允许在远程计算环境生成提案；研究代码与模型不可直接访问券商账户、风控配置和下单通道。
3. 无论提案来自本地还是云端，均进入同一个版本化交易提案协议，经本地 Portfolio / Risk / Execution 路径处理；远程系统只提交提案，不能直接下单。
4. 提案在被采纳前应验证所属策略身份/版本、来源授权、基础数据的可用时间、提案有效期及必要的账户/风险状态。具体字段待 M0 契约设计。
5. 远程策略不可用或信号过期：禁止使用旧提案新增风险；本地风控、订单状态恢复与账户对账仍独立运转。交易过程中不能因网络故障假装止损可以保证成交。
6. 原则上支持 Windows x64、macOS ARM64、Linux x64/ARM64 的核心编译与运行；不同券商接口的操作系统支持需要独立验证，必要时可通过隔离网关适配，不能以此绕开本地风控。
7. macOS/Linux 长期部署仍为**候选方案**，只有可靠性、策略与实际成本表现达到门槛后再决定硬件采购。

## 理由与权衡

- 既不强迫所有研究成果塞进迷你主机，也不让本地风控依赖云端 LLM。
- 必须承担远程计算的网络延迟、失联、授权、成本和数据合规等约束；远程策略不一定适合高频或紧迫的交易决策。
- 根据 [ADR-014](0014-isolated-strategy-workers.md) 的后续决策，策略采用独立的本地受限 Worker 或远程隔离 Worker 执行；WASM 可选、不强制。具体 OS 沙箱及工件格式按真实需求确认。
- 实盘风险限制不等于收益保证或损失封顶。

## 验证方向（非新增过度工程任务）

M0 只需证明本地/模拟提案能够统一进入风控通道，未授权或过期提案不能导致模拟新开仓。远程 Worker、macOS 硬件、真实券商和完整 WASM 实现属于后续阶段，按实际需求验收。
