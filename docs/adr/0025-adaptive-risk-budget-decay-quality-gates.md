# ADR-025：双向动态风险预算与策略衰退监测——先证实正确性再允许实盘

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**方案 B：策略资金与风险预算允许上调、下调、冻结，监测市场环境变化与策略优势衰退**。
- Owner 追加要求：**高度重视代码质量与可验证正确性**；这部分很难设计妥当，不得草率交给 AI 直接控制资金。

- 尚未决定：具体风险与失效特征、测量窗口/证据要求、扩缩容幅度和冷却周期、波动与相关性模型、初次风险预算百分比、真实部署开关与审核验收参数。**不得把示例数字当成生产默认值。**

## 背景

新策略即使在历史回测、独立测试与前向模拟中表现可靠，也可能在实盘中因成本、行情结构变化、拥挤交易与策略优势衰减而迅速失效。仅小额试运行并逐步加仓会造成“追随近期赢家、在动荡到来前加大敞口”的风险。Owner 因此确认双向动态管理，但要求先保证软件工程与财务安全边界，而不是堆复杂预测模型。

## 架构决定

1. **区分准入、预算和实际订单。** Strategy Evaluator/Promotion Gate 决定某冻结策略版本是否有资格；Portfolio Allocator 在资格有效时提出**建议的**当前策略风险预算；受信任 Risk Kernel 独立验证并限制所有实际风险，Execution 只处理通过最终检查的交易意图。云端研究 Agent 不能修改 Owner 授权、熔断、账户账本或提高不可变风险上限。
2. **双向但非对称。** 新策略可从小额额度开始，只有持续可信的净收益/风险/执行质量证据和可用组合风险预算才逐步扩容；每次上调受到预先授权的步长、冷却期、上限、换手/成本约束。已证实的风险指标恶化可**更快**降低新风险预算、停止新增风险或冻结策略；这不保证持仓可以即刻卖出，更不意味着依据短期单次亏损就断言 Alpha 已失效。
3. **市场风险 vs 策略失效分层。** 市场波动、相关性集中、流动性缺乏、成交成本恶化可触发组合风险预算下调；策略优势衰减的判断需持久化、分段/前向验证的统计证据与适用样本数量，不以 2–3 天的噪声或单一回测指标做出确定结论。对研究中的参数自适应和频繁策略切换必须防止事后择优/过拟合。系统可以给出“证据不足，保持/收缩新增风险”的结论。
4. **净值与整体相关风险权威唯一。** 实际账户现金、持仓、净值、订单占用及组/策略归属由可信账本给出；策略预算变化不得凭空生出本金，也不得因多个版本或策略组高度相似而重复使用总风险限额。账户级财务熔断、Broker uncertainty 和 Owner 禁令始终优先于预算增加。
5. **纯计算建议、独立强制执行。** 首阶段优先使用简单、确定性、可解释的状态机与有界计算规则；建议接口输出 `strategy_version`、快照 ID、策略当前/目标预算、约束来源、输入数据来源/可得时间、变更理由及版本化策略配置。无账户写权限、无券商密钥、无直接下单权。Risk Kernel 可拒绝/截断上调，并持久化限制和审计证据。
6. **抗抖动和保守缺省。** 区分“风险预算缩小”与“主动平仓指令”；引入明确的冷却期/滞回等机制避免频繁扩缩容造成交易费用与追涨杀跌。数据缺失、指标过期、依赖异常或净值不可信时**不得自动提高风险预算**；保留风险检查与必要的保守停增仓、告警，不凭空假设行情或者盲目清仓。限价跌停、停牌、T+1 与未知订单依 ADR-003/007/018/019 处理。
7. **实盘上线前必须通过高风险代码验证。** 将算法分成可复现的纯决策函数与有状态的可信执行/账本层，避免将 LLM 生成代码直接嵌入持有资金权限的核心。对预定可接受输入构造不变量/边界/回放测试：预算不得超过 Owner/账户/策略限额；金融熔断永不能因表现改善自动解除；任何重复、乱序或过期事件不重复调整资金；突发价格跳变、流动性不足、相关性飙升、成本升高、策略短期失效、恢复后旧信号等均不得错误扩容；净额与已成交/持仓不矛盾；状态和理由重启后可恢复。结合不同市场区间与高摩擦压力场景进行 paper/shadow 对照，核算扩缩容带来的净收益、最大回撤、换手与实际成本。
8. **渐进部署与关闭能力。** M0 不包含动态风险预算引擎；后续先做离线纯函数/回放，再 paper/shadow，不通过足够的实测证据则不启用 live adaptive sizing。首次真实资金启用时，Owner 需明确授权可用的资金与风险上限及是否开启此项适应性预算功能；之后合格策略的日常预算调整可在授权范围内自动完成，不反复要求每笔人工批准。适应性组件出现故障时可由可信配置安全关闭**新的自动扩容**，而不是关掉 Risk Kernel 或已持久化的亏损熔断。
9. **不把测试等同金融保证。** 正确性测试和长期监测只能降低实施失误与过拟合风险，无法保证行情识别正确、策略长期有效、订单可成交或最大损失绝对可控。任何问题都要区分是算法信号退化、数据质量、执行成本还是实现缺陷，避免错误归因。

## 将来具体验收（依风险分阶段）

- 相同输入快照与配置得到一致预算决定，并可重放审计；模型研究版本和实时预算权限分离。
- 账户/策略上限及熔断、Owner 否决优先于任何绩效驱动扩容；多个组与版本不能重复增加实际风险敞口。
- 延迟行情、缺价、异常持仓、网络/订单未知、重复事件或重启，不会意外扩大资金或清除熔断。
- 对波动骤升、执行摩擦扩大、策略长期表现变差及正常短暂回撤分别回测，检验不会因无意义抖动持续买卖。
- 风险预算下降并不被误报成实际卖出成交；任何真实成交仍依券商确认。
- 未达到独立验证、长时间 paper/shadow 与可信实盘启用条件时，该功能保持不可用于真实资金。

> 这是架构和质量门槛决定；Stratide 当前仍处于 M0 scaffold 阶段，未实现可用于真实资金的动态风险引擎。
