# ADR-013：云端研究数据的一次授权与持续使用

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 原则：**首次访问某类账户/研究信息时授权一次；授权范围内后续请求不反复弹窗**。偏向让 Agent 获取完整且有用的研究上下文，而不是每次字段级最小化授权。
- 决策范围：云端 LLM、远程研究 Worker 可以接收的账户/持仓/交易信息及授权体验
- 尚未决定：具体模型服务商、实际授权类别与 UI 文案、具体数据许可条款/供应商存储策略、撤销后第三方已接收数据的保留处理

## 问题和用户意图

过于严格的逐字段最小化访问，会令自动研究反复弹出信息请求，浪费 Owner 时间，阻碍无人值守研究。Owner 希望：首次明确授权后，研究 Agent 可在已授予的范围内持续取得有意义的账户上下文；不用每天或每次请求再确认。

这不意味着忽视隐私或把云端研究模型提升为交易授权主体。

## 决策

1. **首次清晰授权，之后持久复用。** Owner 在首次启用对某个指定云端服务/研究用途的账户上下文共享时，作一次清晰授权，覆盖明确的数据范围、目的和接收服务；在授权没有撤销、到期或实质变化时，不再按每次 API 调用、单个字段或每次研究课题询问。
2. **可授予较完整研究上下文。** 经 Owner 授权，可以共享持仓、交易记录、资金变动、仓位比例、组合风险暴露、业绩记录和必要的研究日志；不强制只允许匿名比例。研究所用输入仍需与真实数据版本、来源及时间语义关联（ADR-005）。
3. **严格禁止将执行密钥交给研究端。** 无论是否已授权，券商登录凭据、访问令牌、交易口令、API Secret、生产下单能力、风险策略写权限、Owner 控制面授权凭据等都必须留在受信任的本地核心。账户标识、身份号码、银行卡资料和其他非研究必需的直接身份标识不应无目的发送。
4. **权限按“服务/用途/数据范围”而非每次访问存储。** 核心应提供一处易懂的授权设置与状态（例如账户研究上下文共享：已授权），显示接收服务和允许的关键数据类别；Owner 可以随时撤销或收窄未来的数据发送。研究 Agent 无权创建、扩大、续期自己的共享权限。
5. **实质越权才再次询问。** 访问新的数据类别、切换到未授权的外部接收方或改变共享目的时需要再取得 Owner 许可；平常对既有类别的新日期、持仓更新或新研究课题的访问无需打扰 Owner。为减轻负担，可在首次授权时一次选择必要的多个类别，不做重复的字段级同意弹窗。
6. **撤销立即限制后续发送，但不谎称云端已删除历史数据。** 后续请求必须执行最新授权；已经发给第三方的内容是否保留、是否用于供应商模型训练及能否删除，受实际 API 产品及合同/服务政策约束，应在授权时透明说明，不能一概承诺外部零留存。
7. **必要的执行边界不受授权影响。** 共享账户数据仅用于研究上下文，不等于允许云端直接修改持仓、操作券商、调整风控、扩大本金、解锁熔断或绕过独立 Evaluator/Promotion Gate。
8. **简单可审计。** 在可信配置中记录授权方、范围、接收服务、首次授权时间、撤销/变更时间；仅记录必要的发送审计信息并避免日志重复保存敏感明文。M0 不需要打造企业级 IAM/审批平台。
9. **数据许可独立检查。** 市场行情/商业数据源可能限制向外部 LLM 传输数据，即使 Owner 愿意共享个人账户信息，也不意味着拥有再分发第三方数据的许可。
10. **M0 仍然 paper-only。** 不因为架构上允许持久授权而在当前工程骨架实现云端账户数据同步或任何实盘凭据操作。

## 关键验收（后续实现）

- Owner 第一次同意某云端服务读取持仓与交易历史后，Agent 再次分析更新后的持仓时，不需要重复人工授权。
- Agent 请求未授权的另一家服务或全新敏感数据类型时，不能悄悄沿用原授权。
- 用户撤销权限后，下一次云端调用无法发送已撤销范围内的数据；既有服务端副本不能被误称为已清除。
- 无论共享选项如何，研究 Worker 无法接触券商密钥、执行 API、Owner 权限配置或 Risk Kernel 写接口。

> 此 ADR 规定最低授权边界和减少打扰的产品体验，不代表当前系统已接入实际云端研究账户数据。
