# ADR-031：撤销保护性挂单需在原接管界面显式勾选确认

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**B：人工接管时若包含可信识别的保护性挂单，在原确认界面列示并要求额外勾选其撤销风险，不增加第二层弹窗。**
- 关联：[ADR-030](0030-owner-takeover-pending-order-choice.md) 接管三按钮与撤单语义、[ADR-029](0029-owner-manual-takeover-explicit-return.md) 接管锁和 Owner 显式交还、[ADR-003](0003-account-wide-order-uncertainty.md) 券商状态不确定、[ADR-017](0017-single-writer-durable-recovery.md) 权威恢复和对账。
- 待定：具体券商对委托的保护作用识别能力、订单数据新鲜度阈值、元数据缺失/冲突时的精确保护分类政策与逐单撤单能力。**不得假定所有卖单均属保护单或所有普通单都无风险。**

## 目的

Owner 已选择人工接管时提供相邻的「保留挂单并接管」（普通按钮）、「尝试撤单并接管」（红色警示按钮）以及另一侧「取消」按钮。若要撤销的委托包含减风险、止损或其他承担保护目的的卖单，单靠按钮颜色可能不足以防止误取消。因此使用同一界面的必要风险确认，而不是叠加第二次弹窗。

## 规则

1. **同一界面完成必要确认。** 在上述三按钮上方（或附近）展示可信查询到的仍活动中的委托摘要；对经可信订单/风控元数据识别的保护性委托，突出展示证券、方向、委托/剩余数量、订单标识及其风险用途。提示撤单可能移除原有风险保护，未成交/撤单中的订单仍可能在券商侧继续成交。
2. **保护单存在时，红色撤单操作须显式勾选。** 提供默认**未勾选**的复选框，例如「我理解本次撤单可能取消上述保护性卖单，并由我接管后续风险处置」。若存在保护性挂单但 Owner 尚未勾选，红色「尝试撤单并接管」不允许提交；说明原因即可，**不弹第二个确认窗口**。按「保留挂单并接管」不要求勾选该项，「取消」也不要求。
3. **不可误报不确定订单为普通安全订单。** 保护属性未知、券商委托清单不完整、有效订单快照明显过期或风控元数据冲突时，应标注「无法确认是否有保护性挂单」。默认不能把这些订单当作非保护单而绕过勾选；需要在受信任界面重新核实或把不确定风险明确纳入同一风险确认。若当前无法获得可信活动订单身份，不得对不明订单执行盲目批量撤单。Owner 仍可选择「保留挂单并接管」使自动新单暂停，并在券商 App 人工处理。
4. **风险确认绑定当次受信任委托快照。** 对勾选时展示的账户、订单集合（包含保护性标记）、剩余数量、券商状态和快照版本记录确认范围。真正发送批量撤单之前，可信核心按最新券商状态核对目标订单身份；若发现新保护性挂单、分类变化或与提示有重大差异，不能拿旧勾选直接授权扩大后的撤单集合，应要求在**原接管页面刷新提示并重新勾选**，而不是继续撤销没被确认过的订单。
5. **先持久化接管锁，再处理挂单。** 两种接管选项都遵守 ADR-029：可信核心完成执行权状态持久化与自动新增买卖委托封锁后，才可能发出 Owner 授权的撤单请求。撤单是受控例外路径，不是自动策略恢复下单权限。若撤单被风险确认阻断，不能误显示「已接管并撤单成功」；具体状态必须透明，避免 Owner 误以为订单已终结。
6. **发起撤单不等于券商撤单成功。** 对每笔活动委托追踪 `cancel_requested`、`cancel_pending`、`cancelled`、`partially_filled`、`filled`、`cancel_rejected`、`unknown` 等实际券商结果；以权威回报/查询为准对账。不能从界面勾选、请求发送或 API 受理推断没有持仓风险。
7. **三按钮布局不改变。** 「取消」继续放在另一侧，只关闭未提交的确认窗口、不会接管也不会发撤单；普通「保留挂单并接管」与红色「尝试撤单并接管」继续相邻且语义明确。不能把「保留」与「撤销」合并为通用“确定”；也不能将此风控勾选用于其它无关高风险操作。
8. **测试优先真实资金风险，而非 UI 微观像素。** 必须覆盖：有保护单未勾选时禁止红色撤单；勾选正确快照后方可按既定计划请求；订单清单或保护分类改变时使旧勾选失效；保留/取消按钮无误触发；网络断线、重复点击/回报、部分成交和重启不产生越权撤单或错误终态；任何接管成功后不会继续自动买卖。测试结果不构成券商实际撤单一定成功的保证。
9. **实现边界。** 当前 Stratide 处于 M0 paper-only，暂不实现券商订单风控分类、真实 UI、撤单 API 或多层权限系统。ADR-031 是未来接管功能的交互与执行安全规则。

## 示意文案（设计描述，并非交互实现）

- 提醒：「以下保护性挂单可能在撤单后不再承担原有减仓/止损作用；券商撤单仍可能失败或发生竞态成交。」
- 默认未勾选：「我了解撤销这些保护性挂单的风险，确认尝试撤单。」
- 布局：另一侧 `取消` ｜ 相邻 `保留挂单并接管` `尝试撤单并接管（红色）`。

> 必须注意，保护性标记只能依据可信订单与风险记录推断。此 ADR 不能保证止损单会得到成交，也不允许简单把所有卖单当作有效保护。
