# ADR-029：紧急人工接管后的自动交易权限必须由 Owner 主动交还

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**方案 A——人工接管之后，只有 Owner 经过可信身份确认并显式交还执行权，Stratide 才可能恢复自动交易。**
- 关联：[ADR-028](0028-dedicated-broker-account-initial-live.md) 初始实盘专户、[ADR-017](0017-single-writer-durable-recovery.md) 唯一执行主体/持久恢复、[ADR-003](0003-account-wide-order-uncertainty.md) 未知订单状态全账户停新增风险、[ADR-004](0004-configurable-conditional-recovery.md) 技术故障条件自动恢复、[ADR-018](0018-equity-based-loss-drawdown-breakers.md) 财务风险熔断。
- 待决：具体管理入口及认证机制、突然在券商 App 抢先介入但尚未来得及暂停系统时的最小告警/自动探测能力、交还操作的用户界面与记录字段。挂单由 Owner 选择保留或尝试撤销的确认按钮方案已由 [ADR-030](0030-owner-takeover-pending-order-choice.md) 确定；不得假设券商能技术性屏蔽其他终端。

## 背景

Stratide 首次实盘以专用证券账户运行，但在异常市场或系统风险事件中，Owner 仍可能需要直接登录券商 App 手动处理持仓。这属于**明确更换交易控制主体**，不等于普通断线恢复。若系统在识别到网络恢复/成功对账后自行重获执行权限，可能与尚未完成的人工操作发生冲突。

## 决策

1. **人工接管是持久的独立控制权状态。** Owner 通过可信管理入口请求接管后，系统首先原子化地持久化 `OWNER_MANUAL_TAKEOVER`（概念性状态名）及接管原因、账户、时间、操作人/授权来源、执行权版本。写入未确认成功时不得宣称已完成安全交接。该状态在重启、进程替换、网络恢复、市场跨日后保持，不能由 Agent、Worker、预算分配器或技术故障自动恢复逻辑清除。
2. **停用自动订单提交；保留监控与核对。** 接管状态下，所有 Stratide 发出的**新券商订单提交**一律禁止，不只是新开仓；包括来自策略 Agent、自动减仓、再平衡或自动晋升的订单。既有券商委托可能继续挂单或成交，因此“停新单”不等于撤单/取消既有委托，不能伪称券商侧已无交易活动。只读风险监控、必要的券商查询、对账和 Owner 报告仍可运行，但不能擅自恢复自动执行。已有委托处理方式留待下一项专门决策。
3. **优先完成真正的执行权隔离。** 可信核心必须用同一账户的持久化接管状态拦截所有自动下单路径，并对并行处理中的提交意图建立可审计的状态屏障，避免“Owner 点了接管，程序还有订单从队列发出去”。物理券商终端的外部人工操作及不可撤销的网络在途请求不一定能被系统硬阻止，故要告知仍未确定的风险并查明最终券商状态；单台主机锁不能当作券商侧跨终端互斥保证（ADR-017）。
4. **交还需要 Owner 明确确认。** 仅 Owner 经可信认证的管理动作可以发起 `RETURN_TO_AUTOMATION`（概念名），不能依据“长时间无人操作”“最后一笔人工委托结束”“网络恢复”或“自动对账成功”猜测人工操作已完成。请求交还也**不是立即生效的恢复指令**：先完成必要的券商授权订单、成交、待决委托、可卖仓位、冻结/可用资金、现金及公司行为检查，修复或标注人工活动对策略虚拟归属的影响，再校验策略资格、Owner 当前授权、账户/策略风险锁与信号有效性，最后才允许一个可信实例恢复自动订单权限。
5. **不能自行解除其他风险锁。** 交还控制权只处理人工接管锁，不覆盖 ADR-003 未知委托、ADR-018/019 损失/回撤或策略限制、Owner 显式禁令和账户资金许可。存在未对账资金变动、来源不明成交或未知工作订单时维持账户新风险冻结；Owner 的确认不能代替事实上的订单/账户对账。
6. **与技术恢复 ADR-004 互不混淆。** ADR-004 的 `conditional_auto` 仅适用于允许自动恢复的**技术性**暂停。即使技术故障已排除并全部对账，只要人工接管锁仍然有效，就不得自动恢复交易。系统不能把人工接管写成普通断线异常以绕开本 ADR。
7. **重返自动化前避免旧信号重放。** 不自动提交人工接管期间积压或早已过期的信号/委托；以最新账户权威状态和符合时间要求的重新计算意图为基础，通过 Portfolio Allocator → Risk Kernel → Execution 的完整审批链再开放新增风险。接管、尝试交还、拒绝交还、最终恢复均保留审计与幂等/版本验证。
8. **实盘功能单独验收，M0 不实现。** 对未来实盘控制台只需一个清晰、可验证、可审计的 Owner 接管/交还入口，不建设复杂权限管理框架。当前 M0 只做 paper-only 可信账本与风险垂直闭环；没有券商 App 联动、人工控制权切换或真实订单取消能力。

## 风险驱动验收

- Owner 开启人工接管后，新的自动订单全部被拒绝，策略和 Agent 无法绕过；监控/只读对账仍可用。
- 重启、换主机、断线恢复及 ADR-004 的 `conditional_auto` 均无法解除接管锁；不存在“断线后自己恢复下单”的路径。
- 有未完成/未知券商委托时，不把“暂停了程序”伪称“撤销了委托”；恢复前核对既有委托、人工成交和资金/可卖数量。
- Owner 发起交还后若券商持仓不一致或财务熔断仍生效，仍不允许自动新增风险；相同交还请求重试不会重复恢复或发单。
- 恢复后只接受新的、可交易、经完整风险审查的提案；没有积压订单意外执行。
- 未来紧急介入不会被解释为允许在专用账户内长期人工与机器人同时交易。

> 这是未来实盘控制权移交规则。当前 Stratide 为 M0 工程骨架，没有真实证券交易或实盘人工接管功能。
