# ADR-018：以账户净值（已实现与未实现盈亏）触发亏损及回撤熔断

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**方案 B — 以可信账户净值变化，而非仅已实现亏损，作为每日亏损与回撤熔断依据**
- 关联：[ADR-003](0003-account-wide-order-uncertainty.md) 订单未知全账户停增仓、[ADR-004](0004-configurable-conditional-recovery.md) 技术性故障恢复与财务熔断区分、[ADR-008](0008-dynamic-portfolio-capital-cap.md) 共享账户资金、[ADR-016](0016-verified-data-source-failover.md) 数据质量、[ADR-017](0017-single-writer-durable-recovery.md) 持久化
- 尚未决定：Owner 的具体每日亏损/回撤百分比、权益估值刷新频率、停牌/无成交标的的可靠估值方法、实盘来源细节、亏损熔断的人工复位流程。策略级风险预算、归属与局部熔断已由 [ADR-019](0019-account-and-strategy-risk-layers.md) 确认。

## 问题与背景

如果亏损熔断仅统计已实现损益，长期持仓即使市值暴跌，也可能因为没有卖出而不触发风险保护。多策略共享一套账户资金时，Risk Kernel 必须基于整个账户实际承担的价值波动评估风险，而非把已实现与未实现损益割裂。

Owner 明确选择 B。此决定仅确定计算依据和核心不变量，不将此前文档中举例的 1% 日损或 8% 最大回撤直接采纳为生产阈值。

## 决策

1. **基于可信总权益（NAV / account equity）：** 纳入可用及冻结现金、所有证券/其他持仓的可信当前市值、已发生交易的手续费与税费、已实现盈亏、持仓浮动盈亏，以及必要的应收应付/负债（若适用）。不允许仅因尚未卖出就排除浮亏。持仓数量、现金等账簿状态必须与权威券商记录对账；交易价格来源走可信 Data Manager。
2. **每日亏损排除外部现金流影响：** Owner 入金不是策略收益，Owner 出金不是策略亏损。比较当日开盘/指定日初基准权益与当前权益时，应识别并中和期间外部入金、出金、非交易性转账等现金流；适当处理盘中流入流出时点，避免用简单余额差算出虚假盈亏。股息、分红、税费等需依据明确会计与除权语义区分投资收益与外部资金流。精确资金流调整算法在契约/会计实现阶段确定。
3. **累计回撤同样基于资金流调整后的净值轨迹：** 高水位（high-water mark）与当前净值必须是可比口径；新入金不能假装刷新投资业绩最高点，出金不能伪造亏损或回撤。持久化日基准、已确认的高水位、估值依据和触发证据；算法可采用一致的资金流调整净值指数或等价方法，M0 不需引入复杂绩效归因系统。
4. **Risk Kernel 独立计算并执行：** 由受信任核心消费可信订单/仓位/价格与现金流记录计算和校验指标。策略 Agent、生产 Worker、研究模型不得自行选择估值或修改资金流记录以抬高权益、降低亏损百分比、调整阈值或解除熔断。
5. **触发后阻止整个账户新增风险：** 当日亏损限额或累计回撤限额达到 Owner 授权的实际配置阈值，持久化 `LOSS_CIRCUIT_BREAKER` 或 `DRAWDOWN_HALT`，禁止所有策略增加相应账户风险。已持仓及减风险操作须依赖可信订单/仓位状态和适用交易规则安全处置；**不自动保证平仓、最大已实现损失或止损价成交**。
6. **估值缺失或不可靠时不能默认安全：** 行情陈旧、停牌/无流动性、价格源重大冲突、证券身份/拆分映射错误或与券商持仓不符，都可能让账户 NAV 和亏损判断不可靠。若整体 NAV 的风险判断因重大未知值而不可信，应暂停该账户新增风险并报告估值不确定性；不允许将缺价资产简单估值为 0、沿用旧价断言无亏损或挑选有利价格。独立 Data Manager 源故障按 ADR-016 限制受影响依赖；若它使**整个账户风控净值无法可靠计算**，则要采用账户级停增仓，不能用局部故障逻辑绕过账户风险检查。
7. **恢复规则不混淆：** 财务亏损熔断与 ADR-004 的可条件自动恢复的技术故障不同。恢复行情、重启、换数据源、跨日重置每日基准等都不能无授权地解除已触发的亏损/回撤熔断。具体 Owner 人工复位流程在后续讨论，但 Agent 不可私自复位。
8. **不使用未批准的具体阈值：** 原 `docs/RISK_POLICY.md` 中 1% 每日亏损和 8% 回撤仅为历史示例，不是当前用户确认值。实际配置的数值、账户范围和触发判据须在未来实现阶段由 Owner 确认。
9. **M0 轻量落地：** 在 paper-only 模拟账本测试中，最少验证一例已实现与浮动盈亏共同作用的 NAV 更新、一个带出入金调整的熔断判断、一次触发后重启仍保持停增仓。无需接入真实券商或复杂多资产估值平台。

## 财务安全验收（未来）

- 持仓未卖出但市值下跌到配置的账户亏损阈值，应触发熔断；单凭“尚未实现亏损”不能绕过。
- Owner 入金或出金不会凭空制造正负策略回报及回撤；高水位可在资金流调整后对比。
- 账户估值重大不确定时，不因为缺少可用亏损数值就允许新增风险。
- Agent 无法修改行情评估权限、限额、现金流记录或财务熔断状态。
- 重启、恢复行情或跨到次日不会擅自解除财务熔断；风险减仓仍需可信状态。

> ADR-018 是架构规则，当前 Stratide 仍处于 M0 paper-only 骨架阶段，没有已实现的真实账户净值/券商风控系统。
