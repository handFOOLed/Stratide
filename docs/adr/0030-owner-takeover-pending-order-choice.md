# ADR-030：紧急接管时明确选择撤销或保留既有挂单

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 对 Question 30 的自定义选择：**保留两种接管方式，由 Owner 在接管确认界面明确选择；「自动尝试撤销挂单」使用红色警示按钮，「保留现有挂单」使用相邻普通按钮，「取消」放在另一侧。**
- 关联：[ADR-029](0029-owner-manual-takeover-explicit-return.md) 接管权限与显式交还、[ADR-028](0028-dedicated-broker-account-initial-live.md) 专用账户、[ADR-003](0003-account-wide-order-uncertainty.md) 券商不确定性冻结、[ADR-017](0017-single-writer-durable-recovery.md) 单写入者与对账。
- 尚未决定：不同券商撤单接口/速率约束、订单状态轮询与超时策略、保护性委托的具体分类与逐单选择能力（同界面额外勾选已由 ADR-031 确定）、接管表单认证方式。按钮外观与排列已决定；不要自行设定默认选中模式。

## 场景

Stratide 已提交的买卖委托可能在 Owner 点击紧急人工接管时仍在券商交易所挂单；自动交易核心停止新单不等于已有委托已经结束。Owner 希望能够选择是否让系统主动发起撤单，而不是强行规定每次都撤单或保留。

## 决策

1. **一个接管确认界面，两种明确操作，不设隐式默认。**
   - `自动尝试撤销挂单并接管`：**红色警示/危险按钮**，强调这是可能撤销保护性卖出等既有交易安排的高影响操作。
   - `保留现有挂单并接管`：与红色按钮**相邻**的普通/中性按钮，强调既有挂单可能继续成交。
   - `取消`：放在**另一侧**，明确仅取消本次接管请求/关闭对话框；**绝不发起券商撤单、也不切换执行权限**。若接管前系统已存在独立财务/技术冻结，取消弹窗当然不解除那些状态。
   - 两种“接管”按钮都要求 Owner 认证及必要的账户/执行权限核验；不使用仅靠颜色区分含义的设计，必须有明确文字和可读的结果状态。
2. **两种选项都先持久化接管锁并阻止任何新的自动买卖委托。** 一旦成功确认接管，按 ADR-029 在可信核心中原子化记录 Owner 的接管状态与选择，并拦截自动策略订单通道；网络恢复、重启或模型建议不能释放。所有在途提交、券商未知结果仍需权威查证。挂单处理是接管之后的单独受信任操作，不可由 Agent 或策略发起。**撤单请求不视为新的买/卖委托**，但必须使用专门的经授权撤单通道，不能开放普通自动下单权限。
3. **红色路径：仅“尝试撤单”，不假设成功。** 对经券商确认仍在委托中的、属于 Stratide 可识别订单的挂单发起撤单（按账户实际 API 能力与身份/订单 ID）；审计逐单请求与返回，持续核对 `PENDING_CANCEL`、`CANCELLED`、`PARTIALLY_FILLED`、`FILLED`、`CANCEL_REJECTED`、`UNKNOWN` 等真实情况。发送撤单请求或收到接口受理并非已撤单成功；不可随意重复向不明状态订单发起请求，避免超限/错误判断。
4. **中性路径：保留挂单，不视为停止成交。** 停止 Stratide 新买/卖委托之后，不自动向券商发起撤单。向 Owner 列示仍有效的挂单清单、方向、标的、数量、已成交数量、价格、可用/冻结资金或证券，明确警告：**人工接管后这些订单仍可能成交**。相关订单继续归入可信账本并由查询/回报更新，直到确认终态。
5. **保护性委托风险明确提醒。** 红色撤单路径可能撤掉用于减风险或保护仓位的卖出/其他保护性委托；界面应在可得数据中标出并提示可能失去保护。保护性标记只能来自可信订单/风控元数据，不能未经验证便保证某单“安全”。若可信识别到保护性挂单，撤单需在**同一接管界面**额外勾选风险确认、无需二次弹窗；该勾选仅对已核实的当次委托快照有效。详见 [ADR-031](0031-inline-confirmation-for-protective-order-cancellation.md)。是否支持逐单选择仍留待券商接口选型后决定。
6. **状态可见且可恢复。** 两种路径都应提供“已接管，自动新单已停用”“挂单处理进行中/已完成/状态未知”的分离状态，不得显示“已全部撤销”除非有完整券商终态证据。若接口故障或断线，保留接管锁、订单未知标记和资金/持仓保守预留，继续执行 ADR-003 的禁止新增风险与人工告警。处理过程要持久化、可重放、幂等，避免进程崩溃或重试导致误操作。
7. **取消按钮没有隐性副作用。** 接管尚未确认时点击「取消」、按退出键或关闭确认框，都不得自动暂停、改变账户锁或发起撤单；如果系统已经因其他原因处于停单状态，不得将“取消”理解为重新开单。在异步撤单已经启动后，关闭状态提示**不等于撤销撤单请求**，此时必须用不同文案避免误导。
8. **后续交还执行权依然必须由 Owner 显式提出。** 不论选择“撤销”还是“保留”，都不能在券商对账恢复后自动重启下单。交还时须查明所有未完成委托及撤单中/部分成交结果、资金/持仓变化、Owner 人工活动及原有风控锁，符合 ADR-029 才能恢复。
9. **不进入 M0。** 当前只固化未来接管确认 UI 与语义契约，不开发券商撤单功能、实际接管弹窗或复杂桌面可视化。继续专注 paper-only 单策略风险/订单/账本闭环。

## UI 参考排列（语义，不是当前可点击页面）

`[ 取消 ]                               [ 保留现有挂单并接管 ] [ 自动尝试撤销挂单并接管（红色警示） ]`

- “取消”为中性次要操作，与两个接管确认操作空间分离；“保留”是中性确认操作，“撤销”是显著红色高风险确认操作。
- 需在操作区上方说明“接管后自动新单将停止，既有挂单可能继续成交；撤单请求未必成功”。具体响应式布局由 UI 实现阶段确定，保持左右分组和按钮语义。

## 风险驱动验收

- 点击「取消」：不新建人工接管锁、不发撤单、不调用券商买卖接口；任何原有风险/技术锁不改变。
- 点击「保留」：接管锁持久化、自动买卖停止，既有挂单无自动撤单请求；之后挂单真实成交仍更新账户且不得自动恢复自动交易。
- 点击红色「撤销」：接管锁已成功持久化后仅对确认可识别的活动委托发起经授权撤单；撤单失败、部分成交和竞态成交均被准确显示、重启后可对账，不误报全部撤销。
- 并发情况下不会存在“接管锁成功后新自动买卖单仍穿过执行闸门”的路径；不可由 Agent 请求绕过接管锁。
- 恢复自动交易始终需要 Owner 显式交还和全部可信对账，不因本次按钮选择而改变。

> 设计已确定；Stratide 当前仍是 M0 工程骨架，未实现实盘账户、撤单 API 或实际按钮界面。
