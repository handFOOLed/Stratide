# ADR-016：经验证的行情/研究数据源自动故障切换

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- Owner 选择：**方案 B**，Data Manager 在主源故障时自主启用已预先验证的备用源；用户无需逐次处理
- 关联：[ADR-003](0003-account-wide-order-uncertainty.md) 券商订单未知时全账户暂停、[ADR-005](0005-tiered-data-evidence.md) 数据证据与时间语义、[ADR-015](0015-automatic-data-manager-network-isolation.md) 可信数据管理
- 尚未决定：实际供应商、各字段/频率的新鲜度标准、冲突阈值、备源选择策略、恢复主源的条件和具体报警频率

## 背景

行情、财务或外部研究数据提供方可能限流、超时、停服或返回不完整数据。要求 Owner 为普通供应商故障逐个手工切换，与无人值守自主交易目标冲突。但“有第二个 API 就直接代替第一个”同样有风险：复权、交易日、时区、停牌标记、延迟、币种、证券代码映射等差别可能产生貌似合理的错误数据，损害正式策略验证或误触发交易。

## 决策

1. **默认自动切换：** Data Manager 检测主源异常或质量不足时，选择**已纳入可信源清单且与该数据类别/市场/频率兼容**的备用源，在切换前执行最小必要的新鲜度、来源、时间戳、单位/代码映射、许可及质量检查。成功即可自主切换，常规场景不要求 Owner 在线。
2. **不信任“备用”标签本身：** 未经生产准入验证的新发现 URL、Agent 临时写的接入代码或未经 Owner 首次授权的付费/敏感共享源，不能因为主源故障而绕过 ADR-015/013/012 的权限与费用边界。
3. **比较之前先统一语义：** 对齐证券身份、交易日/时区、实际可得时间 `available_at`、报价/复权规则、单位及数据类型。经正常化后若出现无法解释的重大冲突，不能自动选择价格对策略最有利的版本继续下单；标记为 `CONFLICTED` 并暂停依赖该数据的**新增风险**。
4. **没有可信数据就局部停止新增风险：** 若主备均不可用、信息过期、版本不一致或存在重大冲突，则限制受影响证券、策略或其共享依赖的新增交易。若关键全局输入影响整套组合，则扩大到相关全部策略。不能伪造行情、把历史缓存当实时行情、盲目清仓或按过期信号开新仓。
5. **与券商不确定性不同：** 数据错误通常按影响依赖范围限制交易，不因单一股票行情故障无条件冻结全账户；但**ADR-003 的订单状态不明**仍必须冻结整个相关账户的新增风险，不可通过更换行情源绕过。
6. **来源转换可追溯：** 记录原主源/新主源、切换时间、数据版本/序列时间、验证依据与失败原因；正式评估与实时信号必须使用实际生效时可得的数据，不能事后悄悄改写源变更前的观察或绩效。数据品质下降时相应降低评估证据资格。
7. **恢复亦受检查约束：** 主源重新可用不意味着立刻切回。应验证稳定性和数据一致性、避免反复来回切换（flapping），并对相关策略按最新有效输入重新判断，不能重放过时订单。
8. **异常可观测、日常低打扰：** 普通、已解决的源切换记日志并在摘要呈现；持续无可用源或实际导致交易冻结、重大报价分歧时升级异常通知。不要求每次自动故障转移人工审批。
9. **保持轻量：** 本 ADR 只确定可信 Data Manager 的行为约束，不要求 M0 接入多个真实源、实现自动切换平台或为所有可能字段设计复杂交叉验证算法。

## 后续验收方向

- 主源超时且已验证备用源的格式、时效、许可、价格含义均合格时，自动切换，受影响策略可用新鲜数据继续判断，但始终经过 Risk Kernel。
- 两源在正确归一化后有重大冲突时，不自动挑较优报价，不允许依赖受争议数据的新开仓。
- 无可靠数据时，只冻结依赖它的新增风险；账户未知订单依旧按 ADR-003 全账户冻结。
- 临时发现但尚未授权的商业源或不可信适配器不能被当作故障备源自动启用。
- 记录来源与数据版本变化；重启后可以区分新鲜数据与旧缓存，不重放过期交易提案。

> 当前 Stratide 仍是 M0 工程骨架；此文不是声称已实现自动行情故障切换。
