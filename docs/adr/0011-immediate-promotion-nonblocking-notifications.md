# ADR-011：自主即时晋升与非阻塞通知（取代 ADR-010 的默认等待）

- 状态：**已接受（Accepted）**
- 日期：2026-10-27
- 取代：[ADR-010](0010-configurable-deployment-grace-period.md) 的“默认 10 分钟等待”及通知阻塞式讨论
- 与 [ADR-009](0009-auto-promotion-owner-veto.md) 配合：保留用户随时否决权
- 未决定：策略资格量化阈值、通知送达平台、每日汇总时点、具体组合策略数/交易额度

## 用户反馈及理由

Owner 可能在夜间休息，Agent 也可能自主发现大量合格策略。要求每次晋升等待用户浏览甚至保证通知送达，会把系统变成高频审批队列，而不是无人值守、自主运行的量化研究与交易引擎。Owner 明确希望“只要风险边界通过就投入运行，损失由风控兜底”。

**澄清风险含义：** 风控并非损失保险。跌停、跳空、停牌、交易故障和 T+1 等可能阻止止损成交；风控可以控制新增敞口和发出风险处置意图，但无法保证最大已实现亏损。独立策略验证也不能省略。

## 最新决策

1. **默认即时自主激活：** 未来 Owner 已单独启用实盘、预设账户本金/风险限额且没有禁令时，独立 Evaluator 验证通过的冻结策略可直接交由可信 Promotion Gate 审查，满足资格、资金、组合风控、执行可用性、当前 Owner 否决状态后立即激活。不要求逐策略人工审核或通知确认。
2. **10 分钟窗口保留为可选配置**：默认 `promotion.grace_period = 0m`；Owner 可显式配置 `10m` 或合理非零延时作为个人偏好。Agent/策略无权自行降低已授权的等待设置。不要把旧默认 10 分钟误写为新默认。
3. **通知是观察，不是授权**：新策略激活与退出记录必须持久化，供 Owner 随时查看。普通通知失败、手机免打扰或用户睡眠不应成为已授权策略的默认部署阻塞条件。重大财务异常/账户冻结与告警通道独立设计，但告警无法送达也不能解除风控冻结。
4. **低打扰监督**：普通研究、晋升、表现、策略退出可以合并为每日汇总；对账户亏损熔断、券商状态不确定、资金与仓位异常等重要情况优先及时提示。不要求 Owner 每早处理大量策略待办。
5. **有边界的自主性**：即时晋升只作用于独立验证且在既有 Owner 授权范围内的策略，不能跳过 ADR-005/006 的可信证据和验证隔离、ADR-007 的真实可执行性、ADR-008 的本金/组合共享账本、ADR-002/003/004 的风险/账户冻结，不能使 Agent 自行打开实盘或扩大风险额度。
6. **策略数量不能累加风险授权**：多策略同时活跃时，必须从同一个共享账户资金和风险预算中配置，按组合相关性、成本和运行资源综合判断，不得每套策略各自享受一份完整账户本金。具体自动选择、淘汰策略的评分/名额政策留待后续决策。
7. **Owner 否决仍是硬约束**：Owner 可随时否决或禁用策略（含已自动晋升版本）。禁用立即阻止新风险；历史订单与持仓需要安全对账与后续风控处理，不能承诺回滚已成交交易。持久否决不可被 Agent 绕过。
8. **审计及状态**：记录候选 ID/版本、资格证据、激活或拒绝决策、资金预算、禁用状态、通知尝试。应用重启不得把原本不合格或被否决的策略升级；配置为非零缓冲时必须维持其期限和再核验。
9. **M0 范围不变**：当前仓库仍是 paper-only scaffold，没有可用的真实券商/策略晋升/告警系统。上述能力只有在后续明确阶段才实现。

## 关键验收（后续实施阶段）

- 预先授权范围内、合格未否决的策略在默认 `0m` 缓冲下无须用户在线或推送送达即可经可信 Gate 自动启用。
- 开启可选 `10m` 缓冲时，不能提前激活；期满重新核验，Owner 否决可拦截。
- 同时发现许多合格策略时，不得超出共享账户的本金/敞口，也不得建立逐条人工审核待办才能继续的依赖。
- 策略未通过独立评估、被否决、账户冻结或风险限额不足时，拒绝部署，即使通知功能故障或用户不在线。
- 实盘未经 Owner 单独开启，不允许任何真实订单。
