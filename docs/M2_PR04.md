
## Windows 离线运行

需要 Python 3.12+、Git 和现有 Rust/MSVC 工具链；Python 仅用标准库。先在本工作树构建可信 CLI。`--offline` 使用已安装的 Cargo 缓存，不下载依赖；缺缓存时构建会明确失败。

```powershell
pwsh -NoProfile -File scripts/with-msvc.ps1 build -p stratide-cli --locked --offline

# 不需要行情、账户、Provider 或密钥的完整工程样例。
$registration = python scripts/research-candidate.py --registry smoke register `
  --owner-input research/synthetic-candidate.example.json | ConvertFrom-Json
$candidate = python scripts/research-candidate.py --registry smoke freeze `
  $registration.registration_sha256 --evidence-class synthetic_test | ConvertFrom-Json
python scripts/research-candidate.py --registry smoke evaluate $candidate.candidate_sha256
python scripts/research-candidate.py --registry smoke status $candidate.candidate_sha256
```

该样例直接使用仓库已有 `samples/m0-pr03-synthetic.json` 和 `first-buy-second-sell-third-risk-probe-v1`，包括真实运行的风险拒绝、模拟费用、持仓和 NAV 校验。它只用于工程验证，评价为 `SYNTHETIC_TEST_ONLY`，不评价 SMA 的研究资格。原 CLI 对“合成来源冒充 historical_replay”的拒绝保留。

真实历史路径只读 Owner 已保存的原始四接口 JSON 和 `extraction.json`，不联网补数。`--source-dir` 应指向原冻结源目录，不能指向旧 ledger 或六报告目录。

```powershell
$sourceDir = '<Owner已有的冻结源目录>'
$registration = python scripts/research-candidate.py --registry history register `
  --owner-input research/fixed-candidate.example.json | ConvertFrom-Json
$candidate = python scripts/research-candidate.py --registry history freeze `
  $registration.registration_sha256 --source-dir $sourceDir `
  --evidence-class historical_replay | ConvertFrom-Json
python scripts/research-candidate.py --registry history evaluate $candidate.candidate_sha256
```

可选 `--expected-input-sha256 <已知dataset SHA>` 要求重新准备的数据与预期一致。缺源时可以省略 `--source-dir`，持久记录 `DATA_BLOCKED`；修复数据后重新 freeze 产生另一个候选。拒绝、数据阻断也是有效输出，不能解释为策略已通过。

每条命令输出 JSON。输入/完整性/执行失败返回退出码 2 和错误码；成功保存的 `RESEARCH_ONLY`、`DATA_BLOCKED` 或不足评价返回 0，调用者必须读取状态。`evaluate` 输出 `report_ref`，相对于本机 `state/candidates/<registry>/`，完整指标和账本引用在该文件。所有新数据都在 Git 忽略的该目录内；`--registry` 只接受名称，没有任意输出路径或可执行文件参数。

```powershell
python scripts/research-candidate.py --registry imported register `
```

未指定 Owner 固定模板的任务保留 `RESEARCH_ONLY / UNSUPPORTED_CANDIDATE`。未知模板、修改参数、额外 `exe`、holdout 或资格字段同样不运行。恶意 shell/Python 文字保留为来源文本；无 `eval`、shell、动态插件、生成代码执行或新 Web 接口。

## 冻结、重复执行和恢复

- `registrations/<SHA>.json`：输入摘要及版本、人工课题/假设/限制、可选 Agent 全部来源、提交时间。相同输入复用登记；修改任一输入内容形成新登记。
- `candidates/<SHA>/candidate.json`：不可变候选版本、登记引用、固定模板/配置 SHA、原输入材料、协议及相关源码 SHA、冻结时间、数据源/源日/模式/证据级别和全部冻结文件 SHA。
- `frozen/`：原源文件的本机副本及既有审计器重建的 input/audit/split。历史固定结束日和 70/30 分界不因回报变化。原文件、旧报告和权威账本均不写入。
- `evaluations/<SHA>/attempt-NNNN/`：执行前先写 plan（含候选、协议、可信二进制 SHA），再在全新独立目录运行既有回放、ledger 重导出、财务一致性、固定基准及研究评价。没有任意资金/规则/窗口参数。
- `result.json`：全部完成并复核 SHA 后原子发布的唯一完成标志，绑定 plan、ledger/六报告/评价/基准 SHA、指标及交接契约。读取/复用前重验完整性。进程中断或失败保留 attempt，无完成标志就不能报告通过；下一次使用新 attempt 和新模拟 ledger，不重用半成品。

相同候选、数据、协议和二进制的成功评价直接复用，经重新启动进程后也不增加 ledger 或报告。更改数据产生新候选；更改可信评价源码后旧候选拒绝评价，必须重新 freeze；更换构建二进制产生独立评价 ID。研究记录保留原尝试，不把重跑当成新盲测。原子发布和本机 OS 文件锁用于崩溃/并发一致性，不声称防范同一 OS 用户恶意改写程序、重算 SHA 或物理掉电。

## 资格交接 v1

`candidate-handoff-v1` 是版本化、默认拒绝的数据引用，当前没有连接 Risk Kernel、权威 Ledger 或前向 journal 的消费者。

```json
{
  "schema_version": 1,
  "contract": "candidate-handoff-v1",
  "candidate_sha256": "<冻结候选SHA>",
  "evaluation_sha256": "<独立评价引用或null>",
  "eligibility": "ELIGIBILITY_DENIED",
  "qualification": "NOT_ELIGIBLE",
  "forward_paper_allowed": false,
  "live_allowed": false,
  "independent_acceptance": "NOT_VERIFIED"
}
```

评价使用可信代码并与 Agent 输出隔离；这不等于开发者获得独立验收身份。后续消费者必须从可信本机记录验证候选/评价/数据/协议及资格，不得信任 Agent 提供的 JSON 或单独布尔值。当前代码没有任何允许交易的分支。仍缺历史 PIT、可信独立开盘可得性、足量未见过的前向证据和另行授权的准入实现；研究 Agent 自述或 UI 状态不能解除这些门槛。
