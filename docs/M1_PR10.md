# M1-PR10：Forward EOD Shadow V1

Issue [#47](https://github.com/handFOOLed/Stratide/issues/47)，基于已合并 PR #46 的 `main 6c86b872360bcaa1dc92d1a02b760f1b08274295`。本模块提供单证券 `600000.SH` 的固定 SMA5/20 前向观察、不可回填日志和只读审计。**NO_ORDERS / NO_FILLS / NO_NAV**；开发自测见[证据](evidence/m1-pr10/README.md)，仍需 ChatGPT 固定 HEAD 审查及 Owner 合并许可。

## 本地操作

先使用 [PR33](M2_PR05.md) 已有的 store；Shadow 不采集行情、不触发 sync 或 Agent。每个新 EOD 须由原 observer 实收，再通过原 `research-data.py --store owner-eod sync` 发布成功快照。此处 `owner-eod` 仅为受限名称示例。

```powershell
python scripts/forward-shadow.py --store owner-eod init
python scripts/forward-shadow.py --store owner-eod status
python scripts/forward-shadow.py --store owner-eod enable
python scripts/forward-shadow.py --store owner-eod once
python scripts/forward-shadow.py --store owner-eod watch --interval-seconds 300
# Ctrl+C 停止前台 watch；停止新追加须显式 disable
python scripts/forward-shadow.py --store owner-eod disable
python scripts/forward-shadow.py --store owner-eod history
python scripts/forward-shadow.py --store owner-eod verify
python scripts/forward-shadow.py --store owner-eod report
```

`init` 默认 OFF，拒绝覆盖任何已有 Shadow 目录；`enable/disable` 是 Owner 本地文件系统权限下的显式启停，不是交易授权。名称只允许 `[a-z0-9][a-z0-9_-]{0,63}`。无任意路径、时钟、策略代码、指标参数、模型或 HTTP 参数；测试时钟和中断点仅在测试入口注入。`watch` 只循环同一 `once` 路径，间隔 60–3600 秒，无服务、计划任务或自启。退出码：0 为成功操作/冻结重复/只读查询，3 为一次观察被门禁或停用跳过，2 为输入/存储/锁错误，130 为 Ctrl+C。查询成功不代表源日新鲜或已有有效信号，须读 `source_diagnostics` 和 `signal_count`。

## 来源、时点和固定规则

直接复用 `research/data_snapshot.py` 的 PR33 store/current/source reader 与 `research/eod_journal.py` 的 schema-1041 链、原始响应 SHA、证券/单位/日历/时间和规范化校验，没有第二份采集器。快照须匹配重新只读验证的原 observer、最新成功 sync、原始 DB SHA 和 journal HEAD；sync 不得超 24h。来源已变化但未同步、失败 sync、未来版本、未知/冲突日历、已知开市缺收均拒绝。PR33 空 WAL 的已 checkpoint 主文件可不触碰 SHM 地读取；非空 WAL/热回滚日志返回 `STORE_BUSY_OR_RECOVERY_REQUIRED`，待原 writer 完成后再试，查询不自行恢复或 checkpoint。

决策只在 Asia/Shanghai 当日 16:00 后；源日必须等于真正执行当天。`decision_at` 来自持久化事务内的本地进程时钟，`as_of` 单独记录源 journal 时间，不拿源 `available_at` 冒充计算时间。原 `available_at` 的含义仍是 `validated_in_process_precommit_wall_time; not_exact_durable_visibility_or_commit_time`，不是供应商发布时间或精确 durable commit 可见时间。

每个窗口日选原 journal 中**首个 16:00 后同日观察、接收、可用**且不晚于决策的有效版本。晚补/次日修订不替代当日原始 close，同日修订只留来源诊断。窗口由显式源日历决定，绝不按工作日推断；缺日会断开序列，现有 coverage/gap blocker 保持可见，不能跳过坏日拼接 21 根行情。至少 21 个连续有效观察交易日才比较 T-1 与 T 两个窗口：

```text
above(day) = sum(last_5_close_fen) * 4 > sum(last_20_close_fen)
false → true : UP_CROSS
true  → false: DOWN_CROSS（相等归 false，与原冻结规则一致）
不变          : NO_CROSS
不足 21 日     : INSUFFICIENT_FORWARD_WARMUP
```

该定义复用原 `sma5-20-cross-fixed100-v1` 的指标与严格关系交叉；Shadow 的规则版本为 `sma5-20-shadow-v1`，只输出观察标签，没有股数、持仓、限价或下单计划。原 68/77 日历史数据、`historical_replay` 和 `EXPLORATORY_EX_POST` 不进入此路径。

synthetic 来源始终为 `SYNTHETIC_TEST_SHADOW`。真实来源预热不足时仅为 `FORWARD_WARMUP_ONLY`，完整满足门禁才可标 `SHADOW_FORWARD_OBSERVED`。所有结果固定公开 `CORPORATE_ACTION_PIT_NOT_VERIFIED`、`opening_source=BLOCKED`、`historical_pit=NOT_VERIFIED`、`forward_paper_allowed=false`、`live_allowed=false`、`orders=0/fills=0/nav=null`。

## 唯一身份、持久化和恢复

```text
原 source / instrument / endpoint / journal genesis / mode
  + 固定 rule SHA
  → canonical Shadow identity
  → 主 Git checkout 的 state/forward-shadow/<identity>/shadow.sqlite
  → source_day 唯一事件键
```

绝对本机路径、PR33 store 别名、当前工作目录、刷新 snapshot SHA 都不参与每日事件身份。同一个 Git repository 的 worktree 共享主 checkout 的 canonical 状态；复制 observer 到别名 store 也映射同一日志。不会通过改名称得到第二份成功信号；不声称跨独立 clone 或跨主机的分布式唯一性。

单 OS writer lock 覆盖 once 和启停；SQLite DELETE / FULL 事务保存 append-only 输入和带 SHA 链的事件，表级触发器拒绝 UPDATE/DELETE。run_started 先持久保存，输入和 observation 一次提交；未完成的 run 由下一 writer 追加 `PROCESS_INTERRUPTED_NOT_COMMITTED` 诊断。持久化前中断会回滚，持久化后中断保留原成功；重启不重算已冻结源日，不删除旧意图或证据。停用与 once 争同一锁；只有 disable 成功返回后才视为已生效，忙时返回 `STORE_BUSY`。

日内预热不足也冻结一个明确标注不足的观察记录，不算有效信号。已冻结 T 的输入永不更新；后续同日重复仅追加来源 SHA/修订诊断。T+1 才执行的旧源日始终 `MISSED_OR_STALE`，不会把冻结旧信号当新的当日观察。

## 只读核验与本地复算

`status/history/verify/report` 不建目录/库/锁、不 sync、不采集、不调用策略入口、Provider、Agent 或回放；只读取和核验现有源与冻结输入。SQLite 只读使用 `mode=ro&immutable=1`，在无待应用 WAL 时读取，并检查 DB/sidecar 前后 SHA。查询遇到热日志不做恢复，交给显式 writer 操作。

每个冻结输入保存完整规范化 PR33 快照及 SHA、原 journal HEAD、规则/参数 SHA、最新 sync、窗口、原 observed/received/available、实际 decision_at、close 来源与原 raw SHA、coverage/gap/revision、整数计算。默认 CLI 脱敏，不输出行情和 SMA 数值；输出输入承诺、21 日逐日来源证据、交叉结果及 `DECIMAL_RECOMPUTED`。报告在本地以独立 Decimal 均值算法重算并比对，另核对冻结版本与原 journal 的前缀；不是只相信保存的标签。SHA 仅证明本地一致性，不认证供应商来源或历史 PIT。

需要查看完整本地可重算材料时，可信本机 Python 可只读读取新 Shadow SQLite，避免将真实价格提交到 Git：

```python
from research.shadow import Shadow, readonly, audit_input
service = Shadow("owner-eod")
with readonly(service.path) as db:
    records = service.journal(db)["observations"]
for record in records:
    audit_input(record["material"])  # Decimal 独立检查窗口与交叉
```

## 本轮真实边界
