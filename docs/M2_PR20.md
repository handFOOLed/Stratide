## 输入、质量和时点

```text
已有 V1 未复权日线 / 官方日历 / 当前证券目录
   + V2 adj_factor / suspend_d 原版本与质量
   → 明确证券、as_of、84–192 会话历史前缀
   → historical_research_only 冻结输入与 SHA
   → 原离线 TimesFM CPU → 原 tasks → 原 Registry（template=null）
   → status / report / verify
   → DeepSeek Fusion：REAL_MARKET_DATA_EGRESS_DENIED
```

数据/研究真实性按 P1；真实数据外发边界按 P0 验证。不修改 Risk Kernel、Ledger、券商、资金或原 Agent 预算/授权内核，无 Dashboard/EOD 自动调度。

- 必须显式指定已有 V1/V2 仓库、`--symbols`（1–8 个去重证券）与带时区 `--as-of`；只支持已有日历/目录证据的沪深 A 股。北交所等未支持身份明确拒绝。
- 查询只读取截止日及更早价格/因子/停复牌事件，固定版本上界。保留原 OHLC、昨收、成交量、金额、证券/市场、原始响应 SHA、请求元数据 SHA、来源版本与质量。价格为元、成交量为手（100 股）、金额为千元；转换模型 closes 时要求精确整数分。
- `source_received_at`、`available_at` 保存源仓库的实际下载结束时刻，`historical_available_at=null`。这些资料是事后下载；即便 `as_of` 早于下载，也只允许带明确限制的离线历史研究，不能声称当年已获得该信息。
- `as_of` 必须落在已有开放日且为上海时间 16:00 或以后；模型只吃截止日及更早的未复权 closes。84 closes → 83 returns → 64 个 rolling-20 RMS，后续 20 个值是风险代理的会话序号，不是收益、VaR 或已校准置信度。
- 官方日历验证上下文逐日连续；缺少未来日历时，不生成工作日代替交易日。输出使用 `session+001` 至 `session+020`，`ordinal_future_sessions_dates_unknown`，不宣称预测对应确定日期。
- 缺行、重复日、证券/市场错配、上市区间不覆盖、停牌 S 事件、非正/非法价格或量、昨收与上一原始收盘价不连续、超过原 35% 价格断点、上下文内因子变化均拒绝。返回固定原因码；行缺口附 expected/observed/ratio/missing_dates。没有补值、删除会话、拼接断点或使用复权锚点。
- 源覆盖 PARTIAL、当前目录不能验证历史身份、完整公司行为及历史发布时间未知等限制作为质量标签保留。无检测到的因子变化不等于公司行为已认证；始终 `PARTIAL / historical_pit_status=NOT_VERIFIED`。

本期调用已安装的 `tushare` 1.1.12 和 `tushare-data` 1.1.16 skills，并查阅官方 [daily](https://tushare.pro/wctapi/documents/27.md)、[adj_factor](https://tushare.pro/wctapi/documents/28.md)、[suspend_d](https://tushare.pro/wctapi/documents/214.md)、[trade_cal](https://tushare.pro/wctapi/documents/26.md)。daily 未复权、停牌无行，pre_close 为除权昨收；常规入库时间不能证明某历史行的首次发布时间或修订历史。本期复用现有资料，不调用数据 API，不读取 Token。

## CLI 操作

先按 [PR18](M2_PR18.md) 准备 Linux cgroup v2/systemd/bubblewrap，复用已校验的权重、venv 与已有 Owner Agent 绑定，不下载第二份、不建立第二个费用库。构建、venv、模型放在原生 ext4；已有 Windows 数据库可只读访问，不迁移或重做回填。

变量指向本机已有目录。示例是已验收的历史正常窗口，不能解释为实时预测：

```bash
cargo build --workspace --locked --offline
set -- --v1-root "$V1_ROOT" --v2-root "$V2_ROOT" \
  --symbols 600000.SH,000001.SZ,600519.SH \
  --as-of 2022-03-31T08:00:00Z --context 84
NAME=my-historical-risk
python3 -B scripts/timesfm-cpu.py historical-preflight --name "$NAME" "$@"
python3 -B scripts/timesfm-cpu.py historical-freeze --name "$NAME" "$@"
# 原本地开关默认 OFF；显式启用 CPU，不启用云或交易。
python3 -B scripts/timesfm-cpu.py enable
python3 -B scripts/timesfm-cpu.py once --name "$NAME"
python3 -B scripts/timesfm-cpu.py status --name "$NAME"
python3 -B scripts/timesfm-cpu.py report --name "$NAME"
python3 -B scripts/timesfm-cpu.py verify --name "$NAME"
# 如需停止 CPU 并持久禁止后续启动：
python3 -B scripts/timesfm-cpu.py stop
```

冻结文件在 Git common root 的 ignored `state/timesfm-cpu/<batch>/plan.json`，独占创建；任务仍在原 Owner AgentDir `tasks`。来源/adapter/代码/配置/模型 manifest/权重/时间与输入 SHA 绑定。同名变更拒绝；失败或遗留 local_running 不自动重跑。计划 IPC 上限 2 MiB、原 Registry 任务导入上限 4 MiB，覆盖 8×192 上下文；Worker 原 2 MiB 输入、512 KiB 输出及 6 GiB cgroup 限额保持。

`once` 完成后把原任务存入原 Registry，`template=null / research_only`，保存归档 ref。重复 once 复用 completed 任务，并可恢复尚未完成的可丢弃归档；不重新推理或创建云预留。`report/verify` 只读检查任务、输入/输出 SHA、实际权重及 Registry；不恢复任务或发送请求。旧 PR18 synthetic 和 PR19 已记录任务保留精确旧代码指纹的只读验证；新启动要求当前代码，不用新版本重新签名旧结果。
