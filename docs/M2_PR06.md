## 无 Dashboard 的可复现闭环

Windows、Python 3.12+、已有 Rust/MSVC 缓存；不下载依赖、不需要行情或模型密钥。仓库根目录运行：

```powershell
pwsh -NoProfile -File scripts/with-msvc.ps1 build -p stratide-research -p stratided -p stratide-cli --locked --offline
python -B scripts/test-eod-agent.py --evidence
```

第二条命令真正执行 Rust Agent，读取保存的任务详情，再调用 Python 候选 CLI；断言跨进程重启、来源一致、资格拒绝及无额外调用。每次创建独立名称，完整本机材料保存在 git-ignored `state/m2-pr06-validation/`、`state/data-sync/`、`state/eod-agent/`、`state/candidates/`。输出脱敏 JSON，`verification=Sol_developer_selftest_not_independent_acceptance`。

手动分步示例（使用一个未使用过的名称；PowerShell 7）：

```powershell
$runName = 'eod-demo-' + [Guid]::NewGuid().ToString('N').Substring(0, 10)
python -B scripts/research-data.py --store $runName sync --fixture
./target/debug/eod-research.exe summary $runName
$taskJson = ./target/debug/eod-research.exe run $runName $runName
if ($LASTEXITCODE -ne 0) { throw 'fake task failed' }
$taskFile = Join-Path $PWD "state/eod-agent/$runName/task.json"
[IO.File]::WriteAllText($taskFile, $taskJson, [Text.UTF8Encoding]::new($false))
$savedTask = $taskJson | ConvertFrom-Json
./target/debug/eod-research.exe task $runName $savedTask.id
$r = python -B scripts/research-candidate.py --registry $runName register --agent-task $taskFile --snapshot-store $runName | ConvertFrom-Json
python -B scripts/research-candidate.py --registry $runName source $r.registration_sha256
```

`run` 创建新目录并只执行一个固定本地研究课题；不能选择云 Provider 或覆盖旧 run。使用现有 `Agent::open/create/tick/store.task`，不是手造 result JSON。`task` 仅重开该 CLI 的隔离 run，沿用原恢复流程，输出保存的 request/input/result/calls，不做第二次研究。没有安装服务、调度器或 UI 资源依赖。成功退出 0，失败退出 2 和固定错误码。

## 显式来源与只读契约

`SnapshotSource::named(name)` 仅访问本构建仓库根目录的 `state/data-sync/<name>/snapshots.sqlite`；Python 对应 `Store(name).agent_input()`。只接受小写字母/数字开头及至多 64 字符的名称，不接受路径。检查祖先和 SQLite sidecar 的 symlink/junction、已有文件类型和大小。DB 与单个 sidecar 各至多 64 MiB，当前内容至多 8 MiB。

Rust 用 `SQLITE_OPEN_READ_ONLY`、`query_only`、只读事务读取 v1050 WAL store 的已提交 current 指针，验证 quick_check、规范 UTF-8 JSON SHA、内容 v1、genesis/mode/source kind、journal head 与最近 sync 的一致性、源日/时间/质量及固定权限。保留 SQLite 的 WAL 一致读，不用 `immutable=1` 忽略 WAL，不复制数据库；发现 WAL 却缺少 SHM 时拒绝。新 reader 不打开原 observer，也不把其 bars/raw 写进 Agent DB。

只有最近尝试为 `succeeded`、无 blocker，且 `0 < started_at <= finished_at <= now`、距开始不超过 **24 小时**，才允许新的研究输入。超时、running、blocked、缺失、未知版或篡改均失败关闭；明确再次 `sync` 后才可重试。24 小时限制的是本地核验时效，**不代表交易日数据新鲜、历史 PIT 或外部来源认证**。原 journal 在上次 sync 之后可能已变化；`source_checked_only_at_latest_sync=true`、`calendar_after_snapshot=UNKNOWN_NOT_FETCHED` 保持透明。

摘要至多 8 KiB；coverage/gaps 各保留最近 16 条及完整条数，warnings 只接受现有固定错误类别。包含：

- `version=eod-agent-input-v1:<snapshot SHA>`、`snapshot_id=eod-v1:<SHA>`、`snapshot_sha256`。
- 源日 `YYYY-MM-DD`、原 `last_valid_source_day`、模式 `forward_observed_eod` 或 `synthetic_test`；两种模式保持分离。
- 原 observed/received/available/as-of 时间、available_at 原语义、valid/on-day 计数和覆盖质量；没有 raw、证券/账户/观察身份、现金、持仓、费用明细或源文件路径。
- `RESEARCH_ONLY`、`historical_pit=NOT_VERIFIED`、`opening_source=BLOCKED`、`eod_eligible=false`、`can_execute_forward_paper=false`、`live_allowed=false`。

刷新/启动的墙钟不进入冻结内容版本，也不替代源日。相同内容 SHA 在重复 sync、重启后投影相同；已保存任务继续保留自己的输入和研究结果。新的显式任务每次重新校验，不受旧报告 60 秒缓存影响。

现有服务可在 Owner 本机启动时显式传 `--agent-eod-store <name>`，并配 `--agent-dir`。它与 `--report-dir/--evaluation-file` **互斥**，V1 不混合来源；未启用时原报告/历史评价、账户 pinned API 和任务行为保持原路径。账户 API 没有新增来源或路由。现有服务仍使用原静态资源；上述 headless CLI 无此依赖。本期不开发或构建新 Dashboard。

## 新数据 scope 与执行边界

EOD 输入 scopes 固定为 `owner_task` 加独立的 `forward_eod_research_summary_v1`，不借用 `paper_summary_v1` 或 `historical_summary_v1`。新建 `Settings::fake()` 包含本地测试 grant；旧 fake 配置未授权此 scope 时仍拒绝，不自动改写旧配置。

`Model::authorize` 对携带新 scope 的任何非 fake 模型直接返回 `EOD_SNAPSHOT_LOCAL_FAKE_ONLY`，在 DNS、读 Key、真实预算预留和发送前阻断；即使手工把此 scope 加入 grant 也不能开启。本期没有新增真实 grant/Key。既有 Budget Gate、收费、重试、未知账单语义不变；fake 仍走原 TST 合成预留和确定性结算，不能解释为真实账单。

新来源永远不能用于自动 EOD 创建；即使旧开关 ON，也只记录 `EOD_SNAPSHOT_MANUAL_ONLY`。原 `historical_replay` 调度条件和同日 trigger_key 去重保留。Agent 文本继续没有代码、文件、工具或交易执行权。

## 候选来源与查询

`register --agent-task <saved-task.json> --snapshot-store <name>` 接受实际保存的任务详情或原 API 信封，保留 request/input/result/calls。对声称来自 EOD 快照的任务，重新调用可信只读 `agent_input()`，与冻结输入完整比较，匹配后保存 `SNAPSHOT_CONTENT_VERIFIED_AT_REGISTRATION`。缺源、内部字段自洽但与本机不同、模式/源日/SHA/限制错配及伪造 `qualification=PASS` 均拒绝。

来源至少绑定 snapshot ID/SHA、源日/模式、研究任务 ID、input summary 版本/摘要 SHA 与策略限制。**这只证明登记时与本机快照内容匹配，JSON 导出不是 Agent 签发证明**；`task_origin=TASK_ORIGIN_NOT_ATTESTED` 始终保留。省略 `--snapshot-store` 时只能记录 `SOURCE_UNVERIFIED`。后续 `source <registration SHA>` 查询冻结记录，不自动刷新其“登记时”验证或重跑模型。

没有 Owner 模板的自然语言候选为 `RESEARCH_ONLY`；`source` 显示冻结研究文本、来源与 `NOT_EVALUATED / ELIGIBILITY_DENIED`。本期没有运行它的策略评价，不凭空写 `INSUFFICIENT_EVIDENCE`。直接 freeze 被原 `UNSUPPORTED_CANDIDATE` 拒绝，不能把两日 EOD 转为 68 日历史回放。若 Owner 显式另选既有固定模板，原独立数据准备/freeze/evaluator 路径和默认资格拒绝仍适用；EOD 来源不授予评价或交易权限。
